# RedwoodSDK Cron Data Cleanup Worker

## Background
You are building a RedwoodSDK (rwsdk) worker that serves HTTP traffic AND runs a scheduled background job on the Cloudflare platform. The worker stores short-lived records in a Cloudflare D1 database (accessed through Drizzle ORM). A Cloudflare Cron Trigger must periodically sweep the database and remove records that have expired, while HTTP routes let clients create and inspect records so the cleanup can be observed.

A scaffolded RedwoodSDK project already exists at `/home/user/project` (created with `create-rwsdk`). Everything runs locally against the Cloudflare emulator (Miniflare/Wrangler); no Cloudflare account or deployment is required.

## Requirements
Implement the following in the project at `/home/user/project`:

1. **Database (D1 + Drizzle)**
   - Configure a Cloudflare D1 database binding named `DB` in `wrangler.jsonc`, with Drizzle migrations stored in the `drizzle/` directory (`migrations_dir`).
   - Define a Drizzle schema table named `records` with (at least) these columns:
     - `id`: text primary key, auto-generated by the server when a record is created.
     - `label`: text, required.
     - `expiresAt`: integer storing a Unix timestamp in **milliseconds**, required.
   - A record is considered **expired** at cleanup time when its `expiresAt` value is less than or equal to the current time (`Date.now()`).
   - Provide a working migration so the `records` table exists in the local D1 database.

2. **HTTP API (JSON)** — served by `defineApp`:
   - `POST /api/records`: create a record. Accepts a JSON body `{ "label": string, "expiresAt": number }` where `expiresAt` is a Unix timestamp in milliseconds. Responds with status `201` and the created record as JSON `{ "id": string, "label": string, "expiresAt": number }`.
   - `GET /api/records`: respond with status `200` and a JSON array of all records currently in the database, each shaped `{ "id": string, "label": string, "expiresAt": number }`.

3. **Cron Trigger (scheduled background cleanup)**
   - Configure a Cron Trigger in `wrangler.jsonc` using the schedule `0 * * * *`.
   - Export the worker's default entry as an object that provides **both** the HTTP `fetch` handler (from your `defineApp` instance) and a `scheduled` handler.
   - When the `scheduled` handler runs, it must delete **every** record whose `expiresAt` is less than or equal to the current time, leaving non-expired records untouched. The scheduled handler must operate directly on the D1 database (it runs outside the HTTP request lifecycle, so it cannot use per-request context).

## Implementation Hints
- The worker entry point is `src/worker.tsx`. Use `defineApp` from `rwsdk/worker` and `route`/`render` from `rwsdk/router` to define the API routes.
- To support a Cron Trigger you must export the app object and default-export an `ExportedHandler` that exposes `fetch: app.fetch` alongside an `async scheduled(controller)` method. Use `controller.cron` to match the configured schedule.
- Integrate Drizzle with D1 following the RedwoodSDK Drizzle guide: create a Drizzle client with `drizzle(env.DB, { schema })` using `env` from `cloudflare:workers`, define the schema under `src/db/`, and generate/apply migrations with `drizzle-kit` and `wrangler d1 migrations apply`.
- Cron triggers do not fire automatically in local development, but the RedwoodSDK/Vite dev server exposes a scheduler endpoint you can hit to invoke the `scheduled` handler for a given cron expression.
- Remember that D1 stores integers, so keep `expiresAt` as a numeric millisecond timestamp end-to-end.
- The project runs with the standard RedwoodSDK dev server (`npm run dev`, served on port `5173`).
