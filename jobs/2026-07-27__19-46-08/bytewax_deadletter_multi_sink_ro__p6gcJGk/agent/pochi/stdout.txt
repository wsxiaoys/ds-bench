**Pipeline architecture:**

1. **Input**: `FileSource` reads `data/input.jsonl` line-by-line with `batch_size=1` for deterministic ordering
2. **Line numbering**: `stateful_map` with a constant key maintains a monotonically increasing counter (starting at 1) to attach line numbers
3. **Classification**: `map` applies the 6 validation rules in exact precedence order:
   - `malformed_json` — not valid JSON or not a JSON object
   - `missing_field:<field>` — required field absent (checked: id, category, amount, currency)
   - `invalid_type:<field>` — wrong type (id: string/int, category: string, amount: number, currency: string; booleans rejected for id/amount)
   - `unknown_category:<value>` — category not in {orders, payments, refunds}
   - `invalid_amount:non_positive` — amount ≤ 0
   - `invalid_currency:<value>` — currency not in {USD, EUR, GBP}
4. **Branching**: `branch` splits classified records into valid and dead-letter streams; two more branches route valid records to orders/payments/refunds
5. **Output**: `FileSink` instances write compact JSON to `out/orders.jsonl`, `out/payments.jsonl`, `out/refunds.jsonl`, and `out/dead_letter.jsonl`
6. **Metrics**: `CollectingSink` (custom `DynamicSink`) gathers all records; an `atexit` hook writes `out/metrics.json` with total/valid/dead_letter/by_category/by_error counts
