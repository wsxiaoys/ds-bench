# Two-Pass OCR Gating Pipeline for Docling ## Background Docling (`docling` v2.107.0, already installed in this offline container) extracts a PDF's embedded programmatic text layer by default and only falls back to optical character recognition (OCR) for pages it recognizes as bitmap scans. This produces two failure modes for real-world documents: (a) pages that are image-only scans yield little or no usable text from the programmatic layer, and (b) pages with broken/non-standard font encodings emit corrupted "mojibake" text. A robust ingestion pipeline must therefore *detect* per-page text corruption and selectively repair only the affected pages with OCR, while leaving clean pages untouched. You must build a command-line pipeline that performs exactly this two-pass "OCR gating" over a fixed input PDF and emits a repaired Markdown document plus a machine-readable gating report. The environment is fully offline: all model weights and the Tesseract engine are pre-baked into the image. No network access is available at any point. ## Requirements * Read the input PDF and, using only its embedded programmatic text layer (no OCR), extract the text of every page (Pass 1). * For every page, compute a numeric `garble_score` from its Pass-1 text using the exact definition given below, and decide whether the page's programmatic text is unusable and must be repaired via OCR. * For every page decided to need repair, obtain that page's text a second time such that the text is produced by optical character recognition of the rendered page image rather than the embedded text layer (Pass 2).
