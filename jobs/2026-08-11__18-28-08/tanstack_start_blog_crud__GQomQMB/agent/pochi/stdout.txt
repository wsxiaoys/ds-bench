# Full-Stack Blog CMS with TanStack Start (SSR + Server Functions + SQLite) ## Background Build a full-stack, server-side-rendered blog content management system using TanStack Start (React, file-based routing, and server functions) backed by a local SQLite database. A TanStack Start project has already been scaffolded for you at the project path below; you must implement the application on top of it. ## Requirements * Full CRUD for blog posts: create, edit, delete, and list. * Every post has these fields: `title`, `slug` (auto-generated and unique), `body` (authored in Markdown), `tags` (zero or more), and a published/draft status. * The public post detail page MUST be server-side rendered: the post's title and its rendered body MUST be present in the initial HTML document returned by the server (i.e. visible without executing any client-side JavaScript) so the page is indexable for SEO. * A post's `body` is written in Markdown and MUST be rendered to HTML when the post is viewed. * The public post list MUST show only published posts. Draft posts MUST never be reachable or visible through any public page. * An admin post list MUST show all posts, including drafts. * The public post list MUST be filterable by tag through the URL. * Requesting a post that does not exist (or that is a draft) through a public URL MUST return a 404 not-found page. * All data MUST be persisted in a local SQLite database and MUST survive a full restart of the server. ## Implementation Hints * Project path: /home/user/blog * The application MUST run as a production, server-side-rendered build and be served on port 43117, reachable at http://localhost:43117. * Build command: `npm run build` * Start command: `PORT=43117 npm run start` * Exact routes and their required behavior: * `GET /` — public list of published posts only. Each listed post's title MUST be an anchor (`<a>`) element whose `href` is exactly `/posts/<slug>`. When the query parameter `tag` is present (e.g. `/?tag=<tag>`), the list MUST show only published posts that have that exact tag. * `GET /posts/<slug>` — public detail page for a single published post. The post title MUST be rendered inside an `<h1>` element. The Markdown body, rendered to HTML, MUST be placed inside an element carrying the attribute `data-testid="post-body"`. The title and the rendered body text MUST appear in the raw server-rendered HTML of this route. If `<slug>` does not correspond to an existing published post, the server MUST respond with HTTP status code 404 and render a page whose visible text contains `Not Found`. * `GET /admin` — admin list of ALL posts (both published and draft). Each post's title MUST appear as text on this page. For each post the page MUST provide a delete control implemented as a `<button>` element carrying the attribute `data-testid="delete-<slug>"` that permanently deletes that post. * `GET /admin/new` — a form to create a new post. * `GET /admin/<slug>/edit` — a form to edit the post with that slug, pre-filled with the post's current values. * The create form and the edit form MUST both contain these controls: * a text input with attribute `name="title"` * a textarea with attribute `name="body"` * a text input with attribute `name="tags"` that accepts a comma-separated list of tags * a checkbox with attribute `name="published"` (checked means published, unchecked means draft) * a control that submits and saves the post * Tag parsing: the value of the `tags` field is split on commas and each entry is trimmed of surrounding whitespace; empty entries are ignored. Tag filtering matches a tag string exactly. * Slug generation: derive the slug from the title by lowercasing it, replacing every run of characters outside the set `[a-z0-9]` with a single `-`, and trimming any leading or trailing `-`. If the resulting slug is already used by another post, append `-N`, using the smallest integer N greater than or equal to 2 that makes the slug unique (for example `my-title`, then `my-title-2`, then `my-title-3`). * Markdown rendering MUST convert standard Markdown to the corresponding HTML elements (for example, `## Section` becomes an `<h2>` and `**bold**` becomes a `<strong>` element). * Editing a post MUST persist the changes; deleting a post MUST remove it from both the admin and public views. ## Notes * All services are local. Do NOT use any external API, network service, or third-party hosted service.
