## What it does
On every invocation the program:
1. **Ingests** a single 30-day refund policy document into the Alchemyst context engine via `client.v1.context.add(...)`.
2. **Searches** the context engine for the `--question` argument via `client.v1.context.search(...)` and prints each retrieved chunk's `content` to stdout (or a clear "no contexts" message if none are returned).

## Key implementation details (verified against the actual SDK v0.10.0 source)
- Initialized with `AlchemystAI(api_key=os.environ["ALCHEMYST_AI_API_KEY"])` — the key is read from the `ALCHEMYST_AI_API_KEY` environment variable (the program exits with a clear error if it's missing).
- The `/logs/artifacts/run-id` file is read and used to build a unique `file_name` (`refunds-<run-id>.md`) so concurrent runs don't collide with a 409 Conflict.
- `context.add` is called with `context_type="resource"`, `source="documentation"`, `scope="internal"`.
- **Important discovery from the SDK source:** The v0.10.0 API requires a top-level `metadata` record on `add` (a 400 is returned if omitted) and expects `file_name`, `file_size`, `file_type`, and `last_modified`. The quickstart's per-document `metadata` placement does not match the actual server contract, so these fields are passed at the top level. Also, `context.search` in v0.10.0 requires **both** `minimum_similarity_threshold` and `similarity_threshold` (the quickstart only showed `similarity_threshold`). The search uses `scope="internal"` with a `0.5`–`0.7` similarity window per the docs' recommended range.
- The result's `contexts` list is iterated and each `ctx.content` is printed; a clear message is printed when the list is empty.
