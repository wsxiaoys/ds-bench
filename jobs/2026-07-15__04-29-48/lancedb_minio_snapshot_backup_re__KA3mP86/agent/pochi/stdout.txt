## How it works

A LanceDB table is a self-contained, versioned directory tree:
```
<name>.lance/
    data/*.lance          # immutable data fragments
    _versions/*.manifest   # one manifest per version
    _transactions/*.txn    # transaction logs
    _deletions/*.arrow     # deletion files (from delete/update)
```

The snapshot is a faithful **recursive object-by-object copy** of the entire dataset tree so that *every* version survives — not just the latest rows.

### `backup(local_table_path, s3_uri)`
- Parses `s3://<bucket>/<prefix>`, builds a boto3 S3 client from the `AWS_*` env vars (path-style addressing, plain HTTP endpoint).
- Walks the `.lance` directory recursively and uploads each file as one object under `<prefix>/<root_name>/<relpath>`, preserving the relative layout.

### `restore(s3_uri, new_local_table_path)`
- Lists all objects under the prefix **up-front**; if none exist, raises `FileNotFoundError` *before touching the filesystem* — so no half-written/openable table is ever left behind.
- Downloads every object into a sibling **temporary directory**, then atomically `os.rename`s it into the final `<name>.lance` path only after all downloads succeed. Any failure (network/`ClientError`) cleans up the temp dir, guaranteeing the destination never appears in a partial state.
- Restoring over an existing table path removes it first, then replaces it atomically.
