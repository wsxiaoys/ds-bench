## Design

**Lease-based leader election via etcd v3** using only the pure-HTTP/JSON gRPC-gateway (`requests`):
- `acquire()` grants an etcd lease (bounded TTL), then issues an atomic compare-and-create transaction on a single election key bound to that lease. The transaction succeeds only when the key's `create_revision == 0` (key doesn't exist). Only the winner becomes leader; losers revoke their just-granted lease so nothing leaks.
- The election key's **`create_revision`** is the **fencing token** — etcd's revision is globally monotonic, so every new leadership term gets a strictly greater token than every previous term.
- A background daemon thread refreshes the lease (every ~TTL/3) for as long as the leader is healthy.

**Failover:**
- `resign()` — graceful: stops keepalive, deletes the key, revokes the lease → a follower wins immediately.
- `simulate_crash()` — stops keepalive WITHOUT revoking; the lease + key expire after the TTL, only then can a follower take over.

**Fencing / source of truth:**
- `is_leader()` and `fencing_token()` read etcd directly and confirm the key exists, is bound to *our* lease, and its `create_revision` equals our token — so a stale/crashed leader is correctly reported as not-leader once the lease expires or a new term begins.
- `run_maintenance()` raises `PermissionError` unless this instance is the current leader, and performs a defensive re-check against etcd right before touching the table.

**LanceDB maintenance:**
- Runs `table.optimize()` (compacts small fragments + rebuilds/updates the IVF_PQ vector index), which is idempotent and loses no rows (count stays 500).
- Returns exactly `{worker_id, fencing_token, version_before, version_after, unindexed_before, unindexed_after}` (all ints except `worker_id`).

## Verified behaviors
- Single leader elected; follower `acquire()` returns `False` and leaks no lease.
- Follower `run_maintenance()` raises `PermissionError`; leader returns the correct dict (200→0 unindexed rows, version 12→15, rows preserved).
- Graceful failover: after `resign()`, follower wins immediately with a strictly greater fencing token.
- Ungraceful failover: after `simulate_crash()`, no one wins while the lease is alive; after TTL a new leader wins with a strictly greater token.
- A stale (crashed) leader's `run_maintenance()` is correctly fenced with `PermissionError`.
- `close()` releases the keepalive thread.
