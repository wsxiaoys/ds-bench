## Architecture

**Proto service** (`vector.proto`):
- `IngestVectors(stream VectorRecord) returns (IngestSummary)` — client-streaming RPC
- `Search(SearchRequest) returns (SearchResponse)` — unary RPC
- `VectorRecord` carries `id` (int64), `vector` (repeated float), `metadata` (string)
- `IngestSummary` exposes `received`, `written`, `batches` (int64 counts)

**Server** (`server.py`):
- Listens on `127.0.0.1:50051`, prints `gRPC server listening on 127.0.0.1:50051` on startup
- LanceDB embedded at `LANCEDB_PATH` env var (default `/home/user/myproject/lance_data`)
- Table named `vectors_${ZEALT_RUN_ID}` (reads `ZEALT_RUN_ID` from environment)
- On startup: creates/overwrites an **empty** table with a PyArrow schema using a fixed-size list of 16 `float32` values for the vector column
- **Batching**: buffers streamed records and flushes every 100 records to LanceDB, then flushes any remainder when the stream ends
- **Dimension validation**: if any record's vector dimension ≠ 16, aborts with `INVALID_ARGUMENT` and rolls back all partial writes from that RPC using LanceDB's `checkout`/`restore` version mechanism — the table is left in its pre-RPC state
- **Search**: exact brute-force kNN with default L2 (Euclidean) distance, returns ranked results ascending by distance

**Client** (`client.py`):
- `ingest_vectors(records, address="127.0.0.1:50051")` — streams an iterable of dicts (`id`, `vector`, `metadata`) via the client-streaming RPC; returns `{"received": int, "written": int, "batches": int}`; lets `grpc.RpcError` propagate on server-side abort
- `search(query_vector, k, address="127.0.0.1:50051")` — returns a list (length ≤ k) of dicts with `id`, `distance`, `metadata`, ordered by ascending distance
