## How it works

**Cache key construction** (`_cache_key`): A stable, collision-resistant key is built by SHA-256 hashing the query vector's canonical float32 byte representation (`np.asarray(vec, dtype=np.float32).tobytes()`) together with `k`, the filter string, the table name, and the current dataset version. Identical `(query_vector, k, filter)` inputs map to the same key; any differing input maps to a different key. The key is compact (< 250 chars) to fit memcached limits.

**Dataset version in memcached**: A per-table counter `lance_version:{table_name}` is stored in memcached, initialized atomically via `add` (set-if-not-exists) in `__init__`. Every `add`/`update` atomically increments it with `incr`. Because the version is embedded in the cache key, bumping it makes all previously cached entries for that table unreachable — this is the invalidation mechanism, shared across all processes and `CachedSearcher` instances.

**Search** (`search`):
- Reads the current memcached version and builds the cache key.
- **Hit**: returns `json.loads(cached)` without touching LanceDB.
- **Miss**: calls `table.checkout_latest()` to observe the latest committed state (avoiding a stale snapshot pinned when the table handle was first opened — critical for cross-instance freshness), runs the LanceDB L2 search with `.select(["id","category"]).limit(k)` and an optional `.where(filter)`, normalizes each row to `{id:int, category:str, _distance:float}` preserving ascending `_distance` order, serializes with `json.dumps(..., sort_keys=True)`, stores it in memcached with the configured TTL, and returns `json.loads(payload)`. Both hit and miss paths go through the same JSON serialization, so a hit is byte-for-byte identical to the originating miss.

**Mutations**: `add` appends rows to LanceDB then bumps the version; `update` applies the SQL `where`/`values` then bumps the version.

- `checkout_latest()` ensures misses reflect the latest committed state written by other connections.
- Distinct `k`, `filter`, vector, and version each produce distinct cache keys; identical inputs produce the same key.
- TTL expiry works (entries disappear after the configured `ttl_seconds`).
