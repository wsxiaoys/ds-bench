## What it does

**LanceDB ingestion (`ensure_table`)**
- Reads every row of `data/documents.jsonl` and builds a PyArrow table with explicit column types.
- The `vector` column is typed as `pa.list_(pa.float32(), 8)` — a **fixed-size list of 32-bit floats** — so LanceDB vector search works against a float32 query vector.
- Stores the table at `/home/user/project/lancedb`, drops any prior table, recreates, and calls `table.optimize()` to fold rows into index structures.
- Dropping/recreating on each run makes the CLI fully rerunnable and deterministic.

**LanceDB retrieval (`retrieve_candidates`)**
- Fetches the top-K nearest documents using **L2** vector search (`.metric("L2")`) with **no metadata filtering** at the LanceDB stage — the candidate pool is the raw nearest neighbors.
- Returns an Arrow table including LanceDB's `_distance` column.

**DuckDB analytics (`analyse`)**
- Registers the LanceDB result set as a DuckDB relation and the `categories.csv` as a view via `read_csv_auto`.
- All SQL work happens **inside DuckDB** (not Python or LanceDB):
  - `JOIN candidates c ON c.category = cat.category` against the auxiliary categories table.
  - `WHERE` predicate filters: `in_stock = true`, `price <= max_price`, and optional `category` equality.
  - `ROW_NUMBER() OVER (PARTITION BY department ORDER BY distance ASC, id ASC)` window function for `dept_rank`.
  - `GROUP BY department` aggregation for `num_docs`, `avg_price` (rounded to 4 decimals), and `min_distance`.
- Apostrophe-containing category values (e.g. `Women's Apparel`, `Men's Shoes`) are handled via **DuckDB named-parameter binding** (`$category` / `$max_price`), not string interpolation.

**Output**
- Prints **only** a single JSON object to stdout with exactly two keys:
  - `hits`: surviving candidates ordered by ascending distance, ties broken by ascending `id`. Each hit has `id`, `title`, `category`, `department`, `price`, `distance`, `dept_rank`.
  - `departments`: one object per department present in hits, ordered by ascending department name, with `department`, `num_docs`, `avg_price`, `min_distance`.
- All errors/diagnostics go to stderr; stdout stays clean.
