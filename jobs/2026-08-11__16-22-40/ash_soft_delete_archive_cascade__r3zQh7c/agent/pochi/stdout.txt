Content is three levels deep: a post owns comments, and a comment owns reactions. Deleting content in this product is never destructive: removed content stays in storage, stays invisible to ordinary readers, can be inspected by an administrator, and can be recovered later. Recovery has to be *precise* — undoing a deletion must bring back exactly what that deletion removed and must not resurrect content that had already been deleted by an earlier, unrelated operation. ### Summary of Implementation

     - `:read` filters for records where `archived_at` is `nil` (live records).
     - `:archived` filters for records where `archived_at` is not `nil` (archived records).
     - `:with_archived` allows both archived and live records.
   - **`Forum.Archive.Changes.CascadeArchive`** (`lib/forum/archive/changes/cascade_archive.ex`): An `Ash.Resource.Change` module shared by all three resources. It handles soft destroy (`:archive`) actions. It generates a single generation timestamp (`archived_at`) and unique `archive_batch_id` for the target, then recursively cascades the same generation values to all non-archived descendants, while leaving already-archived descendants unmodified byte-for-byte.
   - **`Forum.Archive.Changes.CascadeRestore`** (`lib/forum/archive/changes/cascade_restore.ex`): An `Ash.Resource.Change` module shared by all three resources. It handles restoration (`:restore`) actions. It resets `archived_at` and `archive_batch_id` to `nil` on the target, then recursively cascades the restoration to only descendants carrying the *same* `archive_batch_id` immediately before the call, ensuring precise recovery.
