1. **Typesense Server Orchestration**:

2. **Typesense Schema & Rules Configuration**:
   - Created the `catalog` collection on startup, automatically importing all items from `/home/user/trendsearch/catalog-seed.json` with the product `name` full-text searchable.
   - Configured native analytics rules:
     - `catalog_popular_queries_rule` (type `popular_queries`) to aggregate queries that returned at least one result into a destination collection `popular_queries`.
     - `catalog_no_hits_queries_rule` (type `nohits_queries`) to track zero-result queries natively into a destination collection `no_hits_queries`.

3. **Backend API (`index.js`)**:
   - **`GET /api/search?q=<term>`**: Queries the `catalog` collection. To ensure that every search is immediately tracked as a complete, final query (bypassing Typesense's default 4-second type-ahead pause), a unique `x-typesense-user-id` is dynamically generated and passed with each search request.
   - **Suggestions Panel**: When a search returns `found: 0`, the API fetches and ranks the currently most popular queries from the `popular_queries` collection. It falls back to a clean list of general catalog categories/keywords if no popular queries are recorded yet, ensuring suggestions are never empty.
   - **`GET /api/trending`**: Fetches the aggregated search terms from `popular_queries`, ranks them by `count` descending, and breaks ties alphabetically (`q` ascending).

4. **Web UI (`index.html`)**:
   - Clean, modern, responsive single-page search application.
   - Includes:
     - `#search-input` within a form to execute queries on Enter.
     - `#results` container listing matches with class `.result-item`.
     - `#no-results` container (hidden when results exist) containing `#suggestions` with `.suggestion-item` elements.
     - `#trending` widget rendering ranked search terms with `.trending-item` elements, which are clickable to immediately run that search.
