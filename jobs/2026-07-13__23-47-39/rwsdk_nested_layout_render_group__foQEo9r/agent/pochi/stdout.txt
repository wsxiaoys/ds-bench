# Nested Layouts and Multiple Render Groups in RedwoodSDK ## Background RedwoodSDK (rwsdk) is a server-first React framework for Cloudflare, built as a Vite plugin. Its router lets you compose an application from multiple `render()` groups, where each group binds a distinct HTML *Document* shell to a set of routes. Within a group you can further compose shared UI using `layout()` and group related routes with `prefix()`. You will build a single RedwoodSDK app that serves two clearly separated sections — a **public** section and an **admin** section — each rendered inside its own Document shell and wrapped by its own layout. The nested routes inside the admin section must all share one common admin layout wrapper (header/nav), while the public routes share the public layout. A RedwoodSDK starter project is already scaffolded with dependencies installed at `/home/user/project`. ## What was implemented

### Two distinct Document shells (`src/app/document.tsx`)
- `PublicDocument` — `<title>Public Site</title>`
- `AdminDocument` — `<title>Admin Console</title>`

### Two layouts (`src/app/layouts.tsx`)
- `PublicLayout` — renders `<nav data-testid="public-nav">` with links to `/` (Home) and `/about` (About), wrapping content in `<div data-testid="public-layout">`.
- `AdminLayout` — renders `<nav data-testid="admin-nav">` with links to `/admin` (Dashboard), `/admin/users` (Users), and `/admin/settings` (Settings), wrapping content in `<div data-testid="admin-layout">`.

### Page components (`src/app/pages/`)
- `home.tsx` → `data-testid="page-home"`, "Welcome Home"
- `about.tsx` → `data-testid="page-about"`, "About Us"
- `admin-dashboard.tsx` → `data-testid="page-admin-dashboard"`, "Admin Dashboard"
- `admin-users.tsx` → `data-testid="page-admin-users"`, "Manage Users"
- `admin-settings.tsx` → `data-testid="page-admin-settings"`, "Admin Settings"

### App composition (`src/worker.tsx`)
Two separate `render()` groups bind each section to its own Document:
- `render(PublicDocument, [layout(PublicLayout, [route("/"), route("/about")])])`
- `render(AdminDocument, [prefix("/admin", layout(AdminLayout, [route("/"), route("/users"), route("/settings")]))])`

`prefix()` scopes all admin routes under `/admin`, and `layout()` ensures every nested admin route shares the same `AdminLayout` header/nav. The `render()` middleware sets `rw.Document` per group, so public routes render inside `PublicDocument` and admin routes inside `AdminDocument`.
