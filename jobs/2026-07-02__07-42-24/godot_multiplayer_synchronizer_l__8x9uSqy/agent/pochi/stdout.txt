### Implementation Details:
1. **Dynamic Multiplayer Subtrees**:
   - Inside `main.gd`, we dynamically construct a subtree for the `Server` and a subtree for each of the `N` clients (`Client_0`, `Client_1`, etc.).
   - Each subtree is registered with its own `SceneMultiplayer` instance using `get_tree().set_multiplayer(api, path)`. This allows running the server and all clients isolated but concurrently in a single Godot process.
   - Relative paths are identical (e.g., `Players` and `MultiplayerSpawner` are siblings under each peer's root), ensuring that RPC path resolution and `MultiplayerSpawner` work perfectly.

2. **Deterministic Spawn & Lifecycle Authority Management**:
   - In `player.gd`, we override `_enter_tree()` to dynamically parse the peer ID from the node's name and set the multiplayer authority of both the `Player` node and its child `MultiplayerSynchronizer` during the enter-tree stage. This adheres to Godot 4's strict requirement to set authority before/during the spawn lifecycle, eliminating any warnings or errors.
   - The authoritative peer sets its own position to `Vector2(authority, authority)` in `_ready()`, and the `MultiplayerSynchronizer` automatically propagates this value to all other peers.

3. **Synchronized RPC Execution**:
   - The `@rpc("any_peer", "call_local")` `update_score(value: int)` function is defined in `player.gd`.
   - To ensure that every client receives all other clients' score updates, clients wait to dispatch their score RPCs until all clients are fully connected and spawned (indicated by the total players container child count reaching `clients_count + 1`). This allows Godot's built-in RPC relay to perfectly distribute the scores to all peers in a single round.

4. **CLI Argument Parser & JSON Output**:
   - `main.gd` parses custom CLI arguments passed after the `--` separator (`--port`, `--clients`, `--frames`, `--score-deltas`, `--out`) using `OS.get_cmdline_user_args()`.
   - The simulation pumps exactly `--frames` frames using `await get_tree().process_frame`.
   - It then gathers the state of all players across all peers, sorts the peers lists ascendingly, formats the data in strict accordance with the requested JSON schema, writes the output pretty-printed, and exits with status `0`.
