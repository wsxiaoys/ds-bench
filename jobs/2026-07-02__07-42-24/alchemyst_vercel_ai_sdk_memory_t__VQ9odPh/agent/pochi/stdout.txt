# Cross-Session Memory CLI with Vercel AI SDK + Alchemyst (TypeScript) ## Background You will build a small Node.js TypeScript CLI that uses the Vercel AI SDK (`ai` package) wrapped with Alchemyst's `withAlchemyst` middleware from `@alchemystai/aisdk` to give the LLM persistent, cross-session memory. Alchemyst is a Context Engine that gives LLMs durable memory keyed by `(userId, sessionId)`. When `withAlchemyst(...)` wraps `generateText`, every call to the wrapped function automatically (a) retrieves past memories for the `userId`, (b) injects them into the prompt, and (c) persists the new turn. This lets the agent remember a preference established in one session and reuse it in a completely different session for the same user. The CLI must demonstrate this with two phases: - `--phase establish`: the user tells the assistant a personal dietary preference. The assistant acknowledges and the memory is written. - `--phase recall`: a *new session id* is used, the user asks an open question, and the assistant must answer using the preference that was stored in the previous phase. ## Requirements - A Node.js project (npm) at `/home/user/vercel-ai-memory` written in TypeScript. - Production dependencies that **must** be declared in `package.json`: - `ai` (Vercel AI SDK) - `@ai-sdk/openai` (Vercel AI SDK OpenAI provider) - `@alchemystai/aisdk` (Alchemyst middleware) - TypeScript build that emits the runnable entrypoint to `dist/main.js`. - The CLI accepts a single argument `--phase <establish|recall>` and reads the following environment variables: - `ALCHEMYST_AI_API_KEY` (Alchemyst API key) - `OPENAI_API_KEY` (OpenAI API key) - `RUN_ID` (read from `/logs/artifacts/run-id` and passed to the CLI as an environment variable; used to namespace the user and session ids; see Parallel-Run Safety below) - Use the wrapped function `withAlchemyst(generateText, { apiKey: process.env.ALCHEMYST_AI_API_KEY })` and call it with an OpenAI model from `@ai-sdk/openai` (for example `openai('gpt-4o-mini')` or another small OpenAI chat model). **Do not** call OpenAI directly without the Alchemyst wrapper. - Every call to the wrapped `generateText` MUST pass both `userId` and `sessionId`. The middleware will return `MISSING_PARAMETERS` if either is omitted. - Print the model's response text to **stdout** (nothing else on stdout other than the model output is required, but it must include the response text). - No mocks, stubs, fake clients, or hard-coded model replies: the program must perform real network calls to Alchemyst and OpenAI. ## Parallel-Run Safety (REQUIRED) This task may run multiple times concurrently against the same Alchemyst account. To avoid cross-run memory contamination you MUST namespace the user and session identifiers with the value of the `/logs/artifacts/run-id`: - `userId` = `vercel-memory-user-<run-id>` - `sessionId` for `--phase establish` = `establish-<run-id>` - `sessionId` for `--phase recall` = `recall-<run-id>` The two phases intentionally use **different `sessionId` values** so the test confirms cross-session memory, not just same-session chat history. ## Implementation Hints - Initialize an npm project, add `typescript`, a `tsconfig.json` whose `outDir` is `./dist`, and a `build` script (e.g. `tsc`). The returned function has the same call signature as `generateText`, plus the extra fields `userId` and `sessionId`. - Refer to the Alchemyst Memory Quickstart (https://getalchemystai.com/docs/getting-started/quickstart-memory) and the TypeScript tutorial index at https://getalchemystai.com/docs/llms.txt if you need API details. - Choose a small OpenAI chat model (e.g. `gpt-4o-mini`) to keep cost and latency low. - In `--phase establish`, send a prompt that *clearly states the dietary preference*. A good prompt is something like `"Please remember this about me: I am vegan and I am allergic to peanuts. Acknowledge that you will remember."`. The user message itself is what Alchemyst persists, so it must include the literal word `vegan`. - In `--phase recall`, use a **different sessionId** and a prompt that forces the model to surface the stored dietary information, for example: `"Based on what you remember about my dietary restrictions, what should I avoid at a dinner party?
