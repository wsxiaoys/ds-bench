# Real-time Collaborative Document Editor in Wasp.sh

## Background
In this task, you will build a full-stack real-time collaborative document editor using Wasp.sh (^0.24.0), React, Node.js, and WebSockets (Socket.IO). Wasp is a full-stack, spec-driven framework where high-level configuration is defined in `main.wasp.ts` using `@wasp.sh/spec`, and data models are defined in `schema.prisma`.

## Requirements

### 1. Authentication & Signup
- Use Wasp's built-in `usernameAndPassword` authentication.
- Map the user's username to the `username` field on the `User` entity during signup using `userSignupFields`.
- Implement a `/signup` page (with `SignupForm` from `wasp/client/auth`) and a `/login` page (with `LoginForm` from `wasp/client/auth`).
- Protect all other routes so that only authenticated users can access them, redirecting to `/login` if unauthenticated.

### 2. Document Management
- Logged-in users can view a list of documents they own or have been shared with on the homepage (`/`).
- Provide a form on the homepage to create a new document. It must have an input field for the document title (`id="document-title-input"`) and a button to submit (`id="create-document-btn"` or text "Create Document").
- Each listed document must link to `/document/:id`.

### 3. Collaborative Editor
- On the document page (`/document/:id`), display the document's title.
- Provide a textarea with `id="document-content-textarea"` for editing the document's content.
- Multiple users must be able to view and edit the same document concurrently. Changes made by any user must be synchronized and reflected in real-time in all other active sessions viewing that document using Wasp's WebSocket integration.
- **Permissions check**: 
  - Only the owner, or users with a shared permission ("VIEW" or "EDIT") can access the document page. Other users must see "Access Denied" or be redirected to `/`.
  - If a user has "VIEW" permission, they can only view the document. The textarea (`id="document-content-textarea"`) must be disabled or read-only (`disabled` or `readOnly` attribute present).
  - If a user is the owner or has "EDIT" permission, they can edit the document content. The textarea must be editable.

### 4. Version History
- Users with edit/owner access can save the current document content as a new version. Provide a button with `id="save-version-btn"` or text "Save Version".
- When clicked, it must save the current content as a new `Version` in the database, with the current user as the author, and update the document's primary content.
- Display a list of saved versions in chronological order under `id="version-history-list"`. Each version item must display:
  - The author's username.
  - The version ID or index.
  - A button/link to restore this version with `class="restore-version-btn"` or text "Restore" (only visible to users with edit/owner access).
- Clicking "Restore" must update the document's active content to that version's content and broadcast the change to all other active WebSocket clients immediately.

### 5. Document Sharing (Permissions)
- The document owner (and only the owner) must see a sharing section on the document page.
- Provide an input with `id="share-username-input"` to enter a username, a dropdown/select with `id="share-role-select"` to choose "VIEW" or "EDIT", and a button with `id="share-document-btn"` or text "Share" to share the document.
- Provide a list of users with current permissions under `id="permissions-list"`, including a button to revoke access.
