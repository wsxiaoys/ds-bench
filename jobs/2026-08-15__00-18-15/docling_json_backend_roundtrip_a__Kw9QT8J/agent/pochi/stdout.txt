### What was completed:
1. **Created `docaudit` package** with `__init__.py` and `cli.py` to process candidate Docling JSON files directly inside the input directory.
2. **Robust Classification & Recovery Pipeline**:
   - `malformed_json`: Validates UTF-8 decoding and JSON parsing.
   - `not_an_object`: Ensures the top-level value is a JSON object.
   - `version_mismatch`: Detects if document-schema validation fails and the major version component of its `version` field differs from the installed Docling document model (`1.10.0`).
   - **Automatic Recovery**: Retries `version_mismatch` candidates by replacing their top-level `version` with the installed model's schema version. If successful, the candidate is marked as `recovered` and keeps the status `version_mismatch` but is processed as successfully ingested.
   - `schema_invalid`: Handles any other document-schema validation failure.
   - `unreadable`: Handles other ingestion failures.
   - `ok`: Handles candidates that successfully ingest without any modifications.
3. **Artifact Generation**:
   - **Normalized JSON** (`<out-dir>/normalized/<stem>.json`): Serialized with 2-space indentation, sorted keys at every level, and non-ASCII characters kept verbatim, ending with exactly one trailing newline.
   - **Markdown Export** (`<out-dir>/markdown/<stem>.md`): Strips all trailing newlines and appends exactly one trailing newline.
4. **Validation Parity & Stability**:
   - **Stream Parity (`stream_parity`)**: Verifies if loading from an in-memory byte stream (`io.BytesIO`) yields a document with an identical exported dictionary compared to path-based ingestion.
   - **Round-Trip Stability (`roundtrip_stable`)**: Verifies if re-ingesting the emitted normalized JSON yields a document with an identical exported dictionary.
5. **Deterministic Report**:
   - Generates `<out-dir>/audit_report.json` with the required keys (`schema_version`, `input_dir`, `total`, `ok`, `recovered`, `failed`, `status_counts`, `documents`), sorted alphabetically by candidate name.
6. **Strict Exit Codes**:
   - `5` when `--input-dir` does not exist or has no candidate JSON files.
   - `4` when at least one successfully ingested candidate fails `stream_parity` or `roundtrip_stable`.
   - `3` when `failed` > 0 and no parity/stability issues exist.
   - `0` otherwise.
