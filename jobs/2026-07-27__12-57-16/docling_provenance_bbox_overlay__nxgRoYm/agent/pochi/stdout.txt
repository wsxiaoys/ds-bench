### Solution Overview

1. **Docling Document Conversion**:
   - We configure the `DocumentConverter` with `PdfFormatOption` where `PdfPipelineOptions` has `generate_page_images = True` and `images_scale = 2.0`.
   - The PDF document located at `assets/report.pdf` is fully converted offline using Docling's local pre-baked model weights.

2. **Coordinate Mapping and Transformation**:
   - For each element in the document, we iterate through its provenance items (`item.prov`).
   - The bounding boxes in Docling are originally in `BOTTOMLEFT` coordinates. We convert them to `TOPLEFT` coordinates using `bbox.to_top_left_origin(page_height)`.
   - We then scale the coordinates to the page's rendered raster pixel space by multiplying them by the scale factor (dynamically derived from the ratio of the image dimensions to the PDF page dimensions, which is exactly `2.0`).
   - We ensure the coordinates are well-formed and valid (`0 <= x0 < x1 <= image_width` and `0 <= y0 < y1 <= image_height`).

3. **Rendering & Output Generation**:
   - For each page `N`, we draw rectangles representing the bounding boxes on a copy of the rendered page image using Python's `PIL.ImageDraw`.
   - The rectangles are drawn using the specified case-insensitive hex color for each supported element type (`text`, `section_header`, `list_item`, `table`, `picture`, `caption`).
   - The resulting annotated image is saved to `output/overlay_page_<N>.png`.
   - A JSON manifest file is generated at `output/overlay_page_<N>.json` with the exact requested keys, including the page number, image dimensions, and the list of bounding boxes with their IDs, types, and colors.
