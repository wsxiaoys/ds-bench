# Signed Webhook Receiver with RedwoodSDK ## Background You are building a webhook receiver for an application built with RedwoodSDK (rwsdk), a server-first React framework for Cloudflare that stays close to the standard Web `Request`/`Response` APIs. An upstream service delivers events by POSTing a JSON payload to your endpoint. To make sure the payload really comes from the upstream service and was not tampered with in transit, every request is signed with an HMAC-SHA256 signature derived from a shared secret. Your endpoint must verify this signature before it trusts and processes the payload. ## Requirements Extend the RedwoodSDK application so that it exposes a signed webhook endpoint that authenticates and processes incoming events. * Add a route that handles `POST /webhook`. * Read the shared secret from the environment variable `WEBHOOK_SECRET`. * Compute the HMAC-SHA256 of the **raw, unmodified request body bytes** using `WEBHOOK_SECRET` as the key. Use the Web Crypto API (`crypto.subtle`) available in the Cloudflare Workers runtime; do not shell out to Node's `crypto` module. * The incoming request carries the expected signature in the `X-Signature-256` header, formatted as `sha256=<hex>`, where `<hex>` is the lowercase hexadecimal HMAC-SHA256 digest of the body. * Compare the computed signature against the header value using a constant-time comparison (do not use a plain `===`/early-return string comparison that can leak timing information). * If the `X-Signature-256` header is missing, or the signature does not match, respond with HTTP `401`. * If the signature is valid, parse the request body as JSON and process it. A valid payload is a JSON object with a string field `event` and an array field `items`. Respond with HTTP `200` and a JSON body of the shape `{ "ok": true, "event": <event>, "count": <number of items> }`, and set the response `Content-Type` to `application/json`. * If the signature is valid but the request body is not valid JSON, respond with HTTP `400`. ## Implementation Hints * In RedwoodSDK you register handlers inside `defineApp` using the `route` helper; you can attach method-specific handlers (such as `post`) by passing an object of method keys to `route`. * The handler receives the standard Web `Request`; read the raw body once (e.g. as text or an `ArrayBuffer`) and reuse those exact bytes both for signature verification and for JSON parsing so the signed content matches what you parse. * Import `env` from `cloudflare:workers` to access `WEBHOOK_SECRET` at runtime. * `crypto.subtle.importKey` + `crypto.subtle.sign` with the `HMAC` algorithm and the `SHA-256` hash produce the raw signature bytes; convert them to a lowercase hex string to compare with the header value. * A constant-time comparison should always inspect every byte regardless of where a mismatch occurs. ## Project * Project path: `/home/user/webhook-app` * Start command: `npm run dev` * Port: `5173` * The `WEBHOOK_SECRET` environment variable is already provisioned in the project environment.
