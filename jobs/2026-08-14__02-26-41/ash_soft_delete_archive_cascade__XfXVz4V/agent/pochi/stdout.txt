# Cascading Soft-Delete, Global Read Scoping and Archive Recovery (Ash Framework v3) ## Background `/home/user/forum` holds a Mix project (OTP app `:forum`) for a discussion-forum backend built on the Ash Framework v3 (`ash 3.31.0`). Content is three levels deep: a post owns comments, and a comment owns reactions. Deleting content in this product is never destructive: removed content stays in storage, stays invisible to ordinary readers, can be inspected by an administrator, and can be recovered later. Recovery has to be *precise* — undoing a deletion must bring back exactly what that deletion removed and must not resurrect content that had already been deleted by an earlier, unrelated operation. The project currently contains only the domain shell and the project configuration. Everything described below is missing and must be built. ## Requirements ### Domain and resources The domain module `Forum.Content` (`lib/forum/content.ex`) must expose exactly these three resources, each using `Ash.DataLayer.Ets` configured with `private? true`: | Module | File | Own attribute | | ------------------------ | ------------------------------- | ------------------------------------- | | `Forum.Content.Post` | `lib/forum/content/post.ex` | `title` — `:string`, public, required | | `Forum.Content.Comment` | `lib/forum/content/comment.ex` | `body` — `:string`, public, required | | `Forum.Content.Reaction` | `lib/forum/content/reaction.ex` | `emoji` — `:string`, public, required | Every one of the three resources also has: * a primary key attribute named `id` of type `:uuid`, generated by default; * a public attribute `archived_at` of type `:utc_datetime_usec`, `nil` for live records; * a public attribute `archive_batch_id` of type `:uuid`, `nil` for live records. Relationships: * `Forum.Content.Post` — a to-many relationship named `:comments` pointing at `Forum.Content.Comment`. * `Forum.Content.Comment` — a to-one relationship named `:post` pointing at `Forum.Content.Post`, backed by a required and externally writable foreign-key attribute `post_id`; and a to-many relationship named `:reactions` pointing at `Forum.Content.Reaction`. * `Forum.Content.Reaction` — a to-one relationship named `:comment` pointing at `Forum.Content.Comment`, backed by a required and externally writable foreign-key attribute `comment_id`. Aggregates: * `Forum.Content.Post` must expose a public `count` aggregate named `comment_count` over `:comments`. * `Forum.Content.Comment` must expose a public `count` aggregate named `reaction_count` over `:reactions`. ### Actions All three resources must define these seven actions under exactly these names: | Name | Action type | Input | | ---------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | | `:create` | create | the resource's own required attribute plus its foreign key (`post_id` for a comment, `comment_id` for a reaction) | | `:read` | read (**must be the resource's primary read action**) | none | | `:archived` | read | none | | `:with_archived` | read | none | | `:archive` | destroy | none | | `:restore` | update | none | | `:purge` | destroy | none | "Input: none" is binding: each of those actions must succeed when invoked with an empty parameter map and no additional arguments, e.g. `Ash.Query.for_read(Forum.Content.Post, :with_archived, %{})`, `Ash.Changeset.for_destroy(record, :archive, %{})` and `Ash.Changeset.for_update(record, :restore, %{})`. ### Archive semantics — action `:archive` * Nothing is ever removed from storage by `:archive`. * If the target record is already archived, the call still succeeds but nothing changes anywhere: the target keeps its existing `archived_at` and `archive_batch_id`, and no descendant is modified. * Otherwise the target and every descendant of the target that is not already archived (a post's comments and those comments' reactions; a comment's reactions) are archived together as one generation: all of them end up with the *same* non-`nil` `archived_at` value and the *same* non-`nil` `archive_batch_id` value. * Descendants that were already archived before the call keep their existing `archived_at` and `archive_batch_id` values byte-for-byte. * Two separate archive operations must never produce the same `archive_batch_id`. ### Restore semantics — action `:restore` * On a record that is not archived the call succeeds and changes nothing, anywhere. * On an archived record: the target's `archived_at` and `archive_batch_id` both become `nil`, and every descendant whose `archive_batch_id` equals the target's `archive_batch_id` as it was immediately before the call is restored the same way (`archived_at` and `archive_batch_id` set to `nil`), recursively. * Descendants carrying a different `archive_batch_id` are left exactly as they were. * `:restore` never affects ancestors of the target. ### Purge semantics — action `:purge` * Invoked on a record whose `archived_at` is `nil`, the action must fail and change nothing: the result must be `{:error, %Ash.Error.Invalid{errors: errors}}` where at least one element of `errors` is an `%Ash.Error.Changes.InvalidChanges{}` whose `:fields` is `[:archived_at]` and whose `:message` is exactly `"must be archived before it can be purged"`. * Invoked on an archived record, the record and every one of its descendants are permanently and irrecoverably removed from storage. ### Read scoping * `:read` returns only records whose `archived_at` is `nil`. This scoping is global, not merely top-level: it must also hold everywhere a resource is reached indirectly — relationship loads (`Ash.load/3`), the `comment_count` and `reaction_count` aggregates, and filter expressions that traverse a relationship — so archived records can never leak into a result derived from an ordinary read. * `:with_archived` returns both archived and live records. * `:archived` returns only records whose `archived_at` is not `nil`. * Fetching an archived record through the primary read (for example `Ash.get/3` with its default action) must produce an `Ash.Error.Query.NotFound`. ### Authorization * All three resources must run `Ash.Policy.Authorizer`. * An actor is a plain Elixir map. An actor is an administrator when its `:role` key equals `:admin`. * With authorization enabled, the `:archived` read must be reachable only by an administrator. For any other actor, including `nil`, the call must return `{:error, %Ash.Error.Forbidden{}}` — not an empty result set. * With authorization enabled, every other action on every resource must be permitted for every actor, including `nil`. ### Shared implementation modules Three modules must be written once and shared, rather than duplicated per resource: | Module | File | Behaviour | Must be referenced by | | ----------------------------------------- | ------------------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | | `Forum.Archive.Preparations.ArchiveScope` | `lib/forum/archive/preparations/archive_scope.ex` | `Ash.Resource.Preparation` | the `:read`, `:archived` and `:with_archived` actions of all three resources (directly on the action or through a resource-wide preparation) | | `Forum.Archive.Changes.CascadeArchive` | `lib/forum/archive/changes/cascade_archive.ex` | `Ash.Resource.Change` | the `:archive` action of all three resources | | `Forum.Archive.Changes.CascadeRestore` | `lib/forum/archive/changes/cascade_restore.ex` | `Ash.Resource.Change` | the `:restore` action of all three resources | ## Implementation Hints * Project path: /home/user/forum * The project must keep compiling as a standard Mix project: `mix compile` from `/home/user/forum` must succeed. 2. **Shared Implementation Modules**:
   - **`Forum.Archive.Preparations.ArchiveScope`**: Dynamically filters queries based on the read action. It filters out archived records for `:read` (primary read action), filters for archived records in `:archived`, and returns all records in `:with_archived`.
   - **`Forum.Archive.Changes.CascadeArchive`**: Handles soft-delete/archiving. When invoked, it groups the target and all its live descendants into a single generation with the same `archived_at` and `archive_batch_id` values. Already archived descendants are preserved byte-for-byte.
   - **`Forum.Archive.Changes.CascadeRestore`**: Handles restoring archived records. It sets the target's `archived_at` and `archive_batch_id` to `nil` and cascades down to restore only those descendants whose `archive_batch_id` matches the parent's pre-restoration batch ID.

3. **Read Scoping and Global Scoping**:
   - The primary read action `:read` is scoped globally. Archived records are filtered out of all relationship loads (`Ash.load/3`), filter expressions, and aggregates (`comment_count` and `reaction_count`).
   - Fetching an archived record through the primary read action (e.g., `Ash.get/3`) correctly results in an `Ash.Error.Query.NotFound` error wrapped in `Ash.Error.Invalid`.

4. **Purge Semantics**:
   - Purging a live record fails with an `%Ash.Error.Changes.InvalidChanges{}` error on the `:archived_at` field with the message `"must be archived before it can be purged"`.
   - Purging an archived record permanently and recursively removes the record and all of its descendants from ETS storage.

5. **Authorization**:
   - Configured `Ash.Policy.Authorizer` on all three resources.
   - Restricted the `:archived` read action to administrator actors (actors with `role: :admin`), while permitting all other actions for any actor (including `nil`).
