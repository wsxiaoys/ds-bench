## Root cause
Two configuration problems combined to break Capacitor's web asset detection:

1. **Folder name mismatch** — `angular.json` declared `outputPath: "dist/webapp"` while `capacitor.config.ts` declared `webDir: "dist/mobileapp"`. They pointed at two different folders.
2. **Missing browser sub-directory** — The `@angular-devkit/build-angular:application` builder treats a plain-string `outputPath` as a **base** directory and writes the browser bundle into a nested **`browser`** sub-folder inside it. So the built `index.html` actually lands at `dist/webapp/browser/index.html`, not `dist/webapp/index.html`. Capacitor was looking in a folder that never contained `index.html`.

## Fix
Updated `capacitor.config.ts` so `webDir` points at the real location of the compiled `index.html`:

```ts
// capacitor.config.ts
webDir: 'dist/webapp/browser',
```

This reconciles both issues at once:
- It matches the Angular `outputPath` base (`dist/webapp`).
- It includes the `browser` sub-directory that the application builder creates, so the folder Capacitor reads genuinely contains the built `index.html`.

No `outputPath` object form or static `index.html` was needed — the assets Capacitor reads are the genuine output produced by `npm run build`.
