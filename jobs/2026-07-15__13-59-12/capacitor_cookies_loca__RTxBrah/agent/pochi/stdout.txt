A small **local mock auth server is already provided** in the project (it runs on `http://localhost:8080` and also serves your built web assets). Your job is to enable Capacitor's cookie handling and implement the full session flow (login, session restore/persistence, an authenticated request, and a logout that clears the cookie) so it works end-to-end in a browser. The evaluation environment only has a CLI and a headless browser. There is **no** Android/iOS device, emulator, SDK, or native build. Everything runs locally against the provided mock server; do **not** call any external/third-party service or require internet access. ## Requirements * Enable Capacitor's cookie handling in `capacitor.config.ts` by turning on the `CapacitorCookies` plugin (also enable `CapacitorHttp`). Keep `webDir` pointing at the build output directory `dist`. * Implement a single-page web UI that talks to the provided mock server and drives a cookie-based session: * **Login**: submit a username and password to the server; on success the server responds with a `Set-Cookie: session=<token>` header and the UI must reflect the signed-in state. * **Session persistence**: when the page (re)loads, restore the signed-in state from the existing session cookie by calling the authenticated endpoint. Reloading the page while logged in must keep the user logged in. * **Authenticated request**: fetch the current user's profile from the protected endpoint using the session cookie. * **Logout**: invalidate the session on the server **and clear the session cookie on the client** so the browser no longer holds it. * **Error handling**: invalid credentials must show an error and must not create a session. ## Provided Mock Server (do not modify its contract) The server lives under `mock-server/` in the project and is started by `npm run start`. It serves the built `dist/` at `/` and exposes these JSON endpoints on the same origin (`http://localhost:8080`): * `POST /api/login` — request body `{ "username": string, "password": string }`. * Valid credentials: username `demo` / password `capacitor`, and username `alice` / password `wonderland`. * On success: status `200`, body `{ "username": "<username>" }`, and a `Set-Cookie: session=<token>; Path=/; SameSite=Lax` header (the cookie is readable from `document.cookie`). * On failure: status `401`, body `{ "error": "invalid credentials" }`. * `GET /api/me` — reads the `session` cookie. Valid session: status `200`, body `{ "username": "<username>" }`. Missing/invalid session: status `401`, body `{ "error": "unauthorized" }`. * `POST /api/logout` — reads the `session` cookie and **invalidates that token server-side**.
