## How it works

- **Key encoding**: Each setting is stored under a Preferences key shaped `<namespace>::<settingKey>` (delimiter `::`). Filtering uses the full prefix `<namespace>::`, which is delimiter-aware: the namespace `app` (prefix `app::`) never matches keys of `appearance` (whose keys look like `appearance::...`), so namespaces stay fully isolated even when one name is a textual prefix of another.
- **Type preservation**: Preferences only stores strings, so values are serialized with `JSON.stringify` on `set` and parsed with `JSON.parse` on `get`. A number stays a `number`, a boolean stays a `boolean`, a string stays a `string`.
- **Typed defaults**: The fixed schemas are declared in `SCHEMAS`:
  - `app`: `theme="light"`, `fontSize=14`, `notifications=true`
  - `appearance`: `theme="system"`, `accent="blue"`
  - `editor`: `tabSize=4`, `wordWrap=false`

## API (all methods return Promises)

- `get(namespace, key)` → effective value (stored override, else default); rejects for unknown namespace/key.
- `set(namespace, key, value)` → persists via Preferences; rejects for unknown namespace/key.
- `reset(namespace)` → removes only the overrides whose Preferences key starts with `<namespace>::`; other namespaces untouched.
- `keys(namespace)` → sorted ascending list of that namespace's setting keys that have a stored override, derived from `Preferences.keys()` and delimiter-aware filtering.
- `exportNamespace(namespace)` → plain object of every schema key mapped to its effective value (defaults merged with overrides).
- `importNamespace(namespace, data)` → persists each known setting key present in `data`; keys not in the schema are ignored.
