## What it does

`createVersionedStore(config)` builds a small, reusable versioned store on top of `@capacitor/preferences`. All persistence goes exclusively through `Preferences.set` / `Preferences.get` / `Preferences.remove` (no direct `localStorage` access).

### Envelope format
Every value is persisted as a JSON string of an envelope object with exactly two top-level keys:
```json
{"version":3,"data":{...}}
```

### API (all async)
- **`get()`** — returns `null` when the key is absent. When the stored version equals the current version, returns the stored `data` unchanged. When the stored version is **less than** the current version, it runs the migration chain (applying `migrations[n]` for `n = storedVersion … currentVersion - 1` in ascending order, feeding each output into the next), persists the upgraded envelope back stamped with the current version (so migration happens once), and returns the upgraded `data`. When the stored version is **greater than** the current version, it rejects without modifying the stored value.
- **`set(value)`** — persists an envelope stamped with the store's current `version`.
- **`remove()`** — deletes the key so a subsequent `get()` returns `null`.

### Atomicity
The migration chain is computed fully *before* any write. If any migration function throws, the error propagates and `Preferences.set` is never called, leaving the original envelope in storage exactly as it was.

### Durability
After a successful migration on read, the upgraded envelope is written back, so subsequent reads return the migrated data without re-running migrations.
