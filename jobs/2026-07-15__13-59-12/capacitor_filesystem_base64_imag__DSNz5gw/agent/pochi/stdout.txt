## What the code does

1. **Load & encode** — `fetch("/sample.png")` → `arrayBuffer()` → `Uint8Array`, then base64-encodes the raw bytes via a chunked `String.fromCharCode` + `btoa` approach (chunked to avoid the call-stack limit and to handle bytes > 0x7F correctly as binary, not UTF-8).

2. **Write (binary)** — `Filesystem.writeFile` to `Directory.Data` at path `images/roundtrip/sample.png` with `recursive: true` and **no `encoding`** option. Per the plugin contract, omitting `encoding` means the supplied base64 string is decoded to raw bytes and stored as binary.

3. **Read (binary)** — `Filesystem.readFile` from the same path with **no `encoding`**, which returns the data as a base64 string. The base64 is decoded back to a `Uint8Array`.

4. **Integrity check** — SHA-256 of both the original and read-back byte arrays computed with `crypto.subtle.digest("SHA-256", …)`, formatted as lowercase hex. The two digests are compared.

5. **Directory listing** — `Filesystem.readdir` on `images/roundtrip` in `Directory.Data`; entry names are comma-joined.

6. **DOM rendering** — Populates the existing elements with exact required contents:
   - `#status` → `OK` / `FAIL`
   - `#original-hash` → lowercase hex SHA-256 of original bytes
   - `#readback-hash` → lowercase hex SHA-256 of read-back bytes
   - `#match` → `true` / `false`
   - `#byte-length` → decimal byte length of original image
   - `#write-uri` → the `uri` returned by `writeFile`
   - `#dir-listing` → comma-separated entry names (includes `sample.png`)

7. **Error handling** — Any thrown error sets `#status` to `FAIL` and logs the cause; it never leaves the status blank.
