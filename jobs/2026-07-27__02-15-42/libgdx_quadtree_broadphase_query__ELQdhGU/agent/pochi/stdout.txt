# QuadTree Broadphase Collision Reporter (libGDX Headless) ## Background You are building the collision broadphase for a deterministic 2D physics tick simulator. Many axis-aligned rectangular entities move around a square world. On every tick you must (1) advance every entity, (2) index all entities in a region **QuadTree**, (3) use the QuadTree to enumerate broadphase candidate pairs, and (4) run an exact narrowphase to report the pairs whose axis-aligned bounding boxes truly overlap. The program is a **libGDX** application that MUST run on the **headless backend** (no OpenGL / no window). Use libGDX (`com.badlogicgames.gdx`) version **1.14.2** and its math/collection types for the geometry. ## Requirements * Read a scenario from an input file, run exactly `numTicks` simulation ticks, and write a deterministic report to an output file. * Maintain a region QuadTree over the fixed world for each tick and use it as a broadphase (candidate-pair generator), then confirm overlaps with an exact axis-aligned narrowphase. * The application must be a Gradle project that runs under the libGDX headless backend and must exit on its own after producing output. ## Implementation Hints * Project path: `/home/user/quadtree-broadphase` * The project MUST be a Gradle build using the libGDX **headless** backend, pinned to libGDX `1.14.2`. It MUST be runnable, from the project root, with: ``` ./gradlew --no-daemon --console=plain --quiet :headless:run --args="<inputPath> <outputPath>" ``` where `<inputPath>` and `<outputPath>` are absolute file paths. The program reads the scenario from `<inputPath>`, writes the report to `<outputPath>` (overwriting any existing file), and then terminates the headless application by itself. Only the report may be written to `<outputPath>`; nothing else in the process should write to it. ### Fixed world and QuadTree parameters (constants, not read from the file) * World bounds: a square with bottom-left corner `(0, 0)` and top-right corner `(1024, 1024)`. The coordinate system is y-up (larger y = North). The root QuadTree node covers exactly this world. * Node capacity `C = 3`. * Maximum depth `MAX_DEPTH = 6`, with the root node at depth `0`. A node at depth `6` never subdivides. ### Input file format Whitespace-separated integers (tokens may be split across lines arbitrarily), read strictly in this order: 1. `numEntities` `numTicks` 2. Then `numEntities` records, each of 7 integers: `id cx cy hx hy vx vy` * `id`: unique non-negative integer entity id. * `(cx, cy)`: entity center position at time 0 (before any tick). * `(hx, hy)`: positive half-extents. The entity's axis-aligned box spans `[cx-hx, cx+hx] x [cy-hy, cy+hy]`. * `(vx, vy)`: per-tick integer velocity. ### Tick integration * Ticks are numbered `1, 2, ..., numTicks`. The time-0 state read from the file is NEVER reported. * At the start of each tick, advance every entity by exactly one step: `cx += vx`, `cy += vy` (half-extents are constant). Then build the tree and report. Positions may move outside the world bounds. ### QuadTree construction (rebuilt fresh every tick) * Insertion always begins at the root. At a node: * If the node is subdivided (internal), find the FIRST child, in the order **NW, NE, SW, SE**, that fully contains the entity's box; descend and insert there. If no child fully contains the box, store the entity at the current node. * If the node is a leaf, store the entity at that node; then, if the node now holds MORE THAN `C` entities and its depth `< MAX_DEPTH`, subdivide it (see below). * A child with bounds `[minX,maxX] x [minY,maxY]` **fully contains** an entity box iff `boxMinX >= minX && boxMaxX <= maxX && boxMinY >= minY && boxMaxY <= maxY` (inclusive comparisons). Consequently, the root stores any entity not fully contained by one of its children, including entities extending beyond the world bounds. * Child regions of a node with bounds `[minX,maxX] x [minY,maxY]`, where `midX=(minX+maxX)/2`, `midY=(minY+maxY)/2`: * **NW** = `[minX,midX] x [midY,maxY]` * **NE** = `[midX,maxX] x [midY,maxY]` * **SW** = `[minX,midX] x [minY,midY]` * **SE** = `[midX,maxX] x [minY,midY]` * Subdividing a leaf: create its four empty children (NW, NE, SW, SE), remove the entities currently stored at the node, then re-insert those entities back into the (now internal) node ONE BY ONE, in their current stored order (which equals the order in which they were originally inserted). Re-insertion follows the same rules above, so cascading subdivision may occur. ### Broadphase candidate pairs * Define the candidate-pair count `K` for a tick as the number of unordered pairs of DISTINCT entities `{a, b}` that share a broadphase bucket, i.e. entity `a` and entity `b` are stored either in the same node, or in two nodes where one node is an ancestor of the other. ### Narrowphase overlap * Two entities overlap iff their axis-aligned boxes share positive area. For boxes `a` and `b`: overlap iff `aMinX < bMaxX && aMaxX > bMinX && aMinY < bMaxY && aMaxY > bMinY` (strict). Boxes that only touch at an edge or corner do NOT overlap. Every truly overlapping pair is guaranteed to be a broadphase candidate. ### Output format (written to `<outputPath>`) For each tick `t` from `1` to `numTicks`, in order, emit this block: ``` TICK <t> CANDIDATES <K> TREE <signature> <idA>,<idB> <idA>,<idB> ... ``` followed by exactly one blank line after the block (including after the final tick). * `<K>` is the broadphase candidate-pair count defined above. * `<signature>` is a single-space-separated depth-first PRE-ORDER traversal of the tree. Visiting a node emits one token: `L<n>` if the node is a leaf, or `N<n>` if the node is internal (subdivided), where `<n>` is the number of entities stored directly at that node; when the node is internal its four children tokens follow immediately in **NW, NE, SW, SE** order. * The pair lines list every truly overlapping unordered pair for that tick. Write each as `idA,idB` with `idA < idB` (no spaces). Sort the pair lines ascending by `idA`, then by `idB`. If there are no overlapping pairs, emit no pair lines (the block is the three header lines followed by the blank line).
