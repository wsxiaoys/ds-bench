# Affine Transform Pipeline Interpreter (libGDX, Headless) ## Background Build a command-line interpreter that evaluates named 2D affine-transform pipelines and applies them to points and polygons. The interpreter runs on top of the libGDX game framework (version 1.14.2) using its non-rendering headless backend, so it performs no OpenGL calls and must run fully offline. ## Requirements * Read a pipeline program from a UTF-8 text file and write results to an output text file. * Support named pipeline definitions built from the primitive operations `translate`, `rotate`, `scale` and `shear`, plus references to previously-defined pipelines (nested composition). * Apply named pipelines to points and polygons, reporting the resulting transform matrix, the transformed geometry, the signed area and orientation for polygons, and an inverse round-trip check for probe points. * The program must run under a libGDX `HeadlessApplication` and terminate by itself. ## Input format The input file is UTF-8 text, processed line by line. Rules: * Text from a `#` character to the end of a line is a comment and is ignored. Blank lines are ignored. * Tokens are separated by arbitrary runs of spaces and/or tabs; leading and trailing whitespace on a line is ignored. * All keywords are lowercase and case-sensitive. Names match `[A-Za-z_][A-Za-z0-9_]*`. Numbers are decimal values parseable as a Java `float` (optionally signed, with an optional fractional part). All angles are in degrees. A pipeline definition is: ``` define <name> <operation> ... end ``` where each `<operation>` is exactly one of: * `translate <tx> <ty>` * `rotate <degrees>` * `scale <sx> <sy>` * `shear <shx> <shy>` * `use <otherName>` A `use <otherName>` operation may reference only a pipeline whose full `define ... end` block appears earlier in the same file (no forward references, no recursion, no cycles). Command lines appear only outside of `define ... end` blocks and are one of: * `point <name> <x> <y>` * `polygon <name> <x1> <y1> <x2> <y2> ... <xk> <yk>` (k >= 3 vertices, i.e. an even number of at least 6 coordinates) * `inverse <name> <x> <y>` ## Transform semantics A 2D affine transform is the 3x3 matrix (with implicit bottom row `0 0 1`) described by six numbers `m00 m01 m02 / m10 m11 m12`. A point `(x, y)` maps to: ``` x' = m00*x + m01*y + m02 y' = m10*x + m11*y + m12 ``` The primitive operations denote these matrices: * `translate tx ty` -> `m00=1 m01=0 m02=tx ; m10=0 m11=1 m12=ty` * `rotate d` -> counter-clockwise rotation: `m00=cos(d) m01=-sin(d) m02=0 ; m10=sin(d) m11=cos(d) m12=0` * `scale sx sy` -> `m00=sx m01=0 m02=0 ; m10=0 m11=sy m12=0` * `shear shx shy` -> `m00=1 m01=shx m02=0 ; m10=shy m11=1 m12=0` A pipeline evaluates to a matrix `M` as follows: start from the identity matrix; process the pipeline's operations in listed order (top to bottom); each operation `O` updates `M` by post-multiplication `M <- M . O` (the matrix product with the accumulated `M` on the left and the operation's matrix on the right). For a `use ` operation, `O` is the fully-evaluated matrix of the referenced pipeline. Consequently the operation listed last is the one applied first to a point. The determinant is `det = m00*m11 - m01*m10`. ## Output format Write results to the output file as UTF-8 text with Unix (LF) line endings, one line per command in the same order the commands appear in the input, and a trailing newline after the last line. Every numeric value is formatted with exactly four digits after the decimal point using a period as the decimal separator (US locale). Any value whose four-decimal rendering would be `-0.0000` must instead be written as `0.0000`. Tokens on a line are separated by single spaces. * For `point <name> <x> <y>`: `point <name> matrix <m00> <m01> <m02> <m10> <m11> <m12> image <x'> <y'>` * For `polygon <name> ...`: `polygon <name> matrix <m00> <m01> <m02> <m10> <m11> <m12> area <signedArea> orient <preserved|flipped|degenerate> image <x1'> <y1'> ... <xk'> <yk'>` where `<signedArea>` is the signed area of the transformed polygon computed by the shoelace formula over the transformed vertices in listed order, `A = 0.5 * sum over i of (xi'*y(i+1)' - x(i+1)'*yi')` with indices taken modulo k, and `orient` is `preserved` when `det > 0`, `flipped` when `det < 0`, or `degenerate` when `det == 0`. * For `inverse <name> <x> <y>`: let `p = (x, y)` and `q = M . p`. If `det == 0`, write exactly `inverse <name> matrix <m00> <m01> <m02> <m10> <m11> <m12> singular`. Otherwise let `N = M^-1`, `b = N . q`, and `residual` be the Euclidean distance between `p` and `b`, then write `inverse <name> matrix <m00> <m01> <m02> <m10> <m11> <m12> forward <qx> <qy> back <bx> <by> residual <residual> <ok|fail>`, where the final token is `ok` when `residual <= 1e-3` and `fail` otherwise. ## Implementation Hints * Project path: /home/user/affine-pipeline * The project is a preconfigured Gradle project (Gradle 8.10, JDK 17) that already declares the libGDX 1.14.2 core and headless-backend dependencies and applies the `application` plugin with main class `com.example.affine.HeadlessLauncher`; all required dependencies are present in the local Gradle/Maven cache so the project builds and runs offline. Implement that main class and any supporting classes. * The program receives exactly two arguments, `--input=` and `--output=<path>`; it must read the pipeline program from the input path and write the results to the output path. * The program must run under a libGDX `HeadlessApplication`, must not perform any graphics or OpenGL calls, and must terminate on its own with exit status 0 after the output file has been fully written. * It must be runnable from the project path with: `gradle --offline run --args="--input=<inputPath> --output=<outputPath>"`.
