### Summary of Implementations

1. **`useDebouncedSignal<T>(source, delayMs)`**
   - Returns a read-only signal wrapping a internal debounced signal.
   - Uses Qwik's `useTask$` to track `source.value`.
   - On the server (SSR), it applies the value immediately with no timer or delay.
   - On the browser, it handles debouncing by setting a `setTimeout` and automatically cancels any pending timer using the `cleanup` function of `useTask$`.

2. **`useThrottledSignal<T>(source, intervalMs)`**
   - Returns a read-only signal with leading + trailing edge throttling.
   - Uses `useStore` to keep track of non-tracked throttling metadata (`lastAppliedTime`, `hasPending`, `pendingValue`).
   - On the server, it applies the value immediately with no timer.
   - On the browser:
     - **Leading edge**: If the elapsed time since the last applied update is greater than or equal to `intervalMs`, it updates immediately.
     - **Trailing edge**: Otherwise, it schedules a `setTimeout` for the remaining time to apply the latest value at the end of the current throttling window. It utilizes `cleanup` to clear previous timers if the source changes again within the same window, recalculating the remaining time precisely.

3. **`usePrevious<T>(source)`**
   - Returns a read-only signal holding the value `source` had immediately before its most recent change.
   - Tracks the source signal using `useTask$`, updating the previous value whenever a change is detected.
   - Correctly starts as `undefined` before any changes have occurred.

4. **`useInterval(callback, ms, enabled)`**
   - Takes a serializable QRL callback, an interval duration, and an `enabled` signal.
   - Tracks the `enabled` signal using `useTask$`.
   - On the server, it never starts any timers.
   - On the browser, it starts a `setInterval` when `enabled.value` is `true`, and clears the interval when it becomes `false` or when the component is unmounted.
