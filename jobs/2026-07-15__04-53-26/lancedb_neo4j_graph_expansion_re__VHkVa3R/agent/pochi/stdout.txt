# Graph-Augmented Retrieval: LanceDB Vector Seeds + Neo4j Multi-Hop Expansion ## Background You are building the retrieval core of a knowledge-graph RAG system. Dense vectors for every entity live in a local **LanceDB** table, while the relationships between entities live in a local **Neo4j** graph (already running on `bolt://localhost:7687`). Neither service needs internet access: LanceDB is an on-disk database at `/app/lancedb` and Neo4j is a local server seeded inside this container. A query is answered in three coordinated stages: (1) run a vector search in LanceDB to find the closest *seed* entities, (2) expand from those seeds along graph relationships in Neo4j to pull in related entities within a hop budget, and (3) fuse the vector similarity with a graph-proximity score so that entities that are both semantically similar *and* graph-close rank highest. ## Requirements * Implement a reusable retrieval function that coordinates LanceDB and Neo4j to return a fused, ranked result set. * Select seed entities via vector search in LanceDB. * Expand from the seeds through the Neo4j graph up to a caller-supplied hop limit, correctly handling directed cycles (traversal must terminate) and disconnected seeds (which simply expand to nothing). * Fuse vector similarity and graph proximity into a single score and return a deterministically ordered ranking. ## Implementation Hints * Use the `lancedb` Python client to open the on-disk database and the `neo4j` Python driver (Bolt) to run Cypher. Neo4j authentication is disabled, so connect with `auth=None`. * Data layout you must rely on: * LanceDB: `lancedb.connect("/app/lancedb")`, table name `nodes`, columns `id` (int64), `name` (utf8), and `vector` (fixed-size list of 32 float32 values). * Neo4j: entities are nodes with label `Entity` carrying integer property `id` and string property `name`; relationships are directed and typed `RELATED_TO`. The `id` values are identical across the two systems and are the join key. * Expose a function with exactly this signature in your solution module: `graph_expansion_search(query_vector, num_seeds, max_hops, top_k) -> list[dict]` where `query_vector` is a length-32 sequence of floats. * Scoring is fully specified and must be reproduced exactly: * `vector_similarity(n)` = cosine similarity between `query_vector` and node `n`'s stored 32-d vector. Compute it for every candidate node (seeds and expanded nodes alike) directly from the stored vectors. * Seeds = the `num_seeds` entities with the highest cosine similarity to the query (i.e. the LanceDB vector-search top results using cosine distance). * `hop_distance(n)` = the length of the shortest **directed** path (following outgoing `RELATED_TO` edges) from *any* seed to `n`, with seeds themselves at distance `0`; only nodes reachable within `max_hops` hops are candidates. * `graph_proximity(n)` = `DECAY ** hop_distance(n)` with `DECAY = 0.5`. * `fused_score(n)` = `ALPHA * vector_similarity(n) + (1 - ALPHA) * graph_proximity(n)` with `ALPHA = 0.6`. * The candidate set is the union of the seeds and every node reachable from any seed within `max_hops`. * Return the top `top_k` candidates ordered by `fused_score` descending, breaking ties by `id` ascending. Each element must be a dict with exactly the keys `id` (int), `name` (str), `vector_similarity` (float), `hop_distance` (int), `graph_proximity` (float), and `fused_score` (float). * Traversal must avoid infinite loops on cyclic subgraphs and must not crash when a seed has no outgoing relationships. * Project path: /home/user/myproject * Put the function in `/home/user/myproject/solution.py` so it can be imported as `from solution import graph_expansion_search`.
