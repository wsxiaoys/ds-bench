Producers push embedding messages onto a **local Redis Stream**, and a durable consumer must move them into a **LanceDB** table with **exactly-once** effect. The hard part is crash-safety: the consumer uses a Redis **consumer group** so that a message is only removed from the pending-entries-list (PEL) after it has been durably committed. ## How it works

```
config ──► Redis connect ──► XGROUP CREATE (MKSTREAM, ignore BUSYGROUP)
                       │
                       ├──► XAUTOCLAIM loop from 0-0, min-idle=0, count=BATCH_SIZE
                       │     (recovery — re-delivers entries left pending by a prior crash)
                       │     → merge_insert on `id` → XACK
                       │
                       └──► XREADGROUP `>` loop, count=BATCH_SIZE, block=None
                             (drain — non-blocking, exits on empty response)
                             → create_table on first batch, else merge_insert on `id` → XACK

print:  DONE ingested=<int> reclaimed=<int>
exit:   0
```

## Crash safety / exactly-once effect

- **At-least-once delivery**: `XACK` runs strictly *after* the LanceDB commit. If the process dies mid-batch, the unacknowledged entries stay in the group's PEL for redelivery.
- **Recovery on startup**: `XAUTOCLAIM` with `min_idle_time=0` and `start_id=0-0` picks up any pending entry immediately, regardless of which consumer originally got it. The cursor is threaded through successive calls so multi-batch recovery works (`BATCH_SIZE=5`, 12 pending → 5+5+2 in three iterations).
- **Exactly-once effect in LanceDB**: every commit goes through `merge_insert("id").when_matched_update_all().when_not_matched_insert_all().execute(rows)`, so a re-delivered message overwrites its existing row instead of appending a duplicate. Verified: 2 distinct stream entries sharing the same business `id` resolve to a single row in the table.
- **Table schema on first batch**: `db.create_table(name, data=rows, mode="create")` so the schema is `id: string`, `text: string`, `vector: fixed_size_list<float32>[VECTOR_DIM]`.
