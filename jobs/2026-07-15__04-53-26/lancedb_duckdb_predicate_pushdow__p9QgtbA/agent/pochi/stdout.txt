Implemented `/home/user/project/run.py`, a single-file hybrid LanceDB + DuckDB analytics CLI.

## What it does

1. **Ingest (idempotent on every run)**
   - Reads `data/documents.jsonl` and builds a PyArrow table where the `vector` column is `pa.list_(pa.float32(), 8)` → `fixed_size_list<float32>[8]` (verified after ingest).
   - Drops any existing `documents` table in `./lancedb` and recreates it, then calls `table.optimize()` to fold the rows into the search index.

2. **LanceDB retrieve (no metadata filtering)**
   - `db.open_table('documents')` → `table.search(q).metric('l2').limit(top_k).to_arrow()` — returns raw nearest neighbors with the `_distance` column.
   - Query vector is cast to a Python list from a `pa.array(..., type=pa.float32())`.

3. **DuckDB analytics (all SQL)**
   - Registers the LanceDB Arrow result as a view `candidates` and loads `data/categories.csv` as table `categories`.
   - Predicate filtering (`in_stock = TRUE`, `price <= ?`, optional `category = ?`) happens inside DuckDB via parameterized SQL — apostrophes in category values are safe (parameter binding, not string interpolation).
   - Joins `candidates` ↔ `categories` on `category`, computes `ROW_NUMBER() OVER (PARTITION BY department ORDER BY distance ASC, id ASC) AS dept_rank`, and persists the result as `TEMP TABLE ranked` so the aggregation query can read it.
   - The aggregation query is `GROUP BY department` with `COUNT(*)`, `ROUND(AVG(price), 4)`, `MIN(distance)`, ordered by department name.

4. **Output**
   - Prints exactly one JSON object to stdout:
     - `hits`: surviving candidates ordered by ascending `distance`, ties broken by ascending `id`. Each item: `id`, `title`, `category`, `department`, `price`, `distance`, `dept_rank`.
     - `departments`: one object per surviving department ordered by ascending name, with `department`, `num_docs`, `avg_price`, `min_distance`.
