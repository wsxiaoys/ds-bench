**Key design points:**
- **Topology**: declares `documents.dlx` (fanout, durable), `documents` (durable, quorum, x-dead-letter-exchange=documents.dlx), `documents.dlq` (durable, quorum, bound to dlx).
- **Consume**: `basic_get` with `auto_ack=False` in a tight loop, exits as soon as the broker reports the queue empty — no blocking forever.
- **Poison handling**: `parse_document` rejects non-UTF-8, non-JSON, non-dict, missing/non-string id/text, empty id/text; each failure → `basic_nack(requeue=False)` so the broker dead-letters via the DLX.
- **Dedup**: `load_existing_ids` hydrates a `seen_ids` set from LanceDB on startup; an in-run seen set catches duplicates within the current batch.
- **Embedding**: lowercase → `re.findall(r"[a-z0-9]+", …)` → MD5 mod 64 → accumulate → L2-normalize (no-op if norm==0). Result is float32, length 64.
- **Write order per batch** (the durability invariant the task calls out): (1) `table.add(pyarrow_table)` to LanceDB, (2) write JSON line to `commits.log` and `os.fsync` the fd, (3) increment batch_index, (4) `basic_ack` every delivery tag in the batch. A partial final batch is flushed before exit.
- **Batch index**: starts at `max(existing)+1` from `commits.log`, so reruns keep the sequence strictly increasing across the life of the file.
- **Stdout**: exactly one final line `INGEST_DONE written=<W> skipped_duplicates=<D> dead_lettered=<P>`.

**LanceDB schema** (verified): `id: string`, `text: string`, `vector: fixed_size_list<item: float>[64]`, at `/home/user/project/data/lancedb`, table `documents`.
