## Approach

A LanceDB `*.lance` directory already encodes the entire version history on disk through per-version `*.manifest` files under `_versions/` and the immutable fragments in `data/` (plus transactions and deletion vectors). A faithful snapshot therefore doesn't need to inspect Lance internals — it just needs to copy the whole tree.

**`backup`** — walks `local_table_path` recursively and uploads each file with key = `<prefix>/<relative-path>`, using the `AWS_ENDPOINT_URL` / `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_DEFAULT_REGION` env vars. `upload_file` is multipart-aware so any fragment size is handled correctly.

**`restore`** — first issues a `list_objects_v2` against the prefix and raises `FileNotFoundError("No backup found ...")` immediately if the snapshot is missing. Only after a non-empty listing does it download every object into a `tempfile.TemporaryDirectory` *sibling* of the destination (so the final `shutil.move` is an atomic `rename(2)`), then publishes the directory under `new_local_table_path`. Any failure during download raises out of the function with the staging directory cleaned up; the destination either comes back fully restored or doesn't exist at all.
