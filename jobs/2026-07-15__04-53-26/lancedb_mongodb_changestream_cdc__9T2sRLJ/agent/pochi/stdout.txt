Implemented `/home/user/project/sync.py`, a MongoDB → LanceDB CDC synchronizer.

**Key design decisions:**
- **Change stream:** `coll.watch(full_document='updateLookup', resume_after=token?)` opened with a context manager and drained via `try_next()` in a loop, exiting as soon as the server has no more events buffered. This satisfies the non-blocking requirement.
- **Upsert:** `table.merge_insert("id").when_matched_update_all().when_not_matched_insert_all().execute([row])` — works for inserts, updates, and replaces uniformly.
- **Delete:** `table.delete("id = '...'")` with single-quote escaping in the id.
- **Embedding:** `hashlib.sha256(text.encode("utf-8")).digest()[:8]` → `[b / 255.0 for b in ...]`, stored as `pa.list_(pa.float32(), 8)` to match the required 8-dim float32 fixed-size list.
- **Resume token:** persisted to `/home/user/project/resume_token.json` *after every event* and again after the drain, so even a no-event run, a crash mid-drain, and a successful run all leave a valid token. Write is atomic (`os.replace` on a temp file). Loaded tokens (which contain an `_data` key from pymongo) are passed back to `watch(resume_after=...)`; on first run no token is loaded and the stream opens fresh from the current position.
- **Schema:** the table is created with exactly `id: string, text: string, category: string, vector: fixed_size_list<float32>[8]`, reused on subsequent runs.
- **Re-runnability:** re-running when no new events leave the table unchanged; the only side effect is writing the current resume token (which now reflects a fresh post-batch position).
