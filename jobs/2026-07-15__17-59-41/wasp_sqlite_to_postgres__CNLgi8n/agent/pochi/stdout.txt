Remove the existing `migrations/` directory (and clear Wasp's cached artifacts), then create a brand-new initial migration for PostgreSQL. Each time the startup job runs it must insert exactly **one** new `EventLog` row. * The existing `GET /api/stats` endpoint must return HTTP 200 with a JSON body of the shape `{ "taskCount": <number> }`, where `<number>` is the current count of `Task` rows read from the database. * Start command: `wasp start` (the Wasp server listens on port `3001` and the web client on port `3000`).
