## How it works

### Stage 1 — Vector seeds (LanceDB)
All 60 node rows are fetched from the `nodes` table via `table.to_pandas()`. Cosine similarity is computed directly from the stored float32 vectors for every node (both for seed selection and for final scoring). The `num_seeds` nodes with the highest cosine similarity to `query_vector` become the BFS frontier (ties broken by `id` ascending).

### Stage 2 — Graph expansion (Neo4j BFS)
Starting from the seeds at hop distance 0, a BFS runs layer-by-layer using Cypher:
```cypher
UNWIND $frontier AS src_id
MATCH (:Entity {id: src_id})-[:RELATED_TO]->(nb:Entity)
WHERE NOT nb.id IN $visited
RETURN DISTINCT nb.id AS id
```
The `visited` set is passed into Cypher on every step, so directed cycles (e.g., `0→1→2→0`) terminate naturally — once a node is in `visited` it is never enqueued again. Disconnected seeds simply return an empty `next_frontier` and the loop exits immediately.

### Stage 3 — Score fusion and ranking
For every candidate (seeds ∪ expanded nodes within `max_hops`):
- `vector_similarity(n)` = cosine similarity computed from stored vector
- `graph_proximity(n)` = `0.5 ** hop_distance(n)`
- `fused_score(n)` = `0.6 × vector_similarity + 0.4 × graph_proximity`

Results are sorted by `fused_score` descending, ties broken by `id` ascending, then trimmed to `top_k`.
