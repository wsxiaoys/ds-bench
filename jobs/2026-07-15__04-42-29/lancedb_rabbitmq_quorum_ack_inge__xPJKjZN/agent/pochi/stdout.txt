## What was built

### Broker topology (`declare_topology`)
Declared idempotently on every run:
- Fanout exchange **`documents.dlx`** (durable) — the dead-letter exchange.
- Quorum queue **`documents`** (durable) with `x-dead-letter-exchange → documents.dlx`.
- Quorum queue **`documents.dlq`** (durable), bound to `documents.dlx`.

### Poison-message detection (`parse_document`)
Rejects with `basic_nack(requeue=False)` — causing the broker to forward to the DLQ — for any message that:
1. Is not valid UTF-8.
2. Is not valid JSON.
3. Decodes to something other than a JSON object (`dict`).
4. Has a missing or empty `id` string.
5. Has a missing or empty `text` string.

### Deterministic 64-dim embedding (`embed`)
Implements the spec exactly:
1. Lowercase + regex `[a-z0-9]+` tokenisation.
2. Zero vector of length 64.
3. `idx = MD5(token) % 64`, increment `vec[idx]` by 1.0.
4. L2-normalise (skip if norm == 0).
Returns `float32`.

### Deduplication (two-tier)
- **Cross-run**: on startup, `load_existing_ids` reads all `id` values from the LanceDB table via `table.to_arrow()` into an in-memory set (`existing_ids`).
- **Within-run**: a second set `seen_this_run` catches duplicates that arrive in the same invocation before they would hit LanceDB.
Duplicates are ack'd immediately (they are valid messages, just already processed) and counted in `skipped_duplicates`.

### Batch write + ack ordering (`_flush_batch`)
Messages accumulate in `batch_buffer` up to `INGEST_BATCH_SIZE` (env var, default 16). When the buffer is full (or at end-of-queue), `_flush_batch`:
1. Builds a typed PyArrow table and calls `table.add(pa_batch)` — durable write first.
2. Appends one JSON line to `commits.log` with the 0-based `batch_index` and ordered `ids` list.
3. Only then acks every delivery tag in the batch.

This guarantees **ack-after-persist**: a crash between write and ack causes redelivery on the next run, which the dedup layer handles.

### Commits log (`read_next_batch_index` / `append_commit`)
`batch_index` is strictly increasing across all runs: on startup the log is scanned for the current maximum, and the next run starts from `max + 1`.

### Stdout summary
Exactly one line on completion:
```
INGEST_DONE written=<W> skipped_duplicates=<D> dead_lettered=<P>
```
