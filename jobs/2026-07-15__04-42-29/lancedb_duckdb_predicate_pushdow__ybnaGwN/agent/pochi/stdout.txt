## Implementation complete — `/home/user/project/run.py`

### What was built

A single, self-contained `run.py` that is fully rerunnable:

| Stage | Detail |
|---|---|
| **Ingestion (idempotent)** | On first run, reads `documents.jsonl`, builds a PyArrow table with schema `fixed_size_list<float32>[8]` for the vector column, writes it into LanceDB at `/home/user/project/lancedb`, then calls `table.optimize()` to fold data into the ANN index. On subsequent runs the existing table is detected and reused. |
| **Vector search** | `table.search(query, query_type="vector").metric("l2").limit(top_k).to_arrow()` — pure nearest-neighbour, no metadata pre-filter, returns a PyArrow table including `_distance`. |
| **DuckDB analytics** | The Arrow result is registered as a virtual relation. A single CTE chain does: `JOIN categories` (from `read_csv_auto`), `WHERE in_stock AND price <= $1 [AND category = $2]`, then `ROW_NUMBER() OVER (PARTITION BY department ORDER BY distance, id)` for `dept_rank`, then a `GROUP BY department` aggregation for the `departments` summary. Category values with apostrophes (`Women's Apparel`, `Kids' Toys`, `Men's Shoes`) are passed via DuckDB parameter binding (`$2`) so they never touch string interpolation. |
| **Output** | Exactly one JSON object to stdout with keys `hits` and `departments` matching the specified schema. |
