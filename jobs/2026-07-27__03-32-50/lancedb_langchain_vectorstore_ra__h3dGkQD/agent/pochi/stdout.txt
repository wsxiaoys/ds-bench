Implemented `/home/user/rag/solution.py`, an importable module that builds and queries a fully offline LanceDB-backed LangChain retrieval layer.

Key design points:

- **`build_index()`**: Loads `corpus.json`, embeds all texts with `HashEmbeddings`, and writes them to the `documents` table at `/home/user/rag/lancedb` using `mode="overwrite"` so repeated calls always leave exactly one copy of the corpus (verified: 3 consecutive calls → still 24 rows, no dupes). Each record stores `vector`, `id`, `text`, a nested `metadata` struct (`doc_id`, `source`, `section`, `timestamp` — required for LangChain's `Document.metadata` population), plus flattened top-level copies of those same fields so callers can write simple SQL predicates like `"source = 'guide'"` instead of needing `metadata.source`. Returns the LangChain `LanceDB` vector store instance.

- **`get_retriever(search_type, search_kwargs)`**: Returns a custom `LanceDBRetriever(BaseRetriever)`. This was necessary because `langchain_community==0.3.27`'s `LanceDB.max_marginal_relevance_search` does not forward `prefilter` (or any extra kwargs) down to the underlying LanceDB query — relying on the default `VectorStoreRetriever` would silently turn `where` into a post-filter for MMR. The custom retriever calls the vector store's lower-level, kwarg-forwarding APIs directly (`similarity_search(..., prefilter=True)` for `"similarity"`, and `max_marginal_relevance_search_by_vector(..., prefilter=True)` for `"mmr"`), guaranteeing true SQL pre-filtering in both modes. `search_kwargs` supports `k`, `fetch_k`, `lambda_mult`, and `where`.

- **`retrieve(query, k, where=None)`**: Similarity search with `where` applied as a pre-filter; returns ranked `doc_id` list.

- **`retrieve_mmr(query, k, fetch_k, lambda_mult, where=None)`**: MMR search via the same pre-filter-safe path; returns `doc_id` list in MMR selection order.

Verified via direct testing:
- Determinism across repeated calls and fresh processes (identical ranked `doc_id` lists).
- No duplicate rows after multiple `build_index()` calls.
- Pre-filtering confirmed to occur before vector search (e.g., a filter matching only 1 of 24 rows returns exactly that 1 row even when `k=10`).
- Both `retrieve`/`retrieve_mmr` and the `get_retriever`-produced retriever (both `"similarity"` and `"mmr"` search types) return correct, filter-honoring, ranked results with `doc_id` recoverable from `Document.metadata`.
- Empty-filter and `k` larger than corpus size edge cases behave correctly.
