**Design:**
- Each task gets a private `_TaskResume` helper object (a `RefCounted` with `signal fired`). A task's body suspends via `await t.resume.fired`, and the scheduler resumes it by calling `t.resume.fired.emit()` — Godot resumes an awaited coroutine synchronously inside `emit()`, which is what guarantees deterministic, in-order, same-frame resumption chains (including cascading `on_complete` calls) exactly as specified.
- `spawn()` is itself a coroutine (`await _run_task(...)`), so calling it without `await` runs the body synchronously up to its first suspension/completion, matching the required semantics.
- `wait_frames`/`wait_until`/`wait_signal` look up the currently-running task via a scheduler-tracked `_current_task_id` (set right before every body invocation/resumption), record the wait condition on the task, and suspend on the task's private resume signal.
- `advance()` increments `current_frame`, then walks tasks once in ascending id order, resuming any whose condition is met (frame target reached, `cond.call()` true, or signal-fired flag set via a connected one-shot-style callback since the wait began).
