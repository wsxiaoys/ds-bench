Implemented `/home/user/project/pipeline.py`, a Prefect 3.4.20 pipeline that:

- Fans out 12 independent `process_unit` tasks (ids 0-11) via `@flow(task_runner=ThreadPoolTaskRunner(max_workers=12))`, so all 12 submit and contend concurrently.
- Throttles each unit with `prefect.concurrency.sync.concurrency("render-pool", occupy=1, strict=True)`, holding the slot for the whole simulated work (`time.sleep(1.0)`), so occupancy never exceeds — and under contention actually reaches — the limit's live server-side value. `strict=True` also guards against the limit vanishing mid-run.
- Is a pure consumer of `render-pool`: it only reads/acquires/releases slots, never creates/updates/deletes the limit (that's done once beforehand with `prefect gcl create render-pool --limit 3`).
- Checks `render-pool` exists (via `client.read_global_concurrency_limit_by_name`) *before* submitting any work; if it's missing, it prints an error and `sys.exit(1)` without running the batch.
- Writes exactly one `acquire` event right after each slot is acquired and one `release` event right after each slot is released to `occupancy.jsonl` (keys: `event`, `unit`, `ts`), guarded by a `threading.Lock` so concurrent writes from the thread pool never interleave/corrupt lines. The file is truncated (`write_text("")`) at the start of every run, including failed runs.
