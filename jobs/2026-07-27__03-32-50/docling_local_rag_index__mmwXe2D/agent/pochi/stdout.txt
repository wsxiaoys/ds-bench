Implemented /home/user/project/main.py as a single-file, two-subcommand CLI:

**`index --docs <DIR> --index <PATH>`**
- Validates `<DIR>` exists and contains `*.pdf` files (exit 3 otherwise).
- For each PDF (processed in sorted, deterministic order), uses Docling's `DocumentConverter` (offline, using the pre-baked local models) to convert the PDF, then `HierarchicalChunker` (from `docling.chunking`) to produce heading-aware chunks. `HierarchicalChunker` was chosen over `HybridChunker` because `HybridChunker`'s default tokenizer tries to download `sentence-transformers/all-MiniLM-L6-v2` from the Hugging Face Hub, which is unavailable offline — `HierarchicalChunker` needs no tokenizer and still yields heading-scoped, per-doc-item chunks.
- Each chunk's stored `text` is `chunker.contextualize(chunk)`, which prepends the ordered heading path to the chunk body (heading-contextualized serialization).
- Table items are serialized by Docling's built-in `TripletTableSerializer` as `"Row, Column = Value"` triplets, so every row-chunk already embeds its column/header context and remains self-describing.
- Page number is taken from the first `prov` entry of the chunk's first doc item; heading path is `chunk.meta.headings` (or `[]`).
- Persists all chunks into a SQLite file with a `chunks` table (`chunk_id`, `source`, `page`, `heading_path` as JSON array, `text`).
- Idempotency: each `index` run fully clears (`DELETE FROM chunks`) and repopulates the table from a fresh, deterministic conversion/chunking pass, so repeated runs on the same documents produce an identical chunk set (verified byte-for-byte across two consecutive runs).
- Prints `{"documents": N, "chunks": M}` to stdout and exits 0. All Docling logging goes to stderr, keeping stdout clean.

**`query --index <PATH> --query <STR> --top-k <K>`**
- Validates `<PATH>` exists (exit 4 otherwise).
- Loads all chunks and scores them against the query using a local, deterministic Okapi BM25 implementation (pure Python regex tokenization + `math.log`, no external services/models), guaranteeing offline reproducibility.
- Returns the top-K results as a JSON array of `{text, source, page, heading_path, score}`, sorted by descending score with ties broken by ascending `chunk_id`, and exits 0.

**Argument/error handling**
- `argparse` subparsers (`required=True`) naturally exit with code 2 for unknown subcommands or missing required options; a custom `--top-k` type validator also triggers exit 2 for values `< 1`.

Verified end-to-end against the provided `corpus/` (climate.pdf, robotics.pdf, finance.pdf — 3 docs, 12 chunks total): index runs are idempotent (identical DB content across repeated runs), targeted queries for planted codenames (e.g. `VECTORBOND5501`) and table-row content (e.g. `Equity Rating BBB`) correctly surface the right table chunk with heading/page/source context, and all four required error paths (missing docs dir, docs dir with no PDFs, missing index file, invalid `--top-k`/missing args/unknown subcommand) return the specified exit codes (3, 3, 4, 2 respectively).
