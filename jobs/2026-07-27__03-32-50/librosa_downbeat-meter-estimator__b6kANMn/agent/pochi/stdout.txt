Implemented `/home/user/project/estimate_downbeats.py`, a deterministic CLI tool that:

1. Loads the mono WAV at its native sample rate and runs `librosa.beat.beat_track` (on a precomputed onset-strength envelope, `trim=False`) to get beat frames/times and a global tempo estimate.
2. Builds a per-beat accent signal from two beat-synchronous sources, each sampled in a small window centered exactly on each beat frame (avoiding the off-by-one alignment issues of `librosa.util.sync` when the first beat isn't at frame 0):
   - Onset-strength envelope (max within the window) — captures percussive attack strength per beat.
   - Chroma-CQT based harmonic novelty (1 − cosine similarity between consecutive beats' normalized chroma vectors) — captures harmonic change, which tends to spike at bar boundaries.
   - Both are z-score normalized and averaged 50/50 into a single `accent` array, one value per beat.
3. Estimates the **meter** by testing candidates {2, 3, 4, 6}: for each candidate, beats are grouped by `index mod meter` and a one-way ANOVA F-statistic (between-group variance / within-group variance) scores how well that grouping explains the accent's periodicity. The meter with the highest F-statistic wins — this metric is comparable across differing numbers of groups, unlike a raw peak-to-average ratio.
4. Determines the **downbeat phase** in `[0, meter)` as the phase whose beats have the largest total accent, then emits `downbeat_indices` as an arithmetic sequence (`phase, phase+meter, phase+2*meter, ...`).
5. Writes a single JSON object with exactly the required keys: `tempo`, `beat_times`, `meter`, `downbeat_indices`, `downbeat_times`.
