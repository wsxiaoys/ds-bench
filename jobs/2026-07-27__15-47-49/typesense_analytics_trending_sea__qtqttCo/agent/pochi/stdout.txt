The widget must reflect the data returned by `GET /api/trending` and must load it when the page loads. * A zero-results panel with `id="no-results"` that is hidden while there are results and is shown when a search returns no products. It contains a suggestions list with `id="suggestions"` whose items have class `suggestion-item`, each containing a suggested query string. ## How It Works

**Startup (`npm start`):**
1. Reads the Typesense API key from `/etc/typesense-api-key` (falls back to `xyz`)
2. Creates the `catalog` collection and imports all 12 products
3. Creates `popular_queries` and `nohits_queries` destination collections (with `q` and `count` fields, `q` sortable)
4. Creates two analytics rules:
   - `popular_queries_rule` — tracks queries that return results into `popular_queries`
   - `nohits_queries_rule` — tracks queries with zero results into `nohits_queries`

**API Endpoints (port 3000):**
- `GET /api/search?q=<term>` — searches the catalog, returns `{query, found, hits, suggestions}`
- `GET /api/trending` — returns `{trending: [{q, count}]}` sorted by count desc, then q asc
- `GET /` — serves the single-page UI

**Web UI:**
- Search input (`#search-input`) with Enter-to-submit
- Results container (`#results`) with `.result-item` elements
- Trending widget (`#trending`) with `.trending-item` elements, loaded on page load
- Zero-results panel (`#no-results`) with `.suggestion-item` elements, hidden when results exist

**Typesense Configuration:**
- Server started with `--enable-search-analytics=true` and `--analytics-flush-interval=60`
- Analytics aggregate queries with at least a 4-second pause between them
- Popular queries (with results) and no-hits queries (zero results) are both tracked natively
