## How It Works

**Startup**: Ensures the `products` collection exists in Typesense (v26.0), then upserts all 6 baseline documents (idempotent — no duplicates on restart).

**API Endpoints** (all JSON):
- `POST /api/saved-searches` — Create a named search (q, category, max_price). Returns 201.
- `GET /api/saved-searches` — List all saved searches with match_count/new_count.
- `POST /api/saved-searches/{id}/check` — Re-run a single saved search against live Typesense data. Returns updated counts.
- `POST /api/check-all` — Check every saved search. Returns array of updated objects.
- `POST /api/ingest` — Upsert catalog documents into Typesense. Returns `{ingested: N}`.
- `GET /api/catalog` — List available catalog documents for the UI.

**Matching semantics**: A document matches when ALL conditions hold: query text matches `name` field (empty/`*` matches all), category equals exactly (if set), price ≤ max_price (if set). The full match set (all matching IDs) is retrieved from Typesense, not just the first page.

**New-match semantics**: Each saved search remembers the previous match set. `new_count` is the count of IDs in the current match set that weren't in the previous set. First check always reports `new_count=0`. Immediate re-check with no index changes reports `new_count=0`.

**UI**: Create saved searches form, sortable table with match counts and red "new" badges, Check/Check All buttons, and an ingest section listing catalog documents with Ingest buttons.
