# Repair a Broken Qwik Reactive Order Summary ## Background A Qwik (v1.20.0, Qwik City) order-summary page has a broken reactive architecture. The page uses component-level tasks to (a) derive an order total from line items and (b) drive an auto-restock timer. The reactive wiring is wrong: a task both depends on and writes back to the same reactive state, so during server-side rendering the computed total is not correctly produced/serialized and/or the component spins in a re-run loop, and the auto-restock timer keeps running after it is switched off. The application is otherwise complete; do not rebuild it from scratch. ## Requirements Repair the component so that all of the following hold simultaneously, while keeping it a real Qwik application (do not replace the framework, do not move the derivation of the total out of the component into a route loader/endpoint, and do not change the pinned dependency versions): * The page at route `/` renders correctly during SSR and is fully interactive after it resumes on the client. * The page must NOT enter an infinite re-render / task re-run loop, must NOT block or hang SSR, and must produce NO uncaught errors or error-level console messages in the browser. * Preserve the intended derived behavior: * An order total derived from the three line items (unit price times quantity, summed). * A 10% coupon discount that can be toggled on and off. * Per-item increment / decrement quantity controls (a quantity must never drop below 0). * An auto-restock feature that repeatedly increases the Mouse quantity while enabled and stops it while disabled. ## Fixed data (initial state, already present in the code) Three line items, prices stored as integer cents: | id | name | unit price (cents) | initial quantity | | -------- | -------- | ------------------ | ---------------- | | keyboard | Keyboard | 4999 | 1 | | mouse | Mouse | 2550 | 2 | | monitor | Monitor | 19900 | 1 | Initial subtotal = 4999*1 + 2550*2 + 19900\*1 = 29999 cents. ## Implementation Hints * Project path: /home/user/qwik-app * Start command: `npm run dev` (already configured to listen on host 0.0.0.0, port 3000). * Port: 3000. The page is served at `http://localhost:3000/`. * Money is rendered as `$` followed by a fixed 2-decimal dollar amount derived from the integer cents (e.g. 29999 cents renders as `$299.99`). * The discounted total (coupon applied) is `Math.round(subtotalCents * 0.9)` cents, then formatted the same way (e.g. 29999 cents -> `$269.99`). * The following DOM hooks already exist and MUST keep these exact `data-testid` attribute values and semantics: * `total`: element whose text content is the currently displayed order total (e.g. `$299.99`). * `coupon`: a checkbox input; unchecked initially. Toggling it applies / removes the 10% discount. * `qty-keyboard`, `qty-mouse`, `qty-monitor`: element whose text content is that item's current integer quantity. * `inc-keyboard`, `inc-mouse`, `inc-monitor`: buttons that increase the matching item's quantity by 1. * `dec-keyboard`, `dec-mouse`, `dec-monitor`: buttons that decrease the matching item's quantity by 1 (not below 0). * `auto-toggle`: a button that enables / disables the auto-restock feature. * The HTML returned by the server for `/` (i.e. before any client JavaScript executes) MUST already contain the element with `data-testid="total"` showing the correct order total for the current state. A fix that only computes the total on the client is not acceptable. * Reactivity: changing any quantity, or toggling the coupon, must update the `total` text to stay consistent with the current line items and coupon state. * Auto-restock: clicking `auto-toggle` enables the feature, after which the Mouse quantity increases by 1 approximately every 500 ms (and the total stays consistent with it). Clicking `auto-toggle` again disables the feature, after which the Mouse quantity must stop changing immediately with no further (residual) increments. Toggling the feature off and on repeatedly must not cause it to increment more than once per 500 ms interval. ## Notes * No external services, network calls, databases, or credentials are involved. Everything runs locally.
