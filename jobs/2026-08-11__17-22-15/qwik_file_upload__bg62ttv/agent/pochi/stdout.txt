# Qwik City Secure File Upload Service ## Background You are given an existing, buildable Qwik City application (Qwik and Qwik City v1.20.0) served by a preconfigured production Node SSR server. Implement a self-contained, secure file-upload feature. Everything must run locally: uploads are handled by Qwik City server code, bytes are stored on the local filesystem, and file metadata lives in a local SQLite database. The feature MUST NOT use any external network, cloud, API, or third-party storage service. ## Requirements * Serve an upload page at `GET /` containing a Qwik City route action (`routeAction$`) wired to a `<Form>` that accepts a `multipart/form-data` submission with two fields: `file` (the binary file input) and `filename` (a text field carrying the client-declared original filename). * Validate every upload strictly on the server: * Reject a missing or empty file. * Reject a file larger than the maximum allowed size. * Accept only PNG and PDF files, where the type is determined from the actual file content (byte signature), NOT from the filename or any client-declared content type. * Sanitize the client-declared filename so that it can never cause path traversal. * Persist each accepted file's bytes to a local uploads directory, and record its metadata in a local SQLite database: the sanitized original name, a server-generated stored name, the size in bytes, the SHA-256 hex digest of the content, and the detected content type. * Deduplicate by content: uploading byte-identical content must never create a second stored file or a second metadata row, even when identical uploads arrive concurrently. * List all stored files on `GET /` using a `routeLoader$`, and also expose a JSON listing endpoint. * Provide a download endpoint that streams the exact stored bytes back with correct response headers. * No Node-only module or native database driver may leak into the client bundle, and the production build must succeed. ## Implementation Hints * Project path: `/home/user/qwik-upload` * A production Node SSR server is already configured. Build with `npm run build`, then start it with `npm run serve`. It listens on port `3000` (base URL `http://127.0.0.1:3000`). * Metadata MUST be stored in a local SQLite database file inside the project. The `better-sqlite3` package is available in the project dependencies. * Maximum accepted size is `1048576` bytes (1 MiB). A file whose content length is strictly greater than this MUST be rejected. * The only accepted content types are `image/png` and `application/pdf`, detected from the file content only. * The upload form field names MUST be exactly `file` (the file input) and `filename` (the text field with the client-declared original filename). * Validation precedence MUST be: missing/empty file first, then size, then content type. * On `GET /`, after an upload attempt, render exactly one element with `id="upload-result"`: * On success it MUST have attribute `data-status="success"` and attribute `data-dedup` equal to `"true"` when the uploaded content duplicated already-stored content, otherwise `"false"`. * On failure it MUST have attribute `data-status="error"` and attribute `data-error-code` equal to exactly one of `no_file`, `file_too_large`, or `unsupported_type`. * On `GET /`, the list of stored files rendered from the route loader MUST render one entry per stored file; each entry MUST carry a `data-stored-name` attribute equal to that file's stored name and MUST display the file's original name. * The server-generated stored name MUST be unique, filesystem-safe (it MUST NOT contain `/`, `\`, or `..`), and identical for byte-identical content. * `GET /api/files` MUST return status 200 and a JSON array in which every element has exactly these keys: `originalName`, `storedName`, `size`, `sha256`, `contentType`. * `GET /api/files/download/<storedName>` MUST stream the exact stored bytes with response header `Content-Type` equal to the detected content type and response header `Content-Disposition` equal to `attachment; filename="<originalName>"`. A request for an unknown stored name MUST return status 404. * The recorded and served original name MUST be the base filename only, with any directory components and `..` segments removed; Unicode characters in the name MUST be preserved.
