# Scene-Graph JSON Transformer (libGDX Headless) ## Background Build a headless libGDX application that canonicalizes a polymorphic game scene graph. It reads a scene described as nested JSON, deserializes it into a typed node object graph, applies a fixed transformation pipeline, and re-serializes the result to a single line of canonical JSON on stdout. All JSON parsing and writing MUST be done with libGDX's own JSON utilities. ## Requirements * Model a polymorphic node hierarchy with an abstract base node and four concrete node kinds: `group`, `sprite`, `light`, `trigger`. * Deserialize the input scene into this object graph and re-serialize it, driven by a custom libGDX JSON serializer for the node hierarchy that uses a `type` discriminator field carrying the class tag. * Handle libGDX container types inside nodes: an `Array` of child nodes, an `IntArray` of integers, and an `ObjectMap` of string-to-string. * Apply the transformation pipeline below, then print the canonical serialization. ## Node model & input JSON schema Every node object has these common input fields: * `type` — one of `group`, `sprite`, `light`, `trigger` (the class tag / discriminator). * `name` — string. * `enabled` — optional boolean. A node is disabled ONLY if this is explicitly `false`; if the field is absent the node is enabled. * `lx`, `ly` — local translation numbers (each defaults to `0.0` when absent). * `ls` — local uniform scale number (defaults to `1.0` when absent). Kind-specific fields: * group: `children` — an array of node objects (defaults to empty). * sprite: `region` (string), `z` (integer), `frames` (array of integers). * light: `color` (string), `intensity` (number). * trigger: `event` (string), `params` (object mapping string keys to string values), `targets` (array of integers). Input scene files may ALSO contain `id`, `absX`, `absY`, `absScale` on any node (for example, the program's own output). These MUST be ignored on input and always recomputed. ## Transformation pipeline (apply in this exact order) 1. Deserialize the input into the node graph. The root node is always a `group` and is always enabled. 2. Prune: remove every disabled node together with its entire subtree. 3. Assign integer `id`s in a pre-order (depth-first) traversal: the root gets `0`, ids increase by `1`, visiting each group's (already pruned) `children` in array order before descending into them. 4. Compute each node's absolute transform by composing parent transforms; the root's parent frame is scale `1`, x `0`, y `0`: * `absScale = parentAbsScale * ls` * `absX = parentAbsX + parentAbsScale * lx` * `absY = parentAbsY + parentAbsScale * ly` 5. Serialize the resulting graph to canonical JSON (below) and print it. ## Canonical output format * Use libGDX minimal JSON output (`JsonWriter.OutputType.minimal`): a single line, no added whitespace, names and values unquoted wherever the minimal form allows. * Each node object MUST emit its fields in exactly this order: * Common first: `type`, `id`, `name`, `lx`, `ly`, `ls`, `absX`, `absY`, `absScale`. * Then kind-specific fields, in order: * group: `children` * sprite: `region`, `z`, `frames` * light: `color`, `intensity` * trigger: `event`, `params`, `targets` * `children` holds the transformed child node objects in pruned input order. * `frames` and `targets` are JSON arrays of integers in their original order. * Within `params`, keys MUST be ordered ascending by Unicode code point. * Number formatting: * `lx`, `ly`, `ls`, `absX`, `absY`, `absScale`, and `intensity` MUST each be emitted as an unquoted numeric token with exactly three digits after the decimal point, rounded half-up (for example `2.000`, `0.500`, `-4.000`, `0.667`). * `id`, `z`, and the elements of `frames` and `targets` MUST be emitted as plain integers. ## Implementation Hints * Project path: /home/user/scene-baker * Target libGDX `1.14.2` running on its headless backend; no OpenGL/graphics may be used. * Do ALL JSON reading and writing with libGDX's own utilities in `com.badlogic.gdx.utils` (`Json`, `JsonValue`, `JsonReader`). Do NOT use any third-party JSON library (no Jackson, Gson, org.json, moshi, etc.). * The program reads the path of the input scene JSON file as its first argument and writes the canonical JSON as a single line to stdout; the process must exit after printing. * The project root must expose a Gradle `run` task so that this exact command, run from the project path, prints that single line to stdout: * `./gradlew --quiet --console=plain run --args="<absolute path to input scene JSON>"`
