Implemented `/home/user/myproject/solution.py` with an async `run_indexer(max_messages=None)` coroutine that:

1. **Opens a fresh NATS connection per call** (`nats.connect(NATS_URL)`), closed in a `finally` block — each invocation behaves like an independent worker run/restart.
2. **Ensures the JetStream stream exists** (`add_stream`, falling back to `stream_info` if it already exists), then **gets-or-binds the durable pull consumer** via `js.pull_subscribe(subject, durable=..., stream=..., config=ConsumerConfig(ack_policy=EXPLICIT, deliver_policy=ALL))` — nats-py transparently creates the consumer on first use and binds to the existing one (resuming the server-persisted ack floor) on subsequent calls.
3. **Fetches messages in batches** sized by `INDEX_BATCH_SIZE` (capped to the remaining `max_messages` budget when given), decodes the JSON payloads, and de-duplicates by `id` within the batch (keeping the latest copy) before building a PyArrow table with schema `id: int64`, `text: string`, `vector: fixed_size_list<float32>[32]`.
4. **Commits before acking**: each batch is written via `table.merge_insert("id").when_matched_update_all().when_not_matched_insert_all().execute(data)`, and only after that succeeds are the batch's messages explicitly acked (`await m.ack()`) — guaranteeing at-least-once delivery never causes duplicate/corrupted rows, and a crash before ack simply causes harmless redelivery.
5. **Opens/creates the LanceDB table** named `documents_{ZEALT_RUN_ID}` at `LANCEDB_PATH` (`create_table(..., exist_ok=True)`), so repeated calls attach to the same persistent table.
6. **Stops** once `max_messages` have been committed+acked (when given) or once `fetch()` times out with no messages (stream drained), returning `{"committed": <int>}`. A drained stream call returns `{"committed": 0}` and leaves the table untouched.
