Built the grouped search storefront at `/home/user/app`:

**Architecture**
- `server.js` — Express app, `GET /` route accepting `q` and `page` query params (plus an internal `expand` param used for the per-group "Show more" links).
- `lib/typesense.js` — Typesense REST client (using native `fetch`, no SDK dependency). On startup, checks if the `products` collection exists, creates it if not (schema: `name` string, `brand` faceted string, `popularity` int32, `price` float), then upserts all 20 docs from `data/products.jsonl` — safe to run repeatedly (idempotent via `action=upsert`).
- `lib/render.js` — Server-side HTML rendering with the required `data-testid` DOM contract.

**How grouping/pagination is implemented**
Leveraged Typesense's native `group_by=brand&group_limit=3` search feature combined with `sort_by=popularity:desc`, which returns each group's true total count in `grouped_hits[].found` and the true total number of groups in the top-level `found` field — regardless of the `per_page`/`page` values used (verified empirically against the live server). This gives exact per-brand totals and correct group-level pagination (`per_page` on a grouped query paginates groups, 3 per page here) with no extra bookkeeping needed.

"Show more" and pagination are implemented as plain server-rendered `<a>` links (no client JS required) that re-request `/` with an added `expand=<brand>` param; when a brand is in `expand`, the server fetches all matching items for just that brand (`filter_by=brand:=\`Brand\``) so only currently-shown items are ever present in the DOM.

**Verified behavior**
- Fresh start creates collection + loads 20 docs; restarting `npm start` again against the same server does not duplicate documents (`num_documents` stays 20).
- `/` groups by brand sorted by popularity desc, 3 groups/page, 3 items/group with correct "Show more" only on groups >3 items (Azura=5 → show more; Boreas=2, Cirrus=3 → no control).
- `?page=2` shows the remaining brands (Denali, Everest) with correct `page-indicator` text.
- `?expand=Azura` reveals all 5 Azura items with no other groups affected.
- `?q=Turntable` / empty query / no-match query all behave correctly, including the empty-results state.
- Out-of-range/invalid `page` values are clamped safely (no crashes).
