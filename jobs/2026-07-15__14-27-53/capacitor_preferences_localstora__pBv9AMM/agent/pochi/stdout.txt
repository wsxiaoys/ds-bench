## Migration Implementation Complete

I implemented the one-time, idempotent `legacy:` `localStorage` → `@capacitor/preferences` migration in `/home/user/storage-migration/src/main.ts` and exposed it as `window.migrateStorage()`.

### Behavior

1. **Idempotency guard** – On entry, reads the completion flag (key `migration:legacy-to-preferences:completed`) from `Preferences`. If it is `'true'`, the function returns `{ alreadyCompleted: true, migrated: [], skipped: [] }` without touching any other storage.
2. **Key scoping** – Snapshots every `localStorage` key whose name starts with `legacy:` (other prefixes are ignored entirely).
3. **Destination key derivation** – `legacy:theme` → `theme`, by stripping exactly the `legacy:` prefix.
4. **Conflict resolution** – For each candidate, the destination key is checked in `Preferences`. If a value already exists, the destination is appended to `skipped` and the legacy entry is left untouched in `localStorage`.
5. **Migration** – Otherwise, the legacy value is read from `localStorage`, written to `Preferences`, and the `localStorage` entry is deleted; the destination is appended to `migrated`.
6. **Completion flag** – After processing, the completion flag is persisted via `Preferences.set({ key, value: 'true' })` so subsequent calls (even across page reloads) are no-ops.
7. **Report** – Returns `{ alreadyCompleted, migrated, skipped }` with the exact shape required.

### Constraints honored
- `@capacitor/preferences` is used for **every** Preferences read/write (including the completion flag); legacy values are only read from `window.localStorage`.
- Migration runs **only** when `window.migrateStorage()` is invoked — the script does not call it on page load.
- The script assignment `window.migrateStorage = migrateStorage` happens at module load so the function is available for the verifier to call as soon as the page is ready.
