## What the migration does

**`up` method** (in order):
1. **Add column** — `queryInterface.addColumn('Users', 'departmentId', { type: Sequelize.INTEGER, allowNull: true })` adds the new `departmentId` INTEGER column. It's added as nullable so existing rows can be populated without constraint violations.
2. **Backfill data** — `queryInterface.bulkUpdate('Users', { departmentId: 1 })` sets `departmentId` to `1` for all existing user rows (assuming a department with `id = 1` exists).
3. **Add foreign key** — `queryInterface.addConstraint('Users', ...)` adds a named foreign key constraint (`users_departmentId_fkey`) referencing `Departments(id)` with `ON UPDATE CASCADE` and `ON DELETE CASCADE`.

**`down` method** (reverses in safe order):
1. `queryInterface.removeConstraint('Users', 'users_departmentId_fkey')` — removes the FK constraint first.
2. `queryInterface.removeColumn('Users', 'departmentId')` — drops the column.

Both functions use `async/await` and return promises implicitly.

module.exports = {
  up: async (queryInterface, Sequelize) => {
    await queryInterface.addColumn('Users', 'departmentId', {
      type: Sequelize.INTEGER,
      allowNull: true,
    });

    await queryInterface.bulkUpdate('Users', {
      departmentId: 1,
    });

    await queryInterface.addConstraint('Users', {
      fields: ['departmentId'],
      type: 'foreign key',
      name: 'users_departmentId_fkey',
      references: {
        table: 'Departments',
        field: 'id',
      },
      onUpdate: 'CASCADE',
      onDelete: 'CASCADE',
    });
  },

  down: async (queryInterface, Sequelize) => {
    await queryInterface.removeConstraint('Users', 'users_departmentId_fkey');
    await queryInterface.removeColumn('Users', 'departmentId');
  },
};
