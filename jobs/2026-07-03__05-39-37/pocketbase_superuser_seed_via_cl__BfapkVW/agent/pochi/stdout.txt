## How it works

**`setup.sh`** runs in 5 ordered steps:
1. **Superuser** — `pocketbase superuser upsert admin@example.com 'Adm1n_passw0rd!'` (upsert = create-or-update, inherently idempotent).
2. **Migration** — `pocketbase migrate up` applies the JS migration that defines the `tasks` collection. Migrations are tracked in the `_migrations` table, so they only run once.
3. **Start server** — only starts a new `pocketbase serve` if the health endpoint isn't already responding; uses `nohup ... & disown` so the process survives script exit. Waits up to 60s for `GET /api/health` → 200.
4. **Authenticate** — `POST /api/collections/_superusers/auth-with-password` to obtain a bearer token.
5. **Seed tasks** — for each of the 5 titles, queries `tasks` with `filter=title="..."`; creates the record only if the count is 0, otherwise skips.

**`1700000000_create_tasks.js`** defines collection `tasks` (type `base`) with fields `title` (text, required), `done` (bool), `due` (date). It guards creation with a `findCollectionByNameOrId` check so it's safe even if applied out-of-band.
