The TypeScript SDK exposes a `process.codeRun(...)` helper that runs a code snippet inside a sandbox and returns its captured stdout. In this task you will use the Daytona TypeScript SDK to spin up a fresh sandbox, run a small JavaScript/TypeScript snippet that computes a numeric result, persist that result to a local log file, and clean up the sandbox. ## Requirements * Write a TypeScript/Node.js program under `/home/user/myproject` that uses the `@daytonaio/sdk` package to talk to the real Daytona SaaS API. * Create a Daytona sandbox with `language: 'typescript'`. ## What was implemented

**`/home/user/myproject/src/run.ts`** — the main program:
1. Reads `DAYTONA_API_KEY` from the environment and the run id from `/logs/artifacts/run-id` (value: `zrywcxhizz`).
2. Constructs `new Daytona({ apiKey })` and creates a sandbox with `language: 'typescript'` and `name: 'code-run-ts-<run-id>` (also mirrored into `labels` so it's discoverable by name).
3. Runs a snippet via `sandbox.process.codeRun(snippet)` that computes the factorial of 6 and prints it with a delimited marker (`FACTORIAL_RESULT:720`).
4. Inspects the `ExecuteResponse`: throws (→ non-zero exit) when `exitCode !== 0`, otherwise extracts the integer from `response.result` via a regex.
5. Writes `/home/user/myproject/output.log` as a single line: `Factorial: 720`.
6. Deletes the sandbox in a `finally` block so cleanup happens on both success and failure paths.

**Supporting files:** `package.json` (added a `start` script: `tsx src/run.ts`), `tsconfig.json`, and installed `@daytonaio/sdk`, `tsx`, `typescript`, `@types/node`.

## Key finding & robustness fix
The sandbox's TypeScript runtime emits `npm notice …` update messages to stdout, which get captured into `response.result` alongside the snippet's `console.log` output. A naive `result.trim()` therefore polluted the log file. I switched the snippet to print a delimited marker (`FACTORIAL_RESULT:<n>`) and parse it out with a regex, so the extracted value is immune to that noise.
