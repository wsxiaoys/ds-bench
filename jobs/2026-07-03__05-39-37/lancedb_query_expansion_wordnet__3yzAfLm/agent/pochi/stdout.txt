## How it works
1. **Connect once** (cached via `lru_cache`) to the LanceDB at `LANCEDB_URI`, opening table `LANCEDB_TABLE`.
2. **Create the native FTS index** on `content` with `use_tantivy=False, replace=False`, swallowing the "already exists" error so repeated calls never error.
3. **Expand the query**: lowercase, whitespace-split; for each token collect WordNet synonyms via `wn.synonyms`, keeping only single-token lemmas (no `_`/whitespace), de-duplicated, capped at **3** synonyms. The original token is always kept first.
4. **Build a SHOULD/OR boolean FTS query** — `BooleanQuery([(Occur.SHOULD, MatchQuery(term, "content")) for term in terms])` — and run `table.search(q, query_type="fts").limit(k)`.
5. **Return top-k IDs** as native Python `int`, ordered by FTS score descending.

## Verified behavior
- `expanded_search("car")` recovers all 8 REDACTEDmobile-only documents (IDs 6–13) that the plain baseline `table.search("car")` misses — `REDACTEDmobile` is kept as a synonym.
- Queries with **no WordNet synonyms** (`airport`, `highway`, `xyzzy`) return results identical to the plain FTS baseline.
- Queries **with** synonyms legitimately add synonym-matching docs (e.g. `morning`→`aurora` surfaces the aurora document).
- Calling `expanded_search` multiple times is idempotent (no errors).
- Empty query and `k` larger than the result set are handled gracefully.
- Returned IDs are native `int`, and scores are strictly descending (ties among equal scores are unordered, as expected).
