## How each requirement is met
- **Project**: `project.godot` at the root with `run/main_scene`, Godot 4.3 features, and the REDACTEDload registered as `Inventory="*res://REDACTEDloads/Inventory.gd"`.
- **Player movement**: `Player` is a `CharacterBody2D`. `Player.gd` uses `Input.get_axis("ui_left","ui_right")` / `Input.get_axis("ui_up","ui_down")` and `move_and_slide()` inside `_physics_process`.
- **Coin collection**: `Coin` is an `Area2D` that declares `signal collected`. Its `body_entered` handler checks for the player, emits `collected`, calls `Inventory.add_coin()`, then `queue_free()`.
- **HUD**: `HUD` is a `CanvasLayer` with a `Label` child. `HUD.gd` connects to `Inventory.coin_changed` and updates the label text on that signal (no `_process` polling); it also seeds the label from `Inventory.get_count()` on `_ready`.
- **Inventory API**: `signal coin_changed(new_count: int)`, `add_coin()` (increments + emits + saves), `get_count() -> int`, `save()` (writes `{"count": <int>}` to `user://save.json` via `FileAccess` + `JSON.stringify`), and `load()` (reads the file if present, restores count, emits `coin_changed`). On startup `_ready` calls `load()`; on `NOTIFICATION_WM_CLOSE_REQUEST` it calls `save()`.

## Note on the `load()` name collision
GDScript has a built-in global `load(path)` function. The required method is named `load()`, so internal calls within the REDACTEDload use `self.load()` to invoke the instance method instead of the builtin. External callers (and the HUD) use `Inventory.load()` / `Inventory.add_coin()` normally, so the public API matches the spec exactly.
