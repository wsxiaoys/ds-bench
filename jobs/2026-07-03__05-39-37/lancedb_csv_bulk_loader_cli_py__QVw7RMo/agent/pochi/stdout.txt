## What it does

**`ingest`** — `python3 loader.py ingest --csv <path> --table <name> --text-col <col> --batch-size <int>`
- Reads the CSV with pandas (handles `\r\n` line endings), preserving every row exactly once.
- Embeds the chosen text column with real OpenAI `text-embedding-3-small` API calls (1536 dims), batched by `--batch-size` and internally chunked to ≤2048 inputs/request to respect the OpenAI per-request limit.
- Writes all rows + a `vector` column to a LanceDB table at `/home/user/loader_project/lance_db` using `mode="overwrite"` for rerun safety.
- Uses the table name passed via `--table` verbatim, so run-id-suffixed names work for concurrent runs.

**`search`** — `python3 loader.py search --table <name> --query <str> --k <int>`
- Embeds the query with the same model, runs `table.search(query_vector).limit(min(k, row_count))`.
- Prints a **single JSON object** to stdout (logs go to stderr only) with the exact required structure: `{query, k, results:[{id, title, category, published, score}]}`, ordered best-to-worst, `score` = L2 distance (finite float).

## Key implementation notes
- **No `openai` SDK dependency at runtime**: the installed `openai==1.54.5` is incompatible with `httpx==0.28.1` (removed `proxies` kwarg), so embeddings are fetched via the standard-library `urllib` against the OpenAI REST `/embeddings` endpoint. This guarantees real OpenAI calls with zero dependency conflicts.
- Reads `OPENAI_API_KEY` from the environment; honors `OPENAI_BASE_URL` if set.
- Exponential-backoff retry on 429/5xx; defensive None/NaN handling for all columns.
- `id` cast to int; results length = `min(k, table_row_count)`.
