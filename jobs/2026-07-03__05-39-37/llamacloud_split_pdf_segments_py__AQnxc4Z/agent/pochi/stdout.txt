## What it does
`python3 run.py --pdf <pdf_path> --config <config_path> --output <output_path>` drives the LlamaCloud Split API end-to-end:

1. **Validates local inputs first** (config file exists, is valid JSON, and contains a non-empty `categories` list with `name`+`description` entries; PDF file exists) so the user gets the most relevant error before any network/API-key requirement.
2. **Requires `LLAMA_CLOUD_API_KEY`** — fails early with a non-zero exit code if unset.
3. **Uploads the PDF** via `client.files.create(file=..., purpose="split")`.
4. **Submits a split job** with `client.beta.split.split(categories=..., document_input={"type": "file_id", "value": <file_id>})`, which creates the job and waits for completion in one call.
5. **Reads segments** off `result.result.segments`, each exposing `category`, `pages` (1-based ints), and `confidence_category`.
6. **Writes the output JSON** at `<output_path>` in the required structure:
   ```json
   {
     "segments": [
       { "category": "...", "pages": [1, 2, ...], "confidence_category": "high" }
     ]
   }
   ```
   Segment order is preserved as returned by the API.

## Implementation notes
- Uses the official `llama-cloud` SDK (v2.7.0, already installed) with `from llama_cloud import LlamaCloud`.
- `argparse` is used for CLI parsing; missing/invalid arguments exit non-zero (argparse exits `2`; custom validation exits `1`).
- The config schema is loaded from the JSON file and forwarded directly to the API as the `categories` parameter.
- Empty/missing segment results surface the job's `status` and `error_message` for easier debugging.
- Output directory is created if it doesn't exist; JSON is pretty-printed with a trailing newline.
