## What the program does

1. **Reads the run id** from `/logs/artifacts/run-id` so concurrent parallel runs don't clobber each other's expectations.
2. **Instantiates the client** with `new LlamaCloud()` (no args), which picks up `LLAMA_CLOUD_API_KEY` from the environment.
3. **Uploads the three sample files** (`invoice.txt`, `receipt.txt`, `contract.txt`) in parallel using `fs.createReadStream(...)` with `client.files.create({ file, purpose: "classify" })`, collecting each returned `id`.
4. **Submits a single Classify job** via the convenience helper `client.classifier.classify({ file_ids, rules, mode: "FAST" })`. This helper handles the upload → poll → result flow internally. The three rules use the types `invoice`, `receipt`, and `contract`, each with a natural-language `description`.
5. **Writes `/home/user/myproject/output.log`** whose:
   - first line is exactly `Run ID: <run-id>`, and
   - subsequent lines are `Classified: <basename> | Type: <type> | Confidence: <confidence>` — one per file, in the order the `file_ids` were submitted (the SDK guarantees `items` follows that order).

Only the `@llamaindex/llama-cloud` package is used; no legacy wrappers.
