## What it does

`LoggedSearcher(db_uri, articles_table, logs_table)` opens the LanceDB database and the articles table eagerly (so a missing articles table fails loudly at construction). The logs table is opened lazily on the first `search()` call.

`search(query_vector, top_k, query_id, user_id, query_text="")`:
- Runs the real vector search via `self._articles_table.search(query_vector).limit(top_k).to_list()` and returns that list directly (each hit includes `id`, `title`, `embedding`, `_distance`).
- Measures wall-clock latency with `time.perf_counter()` (monotonic, high-resolution) and converts the delta to milliseconds (guarded to be strictly positive).
- Extracts the returned `id` values in rank order as plain Python `int`s into `top_ids`.
- Builds one audit row with a timezone-aware UTC timestamp (`datetime.now(timezone.utc)`) and writes it to the `query_logs` table.

## Audit schema (query_logs)

Built from an explicit PyArrow schema so it is always programmatically queryable:

| field | type |
|-------|------|
| `query_id` | `string` |
| `user_id` | `string` |
| `query_text` | `string` |
| `ts` | `timestamp("us")` |
| `latency_ms` | `float64` (strictly positive) |
| `hit_count` | `int64` (== `len(top_ids)`) |
| `top_ids` | `list<int64>` (rank-ordered ids) |

## Lazy creation

On the first `search()`:
- If `query_logs` is not in `db.table_names()`, it is created with `create_table(..., data=<one-row arrow table>, mode="overwrite")` using the fixed schema.
- If it already exists, the table is opened and the row is appended via `table.add(...)`.

Subsequent calls reuse the cached table handle and append. A single audit row is written per `search()` call — no mocking, only the real `lancedb` package is used.
