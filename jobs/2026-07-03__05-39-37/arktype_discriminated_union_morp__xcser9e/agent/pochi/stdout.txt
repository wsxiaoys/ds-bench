## Files

**`package.json`** — pins `"arktype": "2.2.0"` (verified via `npm ls arktype` → `arktype@2.2.0`), plus `tsx`/`typescript` devDeps for execution. ESM (`"type": "module"`).

**`src/schema.ts`** — exports `PayloadSchema`:
```ts
export const PayloadSchema = type.or(
  { kind: "'int'", value: "string.numeric.parse" }, // numeric string → number
  { kind: "'raw'", value: "string" }                // string preserved
);
```
The `kind` literal (`"int"` vs `"raw"`) is the discriminator, so ArkType deterministically picks a branch *before* applying the morph — the only safe way to compose conflicting morphs on the same `value` field.

**`broken.ts`** — constructs an *ambiguous* union with no discriminator:
```ts
const broken = type.or(
  { value: "string.numeric.parse" },
  { value: "string" }
);
```
Both branches accept `{ value: "42" }` but would return `42` (number) vs `"42"` (string), so ArkType refuses to parse and throws `ParseError` at definition time. The error is left uncaught so it propagates.
