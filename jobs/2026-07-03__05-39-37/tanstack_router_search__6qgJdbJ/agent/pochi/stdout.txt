## What was built

**Project structure:**
- `package.json` — React 18 + `@tanstack/react-router` + Vite 6
- `vite.config.ts` — dev server configured to run on **port 4821**
- `index.html` — app entry HTML
- `src/main.tsx` — sets up the router with code-based routing (root, index, and search routes)
- `src/SearchPage.tsx` — the search page component
- `src/index.css` — basic styling

**Key implementation details:**

1. **Route with search param validation** (`src/main.tsx`): The `/search` route uses `validateSearch` to parse and type the URL search params into `{ q: string, category: string, minPrice: number, maxPrice: number }`, with sensible defaults (empty strings / `0`) when params are absent. This means loading `/search?q=shoes&category=electronics&minPrice=10&maxPrice=500` populates the inputs with those values.

2. **URL-synced inputs** (`src/SearchPage.tsx`): The page contains four `<input>` elements with `name` attributes `q`, `category`, `minPrice`, and `maxPrice`. Each input's `onChange` calls `navigate({ to: '/search', search: (prev) => {...}, replace: true })` to update the URL search params in real time. Numeric inputs (`minPrice`/`maxPrice`) are parsed to numbers before being written to the URL.

3. **Two-way binding**: Inputs are populated from `useSearch()` (the current URL state), and editing an input updates the URL, which flows back into the inputs — so the URL is always the single source of truth.
