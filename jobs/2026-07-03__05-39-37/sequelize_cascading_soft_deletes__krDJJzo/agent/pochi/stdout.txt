Built an Express.js + Sequelize/SQLite API at `/home/user/myproject` that implements cascading soft deletes via Sequelize hooks. Start it with `node index.js` (listens on port 3000).

## Files
- `package.json` — dependencies: express, sequelize, sqlite3
- `db.js` — Sequelize setup with two **paranoid** models (`User`, `Post`) and a one-to-many association (`User.hasMany(Post)`, `Post.belongsTo(User)`)
- `index.js` — Express app with the hooks and REST endpoints

## How the cascade works (hooks)
- **`User.afterDestroy`**: After Sequelize stamps the user's `deletedAt` during a paranoid soft-delete, the hook re-reads that authoritative timestamp and copies it onto every non-deleted `Post` belonging to the user (`UPDATE posts SET deletedAt = <user.deletedAt> WHERE UserId = ? AND deletedAt IS NULL`).
- **`User.beforeRestore`**: Before the user's `deletedAt` is cleared, the hook reads the user's current `deletedAt` and clears `deletedAt` only on posts whose `deletedAt` **matches** it — i.e. the ones deleted as part of this cascade (`UPDATE posts SET deletedAt = NULL WHERE UserId = ? AND deletedAt = <user.deletedAt>`).

Matching on the exact `deletedAt` timestamp is what makes the restore selective: posts that were soft-deleted *independently* (different `deletedAt`) are left deleted, while only the posts cascaded with the user are restored.

## Endpoints
| Method | Path | Behavior |
|---|---|---|
| POST | `/users` | Creates a user from `{"username"}` → `201` + user object (with `id`) |
| POST | `/users/:id/posts` | Creates a post for the user from `{"title"}` → `201` + post object (with `id`); `404` if user missing |
| DELETE | `/users/:id` | Soft-deletes the user and **cascades** to their posts → `200`; `404` if user missing |
| POST | `/users/:id/restore` | Restores the user and **cascades** the restore to its cascaded posts → `200`; `404` if user missing |
| GET | `/posts/:id` | Returns `200` + post when it exists and is not soft-deleted, `404` otherwise |
