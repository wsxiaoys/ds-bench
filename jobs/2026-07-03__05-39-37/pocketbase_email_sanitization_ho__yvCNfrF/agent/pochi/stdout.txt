### Hook file created
`/home/user/myproject/pb_hooks/sanitize_email.pb.js`:

```js
/// <reference path="../pb_data/types.d.ts" />

onRecordCreateRequest((e) => {
    if (e.collection && e.collection.name === "users" && e.record) {
        var email = e.record.getString("email") || "";
        e.record.set("email", email.trim().toLowerCase());
    }
    return e.next();
}, "users");
```

### How it satisfies the requirements
- **Intercepts `users` record creation** — uses the post-v0.23 request-level hook `onRecordCreateRequest`, which fires before the record is persisted.
- **Sanitizes the email** — `getString("email")` reads the in-flight value, then `trim().toLowerCase()` removes surrounding whitespace and lowercases it, and `set("email", …)` writes it back before persistence.
- **Only affects `users`** — two independent safeguards: (1) the `"users"` tag argument restricts the handler to the `users` collection only, and (2) an explicit `e.collection.name === "users"` guard. `_superusers` and any other auth collection are never modified.
- **Works for clean and dirty input** — trimming/lowercasing is idempotent, so already-clean emails pass through unchanged.
- **Propagates the chain** — `return e.next()` ensures the create operation isn't silently blocked (required by the post-v0.23 API).
- **Strictly synchronous** — no `Promise`/`async`/`await`, compatible with the Goja ES5.1 runtime.
