## Changes

### New file: `src/app/api/users.ts`
Defines the `User` type (`{ id, name, email }`) and a module-level `Map<string, User>` that persists state inside the worker module. A `Map` preserves insertion order, so iterating its values naturally returns users in insertion order. IDs are generated server-side via `crypto.randomUUID()`.

All responses set `Content-Type: application/json` via a small `json()` helper (except DELETE, which returns an empty 204 body).

Endpoints:
- **GET `/api/users`** → `200` `{"users": [...]}` (empty array when none exist)
- **POST `/api/users`** → `201` with the created user `{id, name, email}`; `400` `{"error": "invalid payload"}` when `name`/`email` is missing or not a string (also handles malformed JSON bodies)
- **GET `/api/users/:id`** → `200` user object, or `404` `{"error": "not found"}`
- **PUT `/api/users/:id`** → `200` updated user (only applies provided `name`/`email` string fields), or `404` `{"error": "not found"}`
- **DELETE `/api/users/:id`** → `204` empty body, or `404` `{"error": "not found"}`

Routes are grouped with `prefix("/api/users", [...])` using rwsdk's method-based routing (`route("/", { get, post })` and `route("/:id", { get, put, delete })`).
