## Files

### `src/router.ts`
Exports `route`, constructed via `match({...})`. The first three cases (bare `string`, bare `number`, `string[]`) are expressed as object-literal keys in the initial `match({...})` record. The three nested, discriminated cases (two click events discriminated on `target.type`, one submit event) are added via the fluent `.case(def, handler)` API, which is more convenient for nested shapes. The source references the literal `'click'` and `'submit'` discriminators explicitly. `default: "assert"` ensures any non-matching event makes `route` throw a `TraversalError`.

```ts
export const route = match({
  string: (In: string) => `text:${In.length}`,
  number: (In: number) => `num:${In}`,
  "string[]": (In: string[]) => `list:${In.length}`,
})
  .case({ kind: "'click'", target: { type: "'button'", id: "string" } }, (In) => `btn:${In.target.id}`)
  .case({ kind: "'click'", target: { type: "'link'", href: "string.url" } }, (In) => `link:${In.target.href}`)
  .case({ kind: "'submit'", payload: { formId: "string", valid: "boolean" } }, (In) => `submit:${In.payload.formId}:${In.payload.valid}`)
  .default("assert")
```

Note: ArkType interprets bare-word string values in object definitions as references to bound types, so string-literal discriminators use the single-quoted form `"'click'"` / `"'button'"` / `"'link'"` / `"'submit'"`. The `string.url` keyword enforces a syntactically valid URL for the link `href`.

### `cli.ts`
Reads a single JSON document `{"events": [...]}` from stdin, iterates `events` in order, and calls `route` on each. Successfully routed events print their routed string on their own stdout line in input order. The first time `route` throws (the `"assert"` default → `TraversalError`), the CLI prints `ERR <message>` and stops processing remaining events. The process always exits with status 0.
