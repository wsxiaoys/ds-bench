## What was built

**`state_machine.py`** — Framework-agnostic, immutable per-`user_id` state machine:
- Three logical states: `LOGGED_OUT` (represented by `None`, so Bytewax discards the key from its state store), `LOGGED_IN`, `SUSPICIOUS`.
- `@dataclass(frozen=True) UserState` enforces immutability — every transition returns a new object.
- `update_state(state, event)` implements all the required rules:
  - `login` → `LOGGED_IN` (records login timestamp, resets counter).
  - `transaction` with `amount >= 1000` while logged in and within 300s of login → increment counter, → `SUSPICIOUS`.
  - 3rd large tx within the 300s window → emit `FRAUD_ALERT`, reset to `LOGGED_OUT`.
  - `transaction` more than 300s after login → reset to `LOGGED_OUT` (current tx ignored).
  - `logout` → `LOGGED_OUT` immediately.
  - Tx while `LOGGED_OUT` → ignored.
  - The 300s boundary is inclusive (`ts - login_ts <= 300`).

**`run.py`** — The Bytewax `Dataflow` pipeline + CLI:
- `FileSource` → `op.map` parse JSON → `op.key_on` by `user_id` → `op.stateful_map(update_state)` → `op.filter_value` (drop `None` emits) → `op.map_value` serialize to JSON → `FileSink`.
- Uses `map_value` (not `map`) so the `user_id` key is preserved, because `FileSink` routes items by their key.
- Runs synchronously in-process via `bytewax.testing.run_main`.
- Pre-creates the output file so it always exists (even with no alerts).

**`test_state_machine.py`** — 13 unit tests covering every transition, boundary conditions (exactly 300s inclusive, just past 300s), re-login-after-alert, immutability, and unknown events. All pass.

**`input.jsonl`** — Sample input exercising all paths (7 users). `requirements.txt` and `README.md` document usage and the Bytewax specifics.
