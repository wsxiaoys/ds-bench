The price stream MUST be driven by a long-running `@rx.event(background=True)` handler that updates an in-memory price book every 500 ms using a small bounded random walk. The page must render a live table and expose Start / Stop controls. A second click on **Start** MUST NOT spawn a duplicate update loop. The task evaluates correct use of Reflex background events (with `async with self` state-mutation context), cached computed vars, and `api_transformer` for a control / observation REST surface. ## Requirements * Create the Reflex app in the directory `/home/user/ticker_app`. * The verification system runs the backend on port `8000` using the command `uv run reflex run --backend-only --backend-port 8000 --loglevel warning` and interacts only with port `8000` over HTTP using the REST endpoints. The Reflex frontend (Next.js) does not need to be running during verification. * Implement a Reflex app named `ticker_app` whose root page renders: * A table with one row per symbol containing columns: **Symbol**, **Price**, **Percent Change**. * A **Start** button and a **Stop** button. * A small text status showing whether the ticker is currently running. * The price stream MUST be implemented inside a `@rx.event(background=True)` async method on the State class. State mutations MUST happen inside `async with self:` blocks. The loop MUST update prices every 500 ms (`asyncio.sleep(0.5)`) and apply a bounded random walk: every tick each symbol's price changes by `current_price * uniform(-0.005, +0.005)` (i.e. ±0.5% per tick), clamped so that price stays strictly positive. * Implement an idempotency guard so that pressing **Start** while the ticker is already running does NOT spawn a second concurrent update loop. The implementation MUST track this via a backend-only state var (a `_` prefixed attribute) checked / set inside `async with self:`. * Implement a `percent_change` view as a `@rx.var(cache=True)` computed var on the State class. It MUST be a dict mapping `symbol -> float`, computed as `round((current_price - seed_price) / seed_price * 100.0, 4)`. The computed var MUST depend on both the live price dict and the seed price dict. * Mount a FastAPI sub-app onto the Reflex app via `rx.App(api_transformer=...)`. The sub-app MUST expose the following JSON endpoints under the `/api/ticker` prefix. These endpoints share state with the Reflex State by reading / writing a module-level in-memory engine. They exist so headless verification can drive the ticker without a browser; the same engine MUST be used by both the Reflex UI Start/Stop event handlers and the REST endpoints. * `POST /api/ticker/start` — Start the ticker idempotently. Response JSON: `{"running": true, "started": <bool>}` where `started` is `true` only if this call actually started a new loop (i.e. previously not running), and `false` if a loop was already active. * `POST /api/ticker/stop` — Stop the ticker. Response JSON: `{"running": false}`. * `GET /api/ticker/snapshot` — Return a JSON object with the keys: * `running` (bool) * `update_count` (int) — number of completed 500 ms ticks since the most recent start * `seeds` (object: symbol -> float) * `prices` (object: symbol -> float) * `percent_changes` (object: symbol -> float, same formula as the computed var, rounded to 4 decimal places) * The symbol universe and seed prices MUST be exactly: * `AAPL`: 150.00 * `GOOG`: 2800.00 * `MSFT`: 300.00 * `AMZN`: 3300.00 * `TSLA`: 700.00 * The random walk MUST be seeded deterministically inside the task code (the executor chooses any fixed seed; no environment variable is read for randomness). * After verification finishes, the executor MUST kill all background dev servers that were started for this task. The background event handler itself owns the loop and the idempotency guard. * Inside the background handler, use `async with self:` to read / set the idempotency guard (e.g. `_loop_active`) and to write base vars (`prices`, `update_count`, `running`). * For `api_transformer`, build a `fastapi.FastAPI()` instance and pass it to `rx.App(api_transformer=...)`. The endpoints can manipulate / read the shared engine directly; they do NOT need to go through a Reflex State token. * The shared in-memory engine should expose: `start()` (idempotent), `stop()`, `snapshot()`, and a coroutine `tick_once()` (or an internal asyncio task). A clean way is to give the engine its own `asyncio.Task`, and have the Reflex background event also drive (or mirror) the same engine so the UI table updates live. * Computed vars are cached by default. Make sure the `percent_change` computed var actually re-runs when prices change by reading both `self.prices` and `self.seeds` inside its body. * Avoid storing non-serializable types in any State var that is not underscore-prefixed.
