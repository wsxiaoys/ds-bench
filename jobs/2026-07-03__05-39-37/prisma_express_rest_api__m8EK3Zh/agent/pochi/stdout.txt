## What was done

**1. Prisma schema** (`prisma/schema.prisma`) — defined `User` (id, unique email, name) and `Task` (id, title, optional description, status defaulting to `"todo"`, priority defaulting to `0`, userId FK, createdAt, updatedAt) with a `User ↔ Task[]` relation.

**2. Migrations** — ran `npx prisma migrate dev --name init`, which created and applied `prisma/migrations/20260703054521_init/migration.sql` (User table, Task table with FK + unique email index) against `dev.db`.

**3. Driver adapter** — Prisma 7 removed the internal connection engine, so `new PrismaClient()` alone throws. Installed `@prisma/adapter-better-sqlite3` + `better-sqlite3` and instantiated the client as:
```js
const adapter = new PrismaBetterSqlite3({ url: process.env.DATABASE_URL || "file:./dev.db" });
const prisma = new PrismaClient({ adapter });
```

**4. `server.js`** (port 3000) — full CRUD with input validation, Prisma error mapping (P2002→409, P2025→404, P2003→400), JSON body parsing, and graceful shutdown:
- `POST /users` → 201, body `{ email, name }`
- `POST /tasks` → 201, body `{ title, description?, userId, priority? }`
- `GET /tasks` → 200, supports `?status=todo` and `?userId=<id>` filters, includes `user`, ordered by newest first
- `GET /tasks/:id` → 200 with `user` included (404 if missing)
- `PATCH /tasks/:id` → 200, accepts any subset of title/description/status/priority
- `DELETE /tasks/:id` → 204
