## What the pipeline does

1. **Input** — Reads edges from `/home/user/graph_pipeline/input_edges.jsonl` using Bytewax's `FileSource` (batch size 1 for strict in-order processing).
2. **Parse** — `op.map` parses each JSONL line into a `{"u", "v"}` dict.
3. **Single-partition routing** — `op.key_on` assigns every edge a constant key (`"UNION_FIND"`), guaranteeing all edges route to the same `stateful_map` partition so the Union-Find maintains a global view.
4. **Stateful Union-Find** — `op.stateful_map` maintains a `UnionFind` data structure (union-by-rank + path compression) and emits one event per edge:
   - `already_connected` with `component_size` when `u` and `v` share a root.
   - `merged` with `new_component_size` when two distinct components are joined.
5. **Output** — Writes the events to `/home/user/graph_pipeline/output_events_${run-id}.jsonl` via `FileSink`, where the run-id is read from `/logs/artifacts/run-id`.

## Key design decisions

- **Picklable state** — The `UnionFind` class uses only plain `dict` attributes (`parent`, `rank`, `size`) with `__slots__`, making it trivially picklable as required by Bytewax's SQLite recovery (verified with `pickle.dumps`/`pickle.loads`).
- **`FileSink` expects `(key, value)` tuples** — The `stateful_map` output is already keyed `(UNION_FIND_KEY, json_string)`, which is exactly the format `FixedPartitionedSink` needs for routing, so no extra unwrap step is required.
