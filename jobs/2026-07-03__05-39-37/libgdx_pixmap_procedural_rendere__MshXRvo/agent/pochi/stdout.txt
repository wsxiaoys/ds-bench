## How it satisfies the requirements
- **Dependencies**: `build.gradle` declares `gdx:1.14.2`, `gdx-backend-headless:1.14.2`, and `gdx-platform:1.14.2:natives-desktop`.
- **HeadlessApplication**: `Main` extends `ApplicationAdapter`. `main()` boots `new HeadlessApplication(listener, config)`; all `Pixmap` drawing and `PixmapIO.writePNG` happen inside `create()` on the libGDX thread — never directly from `main`.
- **Threading/flush**: after `create()` queues the work and calls `Gdx.app.exit()`, `main()` reflects the headless back-end's `mainLoopThread` and `join()`s it before printing the summary, guaranteeing the PNG bytes are fully flushed. `config.updatesPerSecond = -1` keeps the render loop from spinning.
- **Command script parsing**: one command per line, whitespace-tokenized; blank lines and `#` comments ignored; `SIZE` must be the first non-comment/non-blank line and allocates an `RGBA8888` `Pixmap`. Later commands overwrite earlier ones. Supported: `SIZE`, `FILL`, `RECT`, `LINE`, `CIRCLE`, `PIXEL`. 0–255 color components are normalized to `[0,1]` floats before `Pixmap.setColor`.
- **PNG output**: written via `PixmapIO.writePNG(Gdx.files.absolute(outputPath))`. The pixmap is `dispose()`d, and `HeadlessApplication` shuts down cleanly.
- **Summary line**: prints exactly `RENDER_OK width=<w> height=<h> commands=<n>` to stdout, where `<n>` counts drawing commands only (excludes `SIZE`, comments, blanks). Errors print `RENDER_ERROR <msg>` to stderr and exit `1`.

## `run.sh`
Accepts two positional arguments (`<input-command-file> <output-png-path>`), resolves them to absolute paths, and runs:

`--offline` is used because the Docker image pre-populates the Gradle cache; it falls back to a system `gradle` if the wrapper is absent.
