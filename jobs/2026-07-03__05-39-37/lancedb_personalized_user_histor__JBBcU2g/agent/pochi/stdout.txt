## How it works
1. **Args**: `--user-id`, `--query-vec` (`.npy` path), `--k`, `--output`.
2. **Load query vector** from the `.npy` file (flattened to a 1-D `float32` vector).
3. **Connect** to the LanceDB at `/home/user/project/data` and opens the existing `items` and `user_history` tables (read-only usage — no recreation/modification).
4. **Recent history**: fetches the user's rows from `user_history`, sorts by `ts` descending, and takes up to the 10 most recent `item_id`s.
5. **Taste vector**: joins those item IDs back to the `items` table (`id IN (...)`) to retrieve their 64-d embeddings and computes their mean.
6. **Blending**: `blended = (1 - alpha) * query + alpha * taste`, where `alpha` comes from the `BLEND_ALPHA` env var (default `0.3`). When the user has no history, it falls back to the pure query vector.
7. **Vector search**: runs `items.search(blended)` with a `WHERE id NOT IN (...)` SQL predicate excluding already-seen items.
8. **Output**: writes the top-k item IDs in rank order as a JSON array of integers to the output file.

- **Few-interactions user** (`u_other_0`, 5 interactions): works with partial history.
- Output is a valid JSON list of Python `int`s.
