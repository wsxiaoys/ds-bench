# Shared Team Memory with Alchemyst AI (Python) ## Background Alchemyst AI provides a "Context Engine" that can act as persistent memory for AI agents. A common collaboration pattern is to let multiple users contribute to the **same** `session_id` so that everyone shares a common context (e.g., a team standup, a support ticket thread, or a multi-user chat). In this task you will build a small Python CLI that simulates two teammates, **alice** and **bob**, who participate in the **same** session and add their own memory entries. The CLI must then prove that the shared session can be recalled by either teammate via Alchemyst's memory retrieval. ## Requirements - Use the official Python SDK package `alchemystai` (>= 0.10.0). - The API key MUST be read from the `ALCHEMYST_AI_API_KEY` environment variable. Never hardcode the key, never use mocks, and never stub the SDK. - The project path is `/home/user/myproject` and the CLI entrypoint must be `main.py` inside this path. - The CLI must support the command: `python3 main.py --user-id <user-id> --query <query>` - `--user-id` is the calling teammate's user id. It MUST accept either `alice-<run-id>` or `bob-<run-id>`. - `--query` is a free-form natural-language string used for the retrieval call. - Read the current run id from `/logs/artifacts/run-id` and derive the following identifiers from it: - Shared session id: `session-<run-id>` - Alice's user id: `alice-<run-id>` - Bob's user id: `bob-<run-id>` - On every invocation, the CLI MUST: 1. Ensure both Alice's and Bob's memory entries exist in the shared session `session-<run-id>` (idempotent seeding is acceptable). - Alice's memory content MUST include the phrase: `Alice prefers Python for data processing pipelines` - Bob's memory content MUST include the phrase: `Bob recommends PostgreSQL with TimescaleDB for time-series storage` 2. Retrieve the shared session's context from the Alchemyst memory store and print results to STDOUT. - STDOUT format requirements: - Print exactly one header line in the form `USER: <user-id>`. - Print exactly one header line in the form `SESSION: session-<run-id>`. - Print a line `RETRIEVED:` followed by one or more lines starting with `- ` containing snippet text. Each retrieved snippet must be on its own line. - The retrieved snippets MUST collectively contain BOTH of the seeded phrases (the Alice phrase AND the Bob phrase) so that either user can verify the other's contribution is visible. - Exit code MUST be `0` on success. - The CLI MUST exit with a non-zero code if `ALCHEMYST_AI_API_KEY` or `/logs/artifacts/run-id` is missing. ## Implementation Hints - Install the SDK with `pip install alchemystai` and instantiate it as `AlchemystAI(api_key=os.environ["ALCHEMYST_AI_API_KEY"])`. - Memory entries are written with `client.v1.context.memory.add(user_id=..., session_id=..., contents=[{"content": ...}])` (consult the Python SDK reference for the exact argument names — note that some docs use `content` while v0.10.0 expects a list of `contents`). - **CRITICAL — Python SDK v0.10.0 caveat:** `client.v1.context.memory.search` does **NOT** exist in `alchemystai==0.10.0`. ## Summary

**Behavior of `python3 main.py --user-id <user-id> --query <query>`**

1. Reads the run id from `/logs/artifacts/run-id` and derives:
   - `session_id = "session-<run-id>"` (the shared session)
   - `alice-<run-id>` and `bob-<run-id>` user ids
2. Validates `--user-id` is one of those two; rejects anything else (exit 5).
3. Exits non-zero (exit 3 / 4) if `/logs/artifacts/run-id` or `ALCHEMYST_AI_API_KEY` is missing.
4. Idempotently seeds Alice's and Bob's memories into the shared session via `client.v1.context.memory.add(session_id=..., contents=[{"content": ...}])`. Each entry embeds the user's run-id so it can be attributed to the contributor.
5. Retrieves the shared session context with `client.v1.context.search(...)` (note: `client.v1.context.memory.search` does **not** exist in `alchemystai==0.10.0`, exactly as the task caveat warns). To guarantee both seed phrases appear in the output regardless of the user's natural-language query, the retrieval runs the user's query **plus** two targeted phrase queries, merges and dedupes the results, filters them to contexts that belong to this session (via `file_name` / `group_name` / content in the returned metadata), and retries with back-off until both phrases are visible (15 attempts × 2 s).
6. Emits the exact STDOUT format the spec requires:
   ```
   USER: <user-id>
   SESSION: session-<run-id>
   RETRIEVED:
   - <snippet 1>
   - <snippet 2>
   ...
   ```

**Required phrases (idempotent, always present after the first indexed run):**
- `Alice prefers Python for data processing pipelines` (Alice's entry)
- `Bob recommends PostgreSQL with TimescaleDB for time-series storage` (Bob's entry)
