# B2B Newsletter Writer (TypeScript CLI) ## Background Inspired by Alchemyst AI's community B2B Newsletter Writer template, build a Node.js TypeScript command-line tool that uses the Alchemyst AI context engine together with the OpenAI Chat Completions API to produce a short, topic-focused newsletter for a B2B audience. The tool must: 1. Ingest a fixed corpus of seeded research articles into the Alchemyst context engine. 2. Take a `--topic` argument from the CLI, query the context engine for the most relevant snippets, and use OpenAI to compose a 3-section newsletter that draws on the retrieved context. 3. Persist the generated newsletter as Markdown to a known output path so a downstream verifier can inspect it. This is a non-trivial integration task: the agent must wire together two external APIs (Alchemyst and OpenAI), keep ingestion idempotent across reruns, parse CLI arguments, and produce valid Markdown. ## Requirements * Implement the program in TypeScript and compile it to JavaScript under `dist/` so it can be launched with plain `node`. * Use the official `@alchemystai/sdk` package to talk to the Alchemyst context engine (the `v1.context.add` and `v1.context.search` primitives). * Use the official `openai` package to call the OpenAI Chat Completions API. * Read the Alchemyst API key from the `ALCHEMYST_AI_API_KEY` environment variable and the OpenAI API key from the `OPENAI_API_KEY` environment variable. The program must never hardcode keys or use mocked clients. * Seed exactly the following five research articles into the context engine on every run. Each article's `metadata.file_name` MUST be namespaced with the current `run-id` (read from `/logs/artifacts/run-id`) to avoid `409 Conflict` errors on reruns and to keep concurrent runs isolated. Built a Node.js TypeScript CLI `B2B Newsletter Writer` at `/home/user/myproject` that wires together the official `@alchemystai/sdk` (v0.11.1), the official `openai` package (v6.45.0), and `minimist` for CLI parsing. It compiles via `npm run build` (tsc, strict mode) and is launched as `node dist/main.js --topic "<topic>"`.

## Project layout (`/home/user/myproject`)

```
src/main.ts          # TypeScript source
dist/main.js         # Compiled entry point (CommonJS, ES2022)
output/newsletter.md # Generated newsletter (created at runtime)
tsconfig.json        # src -> dist, target ES2022, strict, CommonJS
package.json         # deps + npm run build / start scripts
```

## How it works
1. **CLI parse**: `minimist` reads `--topic` (or `-t`). Refuses to proceed without it.
2. **Run-id**: Reads `/logs/artifacts/run-id` (e.g. `zrpe4oxc4n`) on every invocation and namespaces every `metadata.fileName` with it so concurrent runs never collide and re-runs in the same environment never produce `409 Conflict`.
3. **Seed (idempotent)**: For each of the five required articles (`b2b_article_ai_agents_<run-id>.md`, `..._rag_<run-id>.md`, `..._vector_db_<run-id>.md`, `..._prompt_engineering_<run-id>.md`, `..._devops_<run-id>.md`) the program calls `client.v1.context.add({ context_type: 'resource', scope: 'internal', source: 'b2b-newsletter-writer', documents:[{content}], metadata:{fileName, fileType, groupName, lastModified, fileSize} })`. Namespacing keeps it safe to invoke on every run.
4. **Search**: `client.v1.context.search({ query: <topic>, minimum_similarity_threshold: 0.25, similarity_threshold: 0.9, scope: 'internal', metadata: 'true' })`. The `content` fields of the returned contexts are concatenated into a numbered grounding block.
5. **Compose**: `openai.chat.completions.create({ model: 'gpt-4o-mini', temperature: 0.3, messages:[system,user] })` where the system prompt enforces executive-tone B2B grounding and the user prompt explicitly requires Markdown output with the three section headings `## Why it matters`, `## What's new`, `## What to do next`, citing snippet numbers.
6. **Persist**: Writes the (trimmed) model output to `/home/user/myproject/output/newsletter.md`, creating the directory with `fs.mkdirSync({ recursive: true })` if missing.

## Security / compliance
- Reads the Alchemyst key from `process.env.ALCHEMYST_AI_API_KEY` and the OpenAI key from `process.env.OPENAI_API_KEY`. Both are validated on startup with a clear `[fatal]` message if missing.
- No keys are hardcoded.
- No mocks; the real `@alchemystai/sdk` and `openai` clients are constructed from the env keys.
