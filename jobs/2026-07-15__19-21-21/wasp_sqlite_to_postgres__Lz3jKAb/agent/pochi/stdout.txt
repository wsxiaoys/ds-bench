Wasp's built-in background job executor, **PgBoss**, only works on PostgreSQL, so once the migration is done you must also add a PgBoss background job to justify (and exercise) the new database. The project is a classic Wasp project: a `main.wasp` declaration file, a separate `schema.prisma` file that holds the datasource/models, a `migrations/` directory with the current SQLite migrations, and the React/Node source under `src/`. Remove the existing `migrations/` directory (and clear Wasp's cached artifacts), then create a brand-new initial migration for PostgreSQL. Add a new entity named `EventLog` to the data model with exactly the fields `id` (auto-increment primary key), `message` (a text/String column), and `createdAt` (a timestamp that defaults to now). This entity must be created by your new PostgreSQL migration. Each time the startup job runs it must insert exactly **one** new `EventLog` row. * The existing `GET /api/stats` endpoint must return HTTP 200 with a JSON body of the shape `{ "taskCount": <number> }`, where `<number>` is the current count of `Task` rows read from the database. * Start command: `wasp start` (the Wasp server listens on port `3001` and the web client on port `3000`).
