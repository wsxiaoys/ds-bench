# Atomic Fund Transfer Action in Wasp ## Background You are working on `bankapp`, a full-stack Wasp application that tracks bank accounts and a ledger of money transfers. The project already defines the data model, a database seed, and a placeholder page, but the money-transfer logic does not exist yet. Your job is to implement it as a Wasp Action that moves funds between two accounts **atomically**. ## Requirements * Implement a Wasp Action named `transferFunds` that transfers money from one account to another. * Within a **single atomic database transaction**, the Action must: debit the sender's balance, credit the recipient's balance, and create a ledger record describing the transfer. * If the sender does not have enough money, the entire operation must roll back: no balance may change and no ledger record may be created. The Action must fail with an error in this case. * The Action must be safe when several transfers run concurrently (no lost updates / partial applies). ## Implementation Hints * The app already defines two Prisma entities: an account model (with a unique `name` and an integer `balance`) and a ledger/transaction model that records each transfer's sender, recipient, and amount. A database seed creates sample accounts that are identified by their `name`. Inspect the project source to learn the exact entity and field names. * Declare the Action in the Wasp configuration and make sure it lists **every entity it touches** so Wasp injects them into the context and invalidates the right caches. * The per-model delegates on `context.entities` cannot, on their own, wrap several writes in one transaction. The full Prisma client (which exposes `$transaction`) can be imported from `wasp/server`. Use an interactive transaction so the debit, credit, and ledger insert either all commit or all roll back together. * Protect against race conditions between concurrent transfers by choosing an appropriate transaction isolation level and gracefully handling transient serialization failures. * Signal insufficient funds by throwing Wasp's `HttpError` with status code `400`; when this happens the database must be left completely unchanged. * The Action receives its arguments as `{ from: string, to: string, amount: number }`, where `from` and `to` are account names and `amount` is a positive integer number of whole currency units. * On success the Action must return an object with: `from` and `to`, each an object `{ name: string, balance: number }` holding the balances **after** the transfer; `amount`, echoing the transferred amount; and `ledgerCount`, the total number of ledger records that exist in the database after the transfer completes. * Do not add authentication to this Action; it must be publicly callable. * Project path: /home/user/bankapp * Start command: `wasp start` (the web client is served on port 3000 and the server/operations HTTP API on port 3001).
