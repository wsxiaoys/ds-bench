Here is a summary of the implementation details:

### 1. Shared Implementation Modules
We created the three required shared modules to ensure reusable logic across the resources:
* **`Forum.Archive.Preparations.ArchiveScope`** (`lib/forum/archive/preparations/archive_scope.ex`): Inspects the action being queried and scopes results dynamically:
  * `:read` action filters where `archived_at` is `nil`.
  * `:archived` action filters where `archived_at` is NOT `nil`.
  * `:with_archived` action returns all records.
* **`Forum.Archive.Changes.CascadeArchive`** (`lib/forum/archive/changes/cascade_archive.ex`): Handles soft deletion recursively. If the record is already archived, it does nothing. Otherwise, it generates a unique `archive_batch_id` and `archived_at` timestamp, updating the current record and recursively cascading the same batch ID and timestamp to all live/unarchived descendants. Already-archived descendants retain their original values byte-for-byte.
* **`Forum.Archive.Changes.CascadeRestore`** (`lib/forum/archive/changes/cascade_restore.ex`): Handles recovery. It sets `archived_at` and `archive_batch_id` to `nil` on the target record, then recursively restores all descendants that share the *same* `archive_batch_id` as the target's pre-restore batch ID. Descendants with different batch IDs remain untouched.

### 2. Resources and Domain Registration
We implemented the three resources inside `lib/forum/content/`:
* **`Forum.Content.Post`** (`lib/forum/content/post.ex`)
* **`Forum.Content.Comment`** (`lib/forum/content/comment.ex`)
* **`Forum.Content.Reaction`** (`lib/forum/content/reaction.ex`)

Each resource:
* Uses the ETS data layer configured with `private? true`.
* Defines the primary key `id` of type `:uuid` (generated by default).
* Defines the public attributes `archived_at` and `archive_batch_id`.
* Configures relationships and aggregates (`comment_count` on `Post`, `reaction_count` on `Comment`).
* Implements the seven required actions: `:create`, `:read` (primary), `:archived`, `:with_archived`, `:archive`, `:restore`, and `:purge`.
* Registers with the `Forum.Content` domain (`lib/forum/content.ex`).

### 3. Purge Semantics
* **`Forum.Archive.Validations.MustBeArchived`** (`lib/forum/archive/validations/must_be_archived.ex`): Validates that a record is archived before it can be purged. It raises the exact requested invalid changes error on the `:archived_at` field with the message `"must be archived before it can be purged"`.
* **`Forum.Archive.Changes.CascadePurge`** (`lib/forum/archive/changes/cascade_purge.ex`): Permanently and recursively removes the record and all of its descendants from storage. It utilizes changeset contexts to bypass the "must be archived" validation for descendants.

### 4. Global Read Scoping
By applying the `ArchiveScope` preparation on the primary read action `:read`, the non-archived scoping propagates globally. This means relationship loads, aggregates (`comment_count`, `reaction_count`), and filter expressions traversing relationships automatically exclude archived records. Calling `Ash.get/3` on an archived record automatically yields an `Ash.Error.Query.NotFound` wrapped in `Ash.Error.Invalid`.

### 5. Authorization
All resources run `Ash.Policy.Authorizer`:
* The `:archived` read action is restricted strictly to administrators (actors where `:role` is `:admin`). Non-admin actors (including `nil`) receive a forbidden error (`Ash.Error.Forbidden`).
* All other actions are permitted for everyone (including `nil`).

The project compiles cleanly with `mix compile` and has been thoroughly tested.
