# Paginated Users API with RedwoodSDK, Cloudflare D1 & Drizzle ## Background You are building a small edge-first backend with RedwoodSDK (rwsdk). A RedwoodSDK starter project has already been scaffolded for you. Your job is to back it with a Cloudflare D1 (SQLite) database accessed through Drizzle ORM, and expose a small JSON REST API for managing users. ## Requirements * Persist users in a Cloudflare D1 database accessed via Drizzle ORM. * Expose a JSON REST API under `/api/users` that supports listing users with pagination and creating users. * The application must run through the standard RedwoodSDK Vite dev server. ## Implementation Hints * RedwoodSDK routes are defined with `defineApp` and `route` in `src/worker.tsx`. A path can map an object of HTTP-method handlers (e.g. `{ get, post }`) and each handler receives the standard Web `Request`. * Read query parameters from the request using the standard `URL`/`URLSearchParams` API. * Configure a D1 binding named `DB` in `wrangler.jsonc`, wire up Drizzle's `drizzle-orm/d1` driver, define your schema, and generate migrations with `drizzle-kit` so the schema can be applied to the local D1 database. * Return `Response` objects with an `application/json` content type and the appropriate HTTP status codes. ## Runtime & API Contract * Project path: `/home/user/project` * The Cloudflare D1 binding MUST be named `DB`. * Database migrations must be generatable/appliable against the local D1 database (a Drizzle migration must exist in the repository). * Start command: `npm run dev` * Port: `5173` ### Data model Each user has: * `id`: integer, auto-generated, unique, monotonically increasing in insertion order. * `name`: string, required. * `email`: string, required, unique. ### Endpoints #### `GET /api/users` Lists users ordered by `id` ascending (i.e. oldest created first). Query parameters (both optional): * `limit`: maximum number of users to return. Defaults to `10` when omitted. * `offset`: number of users to skip from the start. Defaults to `0` when omitted. On success returns status `200` with a JSON body: ```json { "users": [ { "id": number, "name": string, "email": string } ], "total": number, "limit": number, "offset": number } ``` Where `users` is the requested page (respecting `limit` and `offset`), `total` is the total number of users in the database (independent of pagination), and `limit`/`offset` echo the effective values used for the query. #### `POST /api/users` Creates a new user. Request body (JSON): ```json { "name": string, "email": string } ``` * On success returns status `201` with the created user as JSON: `{ "id": number, "name": string, "email": string }`. * If `name` or `email` is missing or empty, returns status `400`. * If a user with the same `email` already exists, returns status `409`.

## What was added/changed

### Database layer

- **`src/db/schema.ts`** (new) — Drizzle schema for the `users` table: `id integer PRIMARY KEY AUTOINCREMENT`, `name text NOT NULL`, `email text NOT NULL UNIQUE`, plus a `created_at` timestamp.
- **`src/db/client.ts`** (new) — Creates a singleton Drizzle client bound to the `DB` D1 binding via `cloudflare:workers`' `env`, matching the pattern in the official RedwoodSDK Drizzle guide.
- **`drizzle.config.ts`** (new) — `drizzle-kit` config pointing at the schema and `drizzle/migrations`.
- **`drizzle/migrations/0000_amused_medusa.sql`** + meta files (generated) — SQL migration creating the `users` table and the `users_email_unique` index.
- **`wrangler.jsonc`** (modified) — added the `d1_databases` binding `DB` whose `migrations_dir` is `drizzle/migrations`. This also surfaces `DB: D1Database` on the global `Env` type via `wrangler types`.

### API

- **`src/app/api/users.ts`** (new) — `listUsers` (GET) and `createUser` (POST) handlers.
  - GET parses `limit` (default `10`) and `offset` (default `0`) query parameters via the standard `URL`/`URLSearchParams` API, runs the page query and a `count(*)` in parallel, and returns `{ users, total, limit, offset }` with status `200`.
  - POST parses the JSON body, returns `400` for missing/empty `name` or `email`, returns `409` when the email is already in use (with a race-safe catch around the unique constraint), and returns `201` with the newly created user on success.
  - Both handlers return `Response` objects with `content-type: application/json`.
- **`src/worker.tsx`** (modified) — registers `route("/api/users", { get: listUsers, post: createUser })` alongside the existing renderer.
- **`package.json`** (modified) — added `migrate:new`, `migrate:dev`, `migrate:prod` scripts.
- **`README.md`** (modified) — short docs for the database setup and the API contract.
