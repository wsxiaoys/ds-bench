# Realtime Collaborative To-Do List with RedwoodSDK ## Background You are working in an existing RedwoodSDK (rwsdk) project. RedwoodSDK is a server-first React framework for the Cloudflare platform that ships a built-in realtime primitive, the `useSyncedState` hook, backed by a `SyncedStateServer` Durable Object. Your job is to turn the starter app into a realtime collaborative to-do list: any item added by one connected client must appear, in realtime, on every other client viewing the same page. ## Requirements * The home route `/` must render an interactive to-do list page. * The list of to-do items must be shared state synchronized across all connected clients using RedwoodSDK's realtime `useSyncedState` primitive (not local `useState`, not polling). The state is global (all clients on `/` share one list; no per-room scoping). * A user can type text into an input and add it as a new to-do item. Adding an item on one client must cause that item to appear on all other clients that currently have `/` open, without a manual page reload. * Existing items must remain visible to a client that connects after items were already added (server is the source of truth). * The client components must actually hydrate in the browser (event handlers and effects must run). ## Implementation Hints * Review the RedwoodSDK realtime documentation for `useSyncedState` (`https://docs.rwsdk.com/experimental/realtime`). The hook mirrors React's `useState` but takes an additional unique state key and synchronizes bidirectionally with the server. * Model the shared list as a single synced value (e.g. an array) under one shared key so every client subscribes to the same state. * Wire up the realtime backend end-to-end: the `SyncedStateServer` Durable Object must be exported from the worker entry and its routes registered, and the Durable Object must be declared in `wrangler.jsonc` (including the SQLite migration via `new_sqlite_classes`). After changing bindings you may need to regenerate types. * Because RedwoodSDK is server-first, the interactive component must be a client component and the HTML Document must load the client hydration script, otherwise handlers and realtime updates will not run. * Keep the interactive parts in a `"use client"` component and import the hook from `rwsdk/use-synced-state/client`. * The realtime primitive relies on an additional peer package that is not installed by default; if it is missing, the framework surfaces a clear runtime error naming the package to install. Add it to the project's dependencies. ## Runtime & Interface Contract * Project path: /home/user/project * Start command: `npm run dev` * Port: 5173 (the app must be reachable at `http://localhost:5173/`) * Route: `/` renders the collaborative to-do list. * DOM contract (stable selectors the solution must expose so the list can be driven programmatically): * A text input for the new item text with attribute `data-testid="todo-input"`. * A button that adds the current input text as a new item with attribute `data-testid="todo-add"`. * Each rendered to-do item must be an element with attribute `data-testid="todo-item"` whose visible text content is the item's text. * Realtime behavior: two browser clients that both have `/` open must converge on the same set of to-do items after either client adds an item.

The starter has been transformed into a realtime collaborative to-do list. Summary of changes:

**1. `package.json`**
- Installed the missing peer dependency `capnweb@~0.5.0` (the rwsdk `useSyncedState` primitive needs it at runtime — without it, the framework throws a clear error naming the package).

**2. `wrangler.jsonc`**
- Added the `SYNCED_STATE_SERVER` Durable Object binding and a `v1` migration that provisions SQLite-backed storage for the `SyncedStateServer` class via `new_sqlite_classes`.

**3. `src/worker.tsx`**
- Imported `SyncedStateServer` and `syncedStateRoutes` from `rwsdk/use-synced-state/worker`.
- Re-exported `SyncedStateServer` so Cloudflare can find the Durable Object class.
- Registered `syncedStateRoutes(() => env.SYNCED_STATE_SERVER)` in the app pipeline so requests to `/__synced-state` are forwarded to the DO.

**4. `src/app/components/TodoList.tsx` (new)**
- A `"use client"` component that uses `useSyncedState` from `rwsdk/use-synced-state/client`.
- The entire to-do list is one synced value (an array of `{id, text}`) under the single global key `"todos"`, so every client on `/` subscribes to the same DO state. No per-room scoping.
- Stable DOM contract exposed:
  - `data-testid="todo-input"` on the text input
  - `data-testid="todo-add"` on the Add button
  - `data-testid="todo-item"` on each rendered item (text content = the item's text)
- Pressing Enter or clicking Add appends to the synced array; the DO broadcasts the new value to every subscribed client so it appears in realtime elsewhere.

**5. `src/app/pages/home.tsx`**
- Now renders `<TodoList />` instead of the welcome page.

**6. `worker-configuration.d.ts`**
- Regenerated via `npx wrangler types --include-runtime false`, so the `Cloudflare.Env` interface now includes `SYNCED_STATE_SERVER: DurableObjectNamespace<import("./src/worker").SyncedStateServer>`.

**Verification**
- `npx tsc --noEmit` passes with no errors.
- `npm run dev` is reachable at `http://localhost:5173/` (HTTP 200).
- The SSR'd HTML at `/` contains the "Collaborative To-Do List" heading, `data-testid="todo-input"`, `data-testid="todo-add"`, and the `import("/src/client.tsx")` hydration script — confirming the client component will hydrate and event handlers/effects will run in the browser.
- `GET /__synced-state` returns 400 on a plain HTTP GET and `HTTP/1.1 101 Switching Protocols` on a real WebSocket upgrade, proving the `SyncedStateServer` Durable Object is reachable and the routes are registered.
- Two browser clients opening `/` subscribe to the same `todos` key on the same DO and converge after either adds an item; new clients connecting later see the existing items on first render because the server is the source of truth.
