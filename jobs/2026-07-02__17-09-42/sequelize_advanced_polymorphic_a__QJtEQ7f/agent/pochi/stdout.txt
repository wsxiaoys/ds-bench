## Polymorphic associations implementation

**`User.hasMany(Image, ...)`** (`models/user.js`):
```js
User.hasMany(models.Image, {
  foreignKey: 'imageableId',
  constraints: false,
  scope: { imageableType: 'user' },
  as: 'profilePictures',
});
```

**`Product.hasMany(Image, ...)`** (`models/product.js`):
```js
Product.hasMany(models.Image, {
  foreignKey: 'imageableId',
  constraints: false,
  scope: { imageableType: 'product' },
  as: 'productPhotos',
});
```

**`Image.belongsTo(...)`** (`models/image.js`) uses two distinct aliases (`imageableUser`, `imageableProduct`) so a single column (`imageableId`) can reference either table. The handler in `GET /images/:id` then resolves the correct one based on `imageableType` and exposes it as `imageable` in the response.

The `scope` option on `hasMany` REDACTEDmatically appends the `imageableType` filter when querying or creating associated images. `constraints: false` prevents Sequelize from adding a DB-level foreign-key constraint that would be ambiguous across tables.
