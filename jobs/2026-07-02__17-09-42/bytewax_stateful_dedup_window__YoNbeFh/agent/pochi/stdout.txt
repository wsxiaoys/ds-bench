## Files

- **`run.py`** — The Bytewax dataflow entrypoint. Run it with `python3 run.py`.
- **`input.jsonl`** — The sample input file.
- **`output.jsonl`** — Generated by running `run.py`.

## How `run.py` works

1. **Read** — `FileSource("input.jsonl", batch_size=1)` reads one line per epoch. The `batch_size=1` is critical because Bytewax's `stateful_batch` (which backs `op.stateful`) re-keys items inside a single batch, so emitting items one-at-a-time preserves the original input order.
2. **Parse** — JSON lines are parsed into Python dicts; blank lines are filtered out.
3. **Key by user** — Each event becomes a `(user_id, event)` 2-tuple so the stateful operator can route per-user.
4. **Stateful dedup** — A `DeduplicationLogic(op.StatefulLogic)` instance is created per user via the `build_logic` builder. On every item:
   - **Cleanup pass**: any `event_id` in state whose last emitted timestamp is more than 10 seconds before the current event's timestamp is purged (`ts < current_ts - 10s`).
   - **Dedup check**: drop if a previous emit exists with `current_ts <= previous_ts + 10s`; otherwise emit and update state to the current timestamp (restarting the 10s window).
   - `snapshot()` returns an immutable shallow copy for recovery; `on_eof()` returns `DISCARD`.
5. **Serialize** — Surviving events are converted back to JSON strings.
6. **Write** — `FileSink("output.jsonl")` writes one JSON object per line. An empty `input.jsonl` results in an empty `output.jsonl` (touched explicitly because `FileSink` doesn't create the file when no items are written).
