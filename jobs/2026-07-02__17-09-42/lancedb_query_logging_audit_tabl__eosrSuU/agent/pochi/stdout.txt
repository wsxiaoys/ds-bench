### Summary of the implementation

**Constructor — `LoggedSearcher(db_uri, articles_table, logs_table)`**
- Opens the database via `lancedb.connect(db_uri)` and eagerly opens the `articles` table (so a missing table fails fast at construction).
- Holds the logs table handle in `None` so it can be created lazily on first `search()`.

**`search(query_vector, top_k, query_id, user_id, query_text="")`**
1. Validates `top_k` is a positive `int`.
2. Wraps `self._articles.search(query_vector).limit(top_k).to_list()` with `time.perf_counter()` start/end, converting the delta to milliseconds and clamping to a strictly-positive float.
3. Builds an audit row with all seven required logical fields.
4. Calls `_ensure_logs_table()` → lazily calls `db.create_table(name, schema=QUERY_LOGS_SCHEMA)` if `logs_table` is not in `db.table_names()`, otherwise reopens it.
5. Appends exactly one row via `logs.add([row])`.
6. Returns the hits list unchanged (each hit contains `id`, `title`, `embedding`, `_distance`).

**`query_logs` schema (created lazily)**
| column | type |
|---|---|
| `query_id` | `string` |
| `user_id` | `string` |
| `query_text` | `string` |
| `ts` | `timestamp[us]` (UTC-aware `datetime.datetime.now(timezone.utc)`) |
| `latency_ms` | `float64`, strictly positive |
| `hit_count` | `int64` (length of returned hits) |
| `top_ids` | `list<int64>` (rank-ordered `id`s coerced to plain Python `int`) |
