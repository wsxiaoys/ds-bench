**How the requirements are met:**

1. **Project setup** — `package.json` pins `arktype` to exactly `2.2.0`. After `npm install`, ArkType 2.2.0 is the only version installed in `node_modules`.

2. **Uses ArkType's `match` record API** — `match` is imported from `'arktype'` and the cases are passed as an object literal: `match.at("status", { ...cases..., default: "assert" })`. This is the natural ArkType 2.x form for a tag-discriminated union: the second `(...)(input)` invocation is the matcher itself being called on the parsed JSON payload. No manual `if/else`/`switch` is used on `status`.

3. **Three branches**:
   - `"'success'"` → `OK: ${JSON.stringify(data)}`
   - `"'error'"` → `ERR ${code} ${reason}`
   - `"'pending'"` → `PENDING`
   - `default: "assert"` so any unmatched payload throws a `TraversalError`.

4. **Executable entrypoint** — reads one JSON object from stdin via a chunked async iterator, dispatches it through the matcher, and writes the formatted result plus a newline to stdout. Thrown errors are caught, logged to stderr, and the process exits with code `1` via `process.exit(1)`. Invoked as `npx tsx src/handler.ts`.

- `{"status":"success","data":{"x":1}}` → `OK: {"x":1}` with trailing `\n`, exit 0
- `{"status":"error","code":500,"reason":"oops"}` → `ERR 500 oops`, exit 0
