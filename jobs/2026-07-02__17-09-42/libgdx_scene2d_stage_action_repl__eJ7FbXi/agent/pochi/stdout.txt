# Scene2D Action Replay under libGDX Headless Backend ## Background libGDX exposes a non-rendering `gdx-backend-headless` module (`com.badlogicgames.gdx:gdx-backend-headless`) that boots a real `HeadlessApplication` thread without an OpenGL context, making it suitable for servers, CI runners, and deterministic simulations. Scene2D's `Actor`, `Group`, and `Action` classes are pure scene-graph logic — they do not invoke OpenGL until you call `draw(...)` — so they can be exercised under the headless backend if the implementation is careful not to touch `Gdx.gl*` or `SpriteBatch`. Your task is to build a small libGDX project that loads a Scene2D scene description from a text file, queues `Action`s on the actors, advances the scene tick-by-tick on the headless main loop, and writes each actor's final 2D position to an output file. ## Requirements * Create a Gradle (single-module) Java project at `/home/user/gdx-stage-sim`. * Use libGDX `1.14.2` with the headless backend (`com.badlogicgames.gdx:gdx-backend-headless:1.14.2`) on top of `com.badlogicgames.gdx:gdx:1.14.2` and the `com.badlogicgames.gdx:gdx-platform:1.14.2:natives-desktop` natives classifier. * Bootstrap the application from a `main` method that constructs a `com.badlogic.gdx.backends.headless.HeadlessApplication` driving an `ApplicationListener` (or `ApplicationAdapter`). * Use Scene2D `com.badlogic.gdx.scenes.scene2d.Actor` instances and Scene2D `Action`s (`com.badlogic.gdx.scenes.scene2d.actions.MoveByAction`, the `Actions` helper, or equivalent) to model and update each actor's position. * Read the script file via `Gdx.files.absolute(...)` in `create()`, register the requested actors and queue their `Action`s, run the requested number of ticks by advancing each actor's action queue by `dt` seconds per `render()` call, and write the output file from `dispose()` before the JVM exits. * Make the program runnable through Gradle's `application` plugin so it can be launched with `./gradlew run --args="<script-path> <output-path>"`. ## Implementation Hints * The headless backend swaps `Gdx.graphics`/`Gdx.audio`/`Gdx.input` for mocks, so **do not** call anything under `Gdx.gl*` and do **not** call `SpriteBatch`/`Stage.draw(...)` — those require a real GL context. Scene2D's `Actor.act(float)`, `Group.act(float)`, and `Action.act(float)` are pure CPU logic and are safe to call under headless. * Use `HeadlessApplicationConfiguration.updatesPerSecond = 0` so the main loop ticks as fast as possible and the simulation is not throttled by wall-clock pacing. * `Gdx.app.exit()` is asynchronous (it posts a runnable that flips `running` and then triggers `pause()` + `dispose()`). To guarantee that the output file is flushed before the JVM exits, write the file from `dispose()` and `join()` the `HeadlessApplication` main loop thread from `main`. * The simulation step must be deterministic and independent of wall-clock time: use the `dt` value parsed from the script file, **not** `Gdx.graphics.getDeltaTime()`. * Use `Locale.ROOT` (or equivalent) when formatting floating-point output so the decimal separator is always `.`. * Look at `HeadlessApplication`, `HeadlessApplicationConfiguration`, Scene2D `Actor`/`Action`, and `MoveByAction` in the libGDX javadoc / source for the contracts you need to satisfy. ## Script File Format (`<script-path>`) * UTF-8 text file, one directive per line, LF line endings. * Lines starting with `#` are comments and are skipped. * Blank or whitespace-only lines are skipped. * Tokens on a line are separated by one or more spaces or tabs; leading/trailing whitespace is trimmed. * Numeric values use a `.` decimal separator and no thousands separators. * The following directives MUST be supported. The first token is the directive name and is case-insensitive (e.g., `DT`, `Dt`, and `dt` are equivalent): * `dt <float>` — fixed simulation time step in seconds (`> 0`). Must appear exactly once before any actor-related directive. * `ticks <int>` — total number of `render()` ticks to run (`>= 0`). Must appear exactly once before any actor-related directive. * `actor <id> <x> <y>` — create an `Actor` with identifier `<id>` (alphanumeric/underscore, case-sensitive, unique within the file) at initial position `(<x>, <y>)`. The order of `actor` directives in the file defines the output order. * `moveby <id> <dx> <dy> <duration>` — queue a Scene2D `MoveByAction` (default linear interpolation) on the previously declared actor `<id>` that moves it by `(<dx>, <dy>)` over `<duration>` seconds (`>= 0`). At most one `moveby` directive may target any given actor in a given script. ## Output File Format (`<output-path>`) * The program creates or overwrites the file. * UTF-8 encoding, LF line endings, one `<id>=<x>,<y>` line per declared actor, in the order the actors were declared in the script. * Each `<x>` and `<y>` is the actor's final position formatted with `%.6f` using `Locale.ROOT`. ## Simulation Semantics * After `create()` completes, the listener performs exactly `ticks` ticks. On each tick it advances every actor's action queue by `dt` seconds (e.g., via `Actor.act(dt)` or `Group.act(dt)`). After the final tick the listener triggers application exit so the headless main loop terminates. * `ticks=0` is a valid input and must produce the initial positions unchanged in the output file. * An `actor` declared with no `moveby` directive must remain at its initial position throughout the simulation. * A `MoveByAction` of duration `D` reaches the full `(dx, dy)` displacement once the simulated time elapsed (`accumulated_dt`) reaches `D`; any remaining ticks must not move that actor further (Scene2D actions REDACTED-remove on completion). * The output file must be flushed and the JVM must terminate within 60 seconds for any input with `ticks <= 50000`.
