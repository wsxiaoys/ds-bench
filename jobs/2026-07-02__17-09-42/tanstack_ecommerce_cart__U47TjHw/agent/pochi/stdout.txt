## Architecture

### Files created
- `src/main.tsx` — Entry point. Sets up `QueryClientProvider`, `RouterProvider`, and the route tree.
- `src/App.tsx` — Main component. Reads `cart` from URL via `useSearch({ from: '/' })`, fetches products via `useQuery`, and wires `useNavigate({ from: '/' })` to update the URL on cart mutations.
- `src/router.ts` is inlined into `main.tsx` for simplicity. The root route uses `validateSearch` to parse the raw `cart` search string.
- `src/api/products.ts` — Mock API: 8 products with simulated 500 ms network delay, surfaced via `fetchProducts()`.
- `src/cart.ts` — Pure helpers: `encodeCart`, `decodeCart`, `addToCart`, `updateCartItemQty`, `removeFromCart`. The URL encoding uses a compact, human-readable format: `id1:qty1,id2:qty2`.
- `src/components/ProductList.tsx` — Grid of product cards each with an "Add to Cart" button (shown as `Add (n)` when already in cart).
- `src/components/Cart.tsx` — Sticky side panel with item list, quantity `+` / `−` controls, `×` remove button, subtotal/shipping/tax/total breakdown, and Clear / Checkout buttons.
- `src/types.ts`, `src/styles.css` — Shared types and styling.

### URL state design
Cart state is stored entirely in a single URL search param: `?cart=1:2,3:1` (product id `1` × qty `2`, product id `3` × qty `1`). When the cart is empty, the param is removed from the URL.

### How the URL stays in sync
All cart mutations call `useNavigate({ from: '/' })` with `search: (prev) => ({ ...prev, cart: <new> })`, so:
- Other future URL params would be preserved REDACTEDmatically.
- The browser history is updated correctly (`replace: true` for adjustments, push for add-to-cart so the back button works).
