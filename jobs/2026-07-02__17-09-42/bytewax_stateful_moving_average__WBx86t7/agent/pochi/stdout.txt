from bytewax.testing import TestingSource, run_main

from collections import deque

    ("s1", 20.0),

    ("s2", 12.0),

def ma(state, value):
    if state is None:
        state = deque()
    new_state = deque(state)
    new_state.append(float(value))
    while len(new_state) > 3:
        new_state.popleft()
    avg = sum(new_state) / len(new_state)
    return (new_state, f"{avg:.2f}")

out = op.stateful_map("ma", inp, ma)
op.inspect("out", out)

## Summary

The pipeline `flow` performs the following:

1. **Reads** `input.csv` via a custom `FixedPartitionedSource` (`CSVSource`) that yields `(sensor_id: str, temperature: float)` tuples, one per batch to preserve input ordering.
2. **Computes** the moving average using `op.stateful_map("moving_avg", inp, moving_average)`. The stateful function:
   - Maintains a `deque` of the most recent 3 readings per sensor.
   - Returns a **new** `deque` (never mutates the persisted state) for snapshot safety.
   - Falls back to the available readings when fewer than 3 are present.
   - Formats the average with `f"{avg:.2f}"` so the output is always exactly 2 decimal places.
3. **Writes** to `output.csv` via a custom `DynamicSink` (`CSVSink`) that emits one `sensor_id,moving_average` line per item. Only worker 0 opens the output file, avoiding race conditions in multi-worker runs.

## Key design choices

- **One item per source batch**: prevents `op.stateful_map` from regrouping items across keys, so output order matches input order.
- **Immutable state updates**: every call to `moving_average` constructs a fresh `deque` so Bytewax's recovery snapshots remain correct.
- **Snapshot support**: `_CSVSourcePartition.snapshot()` returns the number of data lines emitted, allowing clean resume from `resume_state`.
- **EOF signal**: `StopIteration` is raised at end-of-file so the dataflow shuts down cleanly.
- **Key type**: `sensor_id` is emitted as a Python `str` as required by the keyed operators.
