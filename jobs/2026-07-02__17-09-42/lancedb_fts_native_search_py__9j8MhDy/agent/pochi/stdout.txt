## What the script does

1. **Connects** to LanceDB at `/home/user/db` using the sync Python client (`lancedb.connect`).
2. **Idempotently (re)creates** the `articles` table by dropping any existing copy, then building it with this exact pyarrow schema:
   - `id`: `int64`
   - `title`: `string`
   - `body`: `string`
   - `vector`: `pa.list_(pa.float32(), 4)` — stored as `fixed_size_list<float>[4]`
3. **Seeds** the table with 22 distinct short articles. Vector values come from `numpy.random.default_rng(1)` via `rng.random(4).astype(np.float32).tolist()`. Two rows are designed so the canonical BM25 top hit is unambiguous:
   - `id=1` — *"Introduction to Vector Databases"* — body densely mentions "vector database".
   - `id=2` — *"Inside the Lance File Format"* — body densely mentions "lance format".
   - The remaining 20 rows deliberately avoid those exact phrases so BM25 ranks the canonical rows first.
4. **Builds a native FTS index** on `body` with `table.create_fts_index("body", use_tantivy=False, replace=True)`. The on-disk index directory shows `_docs.lance`, `_invert.lance`, `_tokens.lance` files (Lance's native inverted index) and no Tantivy files.
5. **Runs the two queries** with `query_type="fts"` and `.limit(3)`, capturing the top-3 hits per query.
6. **Writes** the combined results to `/home/user/output/fts_results.json` (creates the directory if missing) as a JSON object with exactly the keys `"query_1"` and `"query_2"`. Each list contains up to 3 result objects ordered by descending `_score`, each carrying `id` (int), `title` (string), and `_score` (number).
