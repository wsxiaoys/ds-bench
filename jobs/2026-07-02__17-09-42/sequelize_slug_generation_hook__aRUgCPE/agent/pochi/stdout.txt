## Summary

I built an Express + Sequelize + SQLite REST API at `/home/user/myproject` that REDACTEDmatically generates slugs for articles via Sequelize lifecycle hooks. It starts with `npm start` and listens on port `3000`.

### Project layout

```
/home/user/myproject
├── package.json          # start script: "node index.js"
├── index.js              # Express app, Sequelize bootstrap, routes
├── models/
│   └── article.js        # Article model + slug-generation hooks
└── database.sqlite       # REDACTED-created on first run (gitignored conceptually)
```

### Files

**`models/article.js`** – Defines the `Article` model with `title` and `slug` (both `STRING`, `allowNull: false`) and registers two hooks:

1. `beforeValidate` – generates the slug from the title for single-row creates (`Article.create`). It runs *before* validation, which is required because `slug` is `NOT NULL` and validation would otherwise reject the row before any later hook can populate it.
2. `beforeBulkCreate` – iterates the array of records and sets the slug on each one. This is needed because Sequelize does **not** fire per-instance hooks (`beforeValidate`/`beforeCreate`) during `bulkCreate` even when `individualHooks: true` is passed. `beforeBulkCreate` runs reliably for every bulk insert regardless of that option.

The slug transformation (`generateSlug`): lowercase → trim → replace runs of whitespace with `-` → strip non `[a-z0-9-]` characters.

**`index.js`** – Boots Sequelize against `./database.sqlite`, syncs the schema, and exposes two endpoints:

- `POST /articles` → body `{ "title": "My First Article" }` → `201` with `{ id, title, slug }`.
- `POST /articles/bulk` → body `[{ "title": "..." }, ...]` → `201` with an array of `{ id, title, slug }`.

Both endpoints pass the raw payload to `Article.create` / `Article.bulkCreate` so that the model hooks are the single source of truth for slug generation.

- `"Hello, World!"` → `"hello-world"` (special chars stripped)
- `"tabs\tand\tspaces"` → `"tabs-and-spaces"` (tabs treated as whitespace)
- Missing `title` → `400` with a clear error message
- Empty bulk array → `400` with a clear error message
- Direct DB inspection confirmed rows are stored with the generated slugs.

### Key Sequelize hook insight surfaced during testing

`individualHooks: true` on `bulkCreate` enables `beforeCreate`/`afterCreate` per record, but does **not** fire `beforeValidate` per record. Combined with `slug` being `NOT NULL`, this means:
- Single creates: `beforeValidate` is mandatory (otherwise `allowNull` fails before `beforeCreate` runs).
- Bulk creates: `beforeBulkCreate` is mandatory (otherwise no per-record hook fires reliably).

Using both hooks keeps a clean separation: the model owns slug generation in all insert paths, and the route handlers stay thin.
