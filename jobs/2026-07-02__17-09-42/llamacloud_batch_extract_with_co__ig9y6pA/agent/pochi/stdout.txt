# Batch Invoice Extraction with Bounded Concurrency (LlamaCloud TS SDK) ## Background You are building a production batch-extraction pipeline that pulls structured fields out of a folder of invoice PDFs using **LlamaCloud Extract v2** through the TypeScript SDK `@llamaindex/llama-cloud`. The pipeline must scale to many files without overwhelming the LlamaCloud API. You will: - Upload files to LlamaCloud, - Run schema-driven extraction jobs **concurrently but with a bounded worker pool** (so you do not blow past your account's rate limits), - Poll each job until it reaches a terminal status, with a per-job client-side timeout, - Persist a structured result document for every input PDF (including failures), - Print a final summary so the script can be wired into CI. ## Requirements - Implement the pipeline in a **single TypeScript file** that runs end-to-end via `npx tsx run.ts`. - Discover every `*.pdf` file (case-insensitive) under `/home/user/myproject/invoices/` and process them as a batch. - Use a **Zod schema** named conceptually `Invoice` covering at least: `vendor_name` (string), `invoice_number` (string), `total_amount` (number), `currency` (3-letter ISO code string). - Pass that Zod schema to LlamaCloud Extract by converting it to a JSON Schema with `z.toJSONSchema(...)`. - Use the `cost_effective` tier and `per_doc` extraction target. - Limit in-flight extract jobs to **at most 3 concurrent** workers (use any concurrency primitive you like, e.g. `p-limit`). - Apply a **per-job timeout of 240 seconds** to the polling loop; if a job is still not in a terminal status after the timeout elapses, treat it as a failure (do not throw and abort the whole batch). - Write a JSON artifact to `/home/user/myproject/results.json` that is a JSON array. Each element corresponds to one input PDF and has the shape (`data` is present on success, `error` is present on failure — never both): ```json { "file": "<basename of the input pdf, e.g. invoice_acme.pdf>", "status": "success" | "error", "data": { "vendor_name": "...", "invoice_number": "...", "total_amount": 1234.56, "currency": "USD" }, "error": "<error message string>" } ``` - Write a human-readable log to `/home/user/myproject/output.log` containing at minimum one line per file in the form `PROCESSED : <status>` and a final summary line in the form `SUMMARY total=<N> success=<S> failed=<F>` (also printed to stdout). ## Implementation Hints - Authenticate the client with the `LLAMA_CLOUD_API_KEY` environment variable (already set in the environment). - The TypeScript source must import from `@llamaindex/llama-cloud` (the official LlamaCloud v2 TS SDK) and `zod` to define the extraction schema. - Upload each file with `client.files.create({ file: fs.createReadStream(path), purpose: 'extract' })` to get a `dfl-...` file id. - Create extract jobs with `client.extract.create({ file_input: <file_id>, configuration: { data_schema: ..., extraction_target: 'per_doc', tier: 'cost_effective' } })` and poll with `client.extract.get(jobId)` until `job.status` is one of `COMPLETED`, `FAILED`, or `CANCELLED`. - A successful job exposes the extracted data on `job.extract_result`. - Order of entries in `results.json` does not matter — the verifier matches by `file`. - A `node_modules/` install is **not** preinstalled. Create whatever `package.json` you need and install the dependencies you choose.
