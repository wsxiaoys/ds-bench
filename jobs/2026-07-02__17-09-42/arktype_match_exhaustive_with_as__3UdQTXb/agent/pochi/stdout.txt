
**How it satisfies the spec**
- Reads exactly one JSON object from STDIN via `for await (const chunk of process.stdin)` + `JSON.parse`, and writes the result to STDOUT with a trailing newline.
- Implements the conversion math: meters → feet (`×3.28084`), kilograms → pounds (`×2.20462`), Celsius → Fahrenheit (`×9/5 + 32`), each formatted to two decimal places so `1 m` → `3.28`, `1 kg` → `2.20`, and `0 °C` → `32.00` (containing `32`).
- Dispatches with ArkType's `match` API:
  ```js
  const convert = match
      .at("kind")
      .match({
          "'length'": ({ meters }) => `${(meters * 3.28084).toFixed(2)} feet (${meters} m)`,
          "'mass'":   ({ kilograms }) => `${(kilograms * 2.20462).toFixed(2)} pounds (${kilograms} kg)`,
          "'temperature'": ({ celsius }) => `${(((celsius * 9) / 5) + 32).toFixed(2)} Fahrenheit (${celsius} °C)`,
          default: "assert"
      });
  ```
- `.at("kind")` discriminates on the `kind` property; the case keys (`'length'` etc.) are ArkType-syntax quoted string literals that get compiled into `{ kind: "length" }`-style branches. `.default("assert")` (configured by the `default: "assert"` key in the cases object) wires `throwOnDefault` into the union's `onFail`, so unmatched inputs like `{ kind: "volume", liters: 1 }` make `convert(input)` throw an ArkErrors exception, which the try/catch surfaces on stderr and exits with code `1`.
