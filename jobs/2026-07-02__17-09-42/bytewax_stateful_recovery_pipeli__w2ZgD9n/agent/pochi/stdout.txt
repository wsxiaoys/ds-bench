import math
from collections import defaultdict

base = datetime(2026, 1, 1, 0, 0, 0, tzinfo=timezone.utc)

for s_idx in range(3):
    sensor = f'sensor-{s_idx}'
    for t_idx in range(30):
        t = base + timedelta(seconds=t_idx * 5)
        temp = round(20.0 + 0.1 * t_idx + (s_idx * 0.5), 2)
        records.append((sensor, t, temp))

# Sliding window: 60s length, 30s offset
WINDOW_LENGTH = timedelta(seconds=60)
WINDOW_OFFSET = timedelta(seconds=30)
ALIGN_TO = base

# Group readings by sensor and window
windows = defaultdict(list)
for sensor, t, temp in records:
    # For each reading, find which windows it falls into
    # Window n: [ALIGN_TO + n*OFFSET, ALIGN_TO + n*OFFSET + LENGTH)
    since = t - ALIGN_TO
    # windows: ((since-LENGTH)//OFFSET)+1 ... since//OFFSET inclusive
    start_id = (since - WINDOW_LENGTH) // WINDOW_OFFSET + 1
    end_id = since // WINDOW_OFFSET + 1
    for wid in range(int(start_id), int(end_id)):

expected = []
for (sensor, wid), temps in sorted(windows.items()):
    cnt = len(temps)
    if cnt == 0:
        continue
    avg = sum(temps) / cnt
    # population stddev
    var = sum((x-avg)**2 for x in temps) / cnt
    std = math.sqrt(var)
    ws = ALIGN_TO + WINDOW_OFFSET * wid
    we = ws + WINDOW_LENGTH
    expected.append((sensor, ws, we, avg, std))

## Bytewax Sliding-Window Outlier Detector with Recovery

I built a fault-tolerant Bytewax v0.21.1 dataflow at `/home/user/myproject/pipeline.py`. The module exposes a `flow` Dataflow that satisfies every requirement from the spec.

### Dataflow shape

```
input.jsonl  ─► FileSource ─► parse_line ─► key_by_sensor
                                    │
                                    ▼
                       EventClock (UTC, ISO8601)
                                    │
                                    ▼
                SlidingWindower (60s length, 30s offset, aligned to 2026-01-01T00:00:00Z)
                                    │
                                    ▼
       fold_window(builder / folder / merger; state = (count, sum, sum_sq))
                                    │
                                    ▼
                render_window  (derives window_start / window_end from window_id)
                                    │
                                    ▼
                       FileSink ─► output.jsonl
```

### Key design decisions

* **Picklable state.** All step callables (`parse_line`, `get_event_time`, `key_by_sensor`, `accumulator_builder`, `accumulator_folder`, `accumulator_merger`, `render_window`) are plain module-level functions — no lambdas, no closures, no local definitions. The accumulator is an immutable 3-tuple `(count, sum, sum_sq)`, which round-trips through `pickle` without issue and is compatible with Bytewax's SQLite recovery snapshots.
* **Window start / end derived, not joined.** `SlidingWindower` is configured with `align_to=2026-01-01T00:00:00Z`, so the window with id `n` covers `[align_to + n*offset, align_to + n*offset + length)`. The render step computes `window_start` and `window_end` directly from the window id, avoiding a join against the separate `meta` stream (and keeping `window_id` exact across resumes).
* **Population statistics.** Mean is `sum / count`. Population variance is computed from the running `sum_sq` via `E[X²] − E[X]²`, clamped at zero to absorb floating-point round-off before `math.sqrt`.
* **ISO8601 / UTC.** `parse_line` accepts both `"…Z"` and `"…+00:00"` style timestamps; timestamps without a timezone are forced to UTC; the resulting aware `datetime` is reused by `EventClock`.
* **Keys as strings.** `key_by_sensor` always returns `str(record["sensor_id"])`, matching Bytewax's requirement that keyed-operator keys be strings.
* **Recovery-friendly I/O.** `FileSource` / `FileSink` are used (not `StdOutSink` or custom sources), which is the supported path for exactly-once SQLite recovery; the partition initialisation step is `python -m bytewax.recovery ./recovery_dir 1`.
