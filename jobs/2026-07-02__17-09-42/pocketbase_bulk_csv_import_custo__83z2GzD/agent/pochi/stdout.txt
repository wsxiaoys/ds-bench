# Bulk CSV Import Custom Route (PocketBase Go) ## Goal Implement a Go-embedded PocketBase v0.31.0 application in `/home/user/myproject` that exposes a superuser-only custom route `POST /api/import/products` for bulk-importing products from a CSV file. All inserts must be performed inside a single database transaction; if any row fails validation, the entire batch must be rolled back. The binary should be produced by `go build -o myapp .` inside the project directory, and the application must start with `./myapp serve --http=0.0.0.0:8090` listening on port 8090. ## Implementation Hints - Ensure that a `base` collection named `products` with fields `sku` (text), `name` (text), and `price` (number) exists after the server has started. - The custom route `POST /api/import/products` must handle requests as follows: - Require superuser authentication via the standard PocketBase authorization header (`Authorization: Bearer <superuser-token>`). Return HTTP 401 for unauthenticated requests, and HTTP 403 for authenticated, non-superuser requests. - Accept a `multipart/form-data` request with a single file field named `file` containing a CSV whose first row is the header `sku,name,price`. - Validate every data row: `price` must be > 0, `sku` must be unique within the uploaded file, and `sku` must not already exist in the `products` collection. - Run all inserts inside a single database transaction. If ANY row fails validation, the transaction must be rolled back so that no new records are inserted at all. - On success, return HTTP 200 with JSON body `{"inserted": <int>, "errors": []}`. - On validation failure, return HTTP 400 with JSON body `{"inserted": 0, "errors": [{"row": <int>, "reason": <string>}, ...]}` where `row` is the 1-based row number of the offending data row (the header is not counted). ## Credentials (pre-provisioned) - Superuser: `$PB_SUPERUSER_EMAIL` / `$PB_SUPERUSER_PASSWORD` (already exists in the `pb_data/` directory packaged with the environment). - A regular auth user is provisioned by the verifier at test time; do not hard-code regular-user credentials.
