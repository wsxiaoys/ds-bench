## Implementation summary

**Schema (`CorpusRow`)** — Pydantic `LanceModel` with `concept_id: int`, `language: str`, `text: str`, and `vector: Vector(EMBED_DIM)` (a 1024-d fixed-size-list of `float32`).

**Table naming** — `multilingual_<run-id>` where `run-id` is read from `/logs/artifacts/run-id` (the actual file resolves to `multilingual_zrj8zxyixn` in this run), giving each concurrent run its own table.

**Cohere client** — Reads `COHERE_API_KEY` from the env, then embeds:
- All 90 documents with `input_type="search_document"` (inside `build_index()`).
- The user query with `input_type="search_query"` (inside `cross_lingual_search`).

The `_extract_embeddings` helper handles both the legacy `response.embeddings` list-of-lists form and the new typed `response.embeddings.float_` / `.float` form, so it works across Cohere SDK 5.x and 7.x.

**`build_index()`** — Loads `corpus.json`, embeds the texts in a single Cohere call (90 ≤ 96 max-per-call), creates the table via `db.create_table(name, data=records, schema=CorpusRow)`, and caches it module-globally. Idempotent: drops a stale table with the same run-scoped name first.

**`cross_lingual_search(query, k=3)`** — Embeds the query as `search_query`, runs `table.search(query_vector, vector_column_name="vector").metric("cosine").limit(k).to_list()`, and returns a list of `{"concept_id", "language", "text"}` dicts (no language filter, sorted by ascending distance). If the index hasn't been built yet, it lazily calls `build_index()` first.

**Storage location** — Persisted under `lancedb_data/` next to the script.
