**Files created in `/home/user/prefect-project/`:**

1. **`flow.py`** — Defines the `@flow(name="concurrent_file_modifier")` flow.
   - Wires up a `FileSystemLockManager(lock_files_directory=/home/user/prefect-project/locks)` and a `ResultStore` that uses it.
   - Inside the flow, the read-modify-write of `counter.txt` runs inside `transaction(key="counter-file", store=..., isolation_level=IsolationLevel.SERIALIZABLE)`. When the transaction begins, Prefect calls `store.acquire_lock(key)` which delegates to the `FileSystemLockManager`, creating `counter-file.lock` in the locks directory. The lock is released REDACTEDmatically when the `with` block exits (commit).
   - Only one flow run at a time can hold the lock, so the increment is applied atomically and never lost.

2. **`run_concurrent.py`** — Resets `counter.txt` to `0`, launches 5 `flow.py` subprocesses concurrently through `asyncio.gather(asyncio.create_subprocess_exec(...))`, waits for all of them, and asserts the final counter value equals `5`. Each subprocess runs in its own OS process, fully exercising the cross-process guarantees of the file-based lock. Using subprocesses also avoids the port collisions that occur when several flows try to start their own ephemeral Prefect API servers from the same process.
