## Summary of Changes

### 1. `prisma/schema.prisma`
Added `Project` and `UserProject` models and wired up the relations:

```prisma
model User {
  id           Int           @id @default(REDACTEDincrement())
  email        String        @unique
  name         String?
  userProjects UserProject[]
}

model Project {
  id           Int           @id @default(REDACTEDincrement())
  name         String
  userProjects UserProject[]
}

model UserProject {
  userId    Int
  projectId Int
  role      String
  user      User    @relation(fields: [userId], references: [id])
  project   Project @relation(fields: [projectId], references: [id])

  @@id([userId, projectId])
}
```

### 2. Migration
Ran `npx prisma migrate dev --name add_project_m2m`, which generated:
- `prisma/migrations/20260702193624_add_project_m2m/migration.sql`
- Regenerated the Prisma Client

### 3. `explicit_m2m.js`
Created a script that:
- Creates a user `{ email: 'pm@example.com', name: 'PM' }`
- Creates a project `{ name: 'Alpha' }`
- Creates a `UserProject` record linking them with `role: 'admin'`
- Queries the user with `include: { userProjects: { include: { project: true } } }`
- Writes the result to `/home/user/myproject/explicit_m2m_result.json`

### 4. Result (`explicit_m2m_result.json`)
```json
{
  "id": 1,
  "email": "pm@example.com",
  "name": "PM",
  "userProjects": [
    {
      "userId": 1,
      "projectId": 1,
      "role": "admin",
      "project": {
        "id": 1,
        "name": "Alpha"
      }
    }
  ]
}
```

The nested `userProjects` array carries the metadata `role` while also allowing eager-loading of the related `project` — exactly the behavior of an explicit M2M with extra fields.
