I've built a Bytewax dataflow at `/home/user/bytewax_batching/dataflow.py` that batches device metrics and bulk-inserts them into SQLite. It runs cleanly via `python3 dataflow.py` and produces the required artifacts.

**Dataflow pipeline** (`dataflow.py`):

1. **JSONL input source** – custom `JsonlSource` (extends `DynamicSource`) with a `JsonlSourcePartition` (extends `StatelessSourcePartition`) that reads `input.jsonl` line-by-line, returning one dict per `next_batch()` call and raising `StopIteration` on EOF so the dataflow terminates cleanly.

2. **`op.filter`** – drops any record where `metric_value < 0`.

3. **`op.key_on`** – groups the remaining metrics by `device_id`, producing a keyed stream.

4. **`op.collect`** – batches each device's metrics with `max_size=10` and `timeout=timedelta(seconds=1)` (whichever comes first).

5. **`op.key_rm`** – strips the grouping key so the sink receives pure batched lists (the `device_id` is already carried inside each record).

6. **`op.output`** – writes the batches through a custom `SQLiteSink` (`DynamicSink`) whose `SQLiteSinkPartition` (`StatelessSinkPartition`) flattens all batches into a single list of tuples and inserts them with **one `executemany`** call.

**Setup & lifecycle**:
- The current `run-id` is read from `/logs/artifacts/run-id` (`zrco002mz9`) and the database file is named `metrics-zrco002mz9.db`.
- The `device_metrics` table (with `device_id TEXT`, `timestamp TEXT`, `metric_value REAL`) is created both up-front (`_prepare_database`) and inside the sink partition so it always exists before writes.
- The dataflow is executed via `bytewax.testing.run_main(flow)`, which blocks until completion.
- After `run_main` returns, `Pipeline finished.` is written to `/home/user/bytewax_batching/output.log`.
