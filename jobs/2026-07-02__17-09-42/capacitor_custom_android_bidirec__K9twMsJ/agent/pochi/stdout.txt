The team needs a tiny stateful native module to validate the **bi-directional** JS ↔ Java communication path: JavaScript should be able to drive native state with method calls AND subscribe to native-emitted events when that state changes, then cleanly unsubscribe via the returned listener handle. Your job is to write a custom local Capacitor plugin (Java, inside the existing Android project) named `Counter` that maintains an integer counter as instance state, exposes three methods (`increment`, `reset`, `getValue`), emits a `change` event via `notifyListeners` whenever the counter changes, and is registered in `MainActivity`. The interface declared for the plugin must expose `increment`, `reset`, `getValue`, and `addListener` so that the listener-handle pattern type-checks. - Provide a TypeScript driver file at `/home/user/myapp/src/main.ts` that: - Imports the `Counter` plugin from `./counter`. - Calls `Counter.addListener('change', ...)` to subscribe to the `change` event and stores the returned handle (the value returned from `addListener`, possibly awaited). - At the end of its flow, calls `.remove()` on that stored handle to deterministically detach the listener. - The complete Android project must compile successfully with the Gradle wrapper, and the TypeScript source files must type-check with the project's installed TypeScript compiler. ## Implementation Hints - Refer to the official Capacitor v8 "Custom Native Android Code" and "Android Plugin Guide" documentation.
