```bash
python run.py --input input.csv --output output.jsonl
```

## Dataflow design

1. **Input** – `CSVSource` reads the CSV row-by-row as `{column: str}` dicts.
2. **Parse** – `op.map` converts each row into a typed dict with an aware-UTC `datetime` and `float` price/volume.
3. **Key** – `op.key_on` keys by `symbol`, so each ticker has its own window state.
4. **Windowing** – `EventClock(ts_getter=...)` extracts event time; `TumblingWindower(length=1 min, align_to=1970-01-01Z)` produces 1-minute windows aligned to whole UTC minutes.
5. **Fold** – `fold_window` runs `builder → folder → merger` to accumulate an `(open, high, low, close, volume)` tuple per (symbol, window_id).
6. **Project** – `op.map` derives `window_start = align_to + 1 min * window_id` and serializes each closed bar to a JSONL string.
7. **Sink** – A small custom `DynamicSink` (`JsonlFileSink`) opens the output file in write mode (truncates on each run) and writes one JSON object per line.

A key implementation insight: `fold_window` emits `(window_id, OHLCV)` only when a window closes, while the metadata stream emits `(window_id, WindowMetadata)`. Naively joining those two streams on the symbol key pairs them by arrival order, which can misalign window IDs across windows. By aligning to `1970-01-01Z` and using `window_length * window_id`, the window start can be recovered directly from `window_id` — no join needed, eliminating the ordering hazard.

## Output schema

Each JSONL line has exactly these keys:

```json
{"window_start": "2023-10-01T10:00:00Z", "symbol": "AAPL", "open": 180.1, "high": 181.2, "low": 180.1, "close": 181.2, "volume": 23.0}
```
