## Bytewax Fraud Detection State Machine — Complete

I built the dataflow at `/home/user/fraud_detection/`. The implementation passes the sample test (4 expected `FRAUD_ALERT` records, one per user) and additional edge-case tests (transactions while logged out, exactly-`1000` boundary, late-arriving tx past the 300 s window, login → logout with no fraud, and post-alert suppression).

### Files
- **`run.py`** (executable) – the Bytewax dataflow + state machine.
- **`requirements.txt`** – `bytewax>=0.21,<0.22`.
- **`input.jsonl`** – sample events covering all four scenarios.
- **`output.jsonl`** – generated alerts.

### Run
```bash
python /home/user/fraud_detection/run.py \
    --input  /home/user/fraud_detection/input.jsonl \
    --output /home/user/fraud_detection/output.jsonl
```

### Dataflow shape
```
FileSource(input.jsonl)
  └─ map(json.loads)               # parse each line into a dict
       └─ key_on(user_id)          # partition events by user
            └─ stateful_map(step)  # per-user state machine
                 └─ filter_map(to_alert) # drop None, JSON-encode alerts
                      └─ key_on("output")  # constant key for FileSink routing
                           └─ FileSink(output.jsonl)
```

### State machine (`step(state, event) -> (new_state, alert|None)`)
Each user carries a tiny dict:
```python
{"state": "LOGGED_OUT", "login_timestamp": None, "large_tx_count": 0}
```
The state is **effectively immutable** — `evolve()` returns a `{**base, **overrides}` copy; the input dict is never mutated, satisfying Bytewax's state-immutability guideline.

Transitions implemented exactly as specified:
| Event | Pre-condition | Action |
|---|---|---|
| `login` | any | → `LOGGED_IN`, store `timestamp`, counter = 0 |
| `logout` | any | → `LOGGED_OUT`, clear counter/timestamp |
| `transaction` | `LOGGED_OUT` | ignored (no alert) |
| `transaction` | `LOGGED_IN`/`SUSPICIOUS` and `ts - login_ts > 300 s` | reset to `LOGGED_OUT`, *current* tx ignored |
| `transaction` | `LOGGED_IN`/`SUSPICIOUS`, within 300 s, `amount >= 1000` | counter += 1, → `SUSPICIOUS`; if counter == 3 emit `FRAUD_ALERT` and reset to `LOGGED_OUT` |
| `transaction` | within window, `amount < 1000` | state unchanged, no alert |

### Sample output (4 of 4 expected alerts)
```json
{"user_id": "alice", "alert": "FRAUD_ALERT"}
{"user_id": "bob",   "alert": "FRAUD_ALERT"}
{"user_id": "carol", "alert": "FRAUD_ALERT"}
{"user_id": "dan",   "alert": "FRAUD_ALERT"}
```

### Implementation notes
- Uses Bytewax 0.21 `Dataflow` + `stateful_map` from `bytewax.operators`.
- `stateful_map` emits `(user_id, output_element)` where `output_element` is the *second* tuple member returned by `step` — non-alert returns yield `None`, alert returns yield the alert dict, so downstream `filter_map(to_alert)` cleanly drops None values.
- `FileSink` is a `FixedPartitionedSink` and requires `(key, value)` tuples for routing; the alerts are re-keyed with a constant `"output"` key so everything lands in the single output partition.
- Input file path is validated up front; output directory is REDACTED-created.
