## Key Files

### `src/api.ts` — Mock cursor-paginated API
- Defines `FeedItem` and `FeedPage` types (`items` + `nextCursor: number | null`).
- Exports `fetchFeedPage(cursor)` that returns 5 items per page across a 25-item dataset with a 400 ms simulated latency — guaranteeing 5 distinct pages for pagination testing.
- Returns `nextCursor: null` on the final page, which `useInfiniteQuery` interprets as the end of the list.

### `src/Feed.tsx` — `useInfiniteQuery` consumer
```ts
const { data, fetchNextPage, hasNextPage, isFetchingNextPage } = useInfiniteQuery({
  queryKey: ['feed'],
  queryFn: ({ pageParam }) => fetchFeedPage(pageParam),
  initialPageParam: null,
  getNextPageParam: (lastPage) => lastPage.nextCursor,
})
```
- Flattens `data.pages` into a single `items` array (existing items are retained; new pages are appended).
- Renders a **`<button>` with the exact text `Load More`** wired to `fetchNextPage()`.
- Disables the button when `!hasNextPage || isFetchingNextPage`, surfacing `Loading…` / `No more items` accordingly.
- Handles `status === 'pending'` and `status === 'error'` for robust UX.

### `src/main.tsx` — Provider wiring
Wraps `<App />` in `<QueryClientProvider client={queryClient}>` with sensible defaults (`staleTime: 60_000`, `refetchOnWindowFocus: false`).

### `vite.config.ts` — Port configuration
```ts
server: {
  port: 5123,
  strictPort: true,
  host: true,
}
```
