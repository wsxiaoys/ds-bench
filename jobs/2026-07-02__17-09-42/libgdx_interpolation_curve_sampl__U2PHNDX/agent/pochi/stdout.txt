The class is part of `com.badlogicgames.gdx:gdx` and does not require an OpenGL context, so it can be driven by the headless backend (`com.badlogicgames.gdx:gdx-backend-headless`) and used inside CI / server pipelines. The `render()` method must produce exactly one new sample per invocation. After exactly `samples` ticks, the program must call `Gdx.app.exit()`. No additional samples may be produced after `samples` ticks. - Bootstrap the application from a `main` method that constructs a `HeadlessApplication` with a `HeadlessApplicationConfiguration`. After the last sample call `Gdx.app.exit()` and join the main-loop thread so the JVM exits cleanly. - The input configuration file at `<config-path>` is a Java properties file containing these keys: - `curve` (string): one of `linear`, `smooth`, `smoother` (case-sensitive, matching the static field name on `Interpolation`). - `start` (double): start value of the range. - `end` (double): end value of the range. - `samples` (integer, `>= 2`): number of equally-spaced samples to produce (inclusive of both endpoints). - Write the final result to `<output-path>` (created or overwritten) using UTF-8 encoding and LF line endings, with the following format: - Line 1: `curve=<curve-name>` - Line 2: `samples=<integer>` - Next `samples` lines (lines 3..2+samples): one decimal number per line, formatted with `%.6f` using `Locale.ROOT`, in sample-index order (i.e. `t = 0/(samples-1)` first, then `1/(samples-1)`, ..., ending with `t = 1`). - The file MUST end with a trailing newline (so the total number of lines is `2 + samples`). - The sample at index `i` (zero-based) must equal `Interpolation.<curve>.apply(start, end, t)` where `t = i / (samples - 1)` as a single-precision `float` and `samples >= 2`. - Supported curve names (must be looked up on `com.badlogic.gdx.math.Interpolation`): `linear`, `smooth`, `smoother`.
