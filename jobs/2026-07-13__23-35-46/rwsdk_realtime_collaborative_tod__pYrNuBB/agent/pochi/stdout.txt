# Realtime Collaborative To-Do List with RedwoodSDK ## Background You are working in an existing RedwoodSDK (rwsdk) project. RedwoodSDK is a server-first React framework for the Cloudflare platform that ships a built-in realtime primitive, the `useSyncedState` hook, backed by a `SyncedStateServer` Durable Object. Your job is to turn the starter app into a realtime collaborative to-do list: any item added by one connected client must appear, in realtime, on every other client viewing the same page. ## Requirements * The home route `/` must render an interactive to-do list page. * The list of to-do items must be shared state synchronized across all connected clients using RedwoodSDK's realtime `useSyncedState` primitive (not local `useState`, not polling). The state is global (all clients on `/` share one list; no per-room scoping). * A user can type text into an input and add it as a new to-do item. Adding an item on one client must cause that item to appear on all other clients that currently have `/` open, without a manual page reload. * Existing items must remain visible to a client that connects after items were already added (server is the source of truth). * The client components must actually hydrate in the browser (event handlers and effects must run). ## Implementation Hints * Review the RedwoodSDK realtime documentation for `useSyncedState` (`https://docs.rwsdk.com/experimental/realtime`). The hook mirrors React's `useState` but takes an additional unique state key and synchronizes bidirectionally with the server. * Model the shared list as a single synced value (e.g. an array) under one shared key so every client subscribes to the same state. * Wire up the realtime backend end-to-end: the `SyncedStateServer` Durable Object must be exported from the worker entry and its routes registered, and the Durable Object must be declared in `wrangler.jsonc` (including the SQLite migration via `new_sqlite_classes`). After changing bindings you may need to regenerate types. * Because RedwoodSDK is server-first, the interactive component must be a client component and the HTML Document must load the client hydration script, otherwise handlers and realtime updates will not run. * Keep the interactive parts in a `"use client"` component and import the hook from `rwsdk/use-synced-state/client`. * The realtime primitive relies on an additional peer package that is not installed by default; if it is missing, the framework surfaces a clear runtime error naming the package to install.
