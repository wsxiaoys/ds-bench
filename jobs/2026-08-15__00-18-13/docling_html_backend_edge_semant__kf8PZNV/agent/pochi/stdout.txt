### Features of the Implementation
1. **Structural Fidelity Assessment**:
   - Parses each HTML fixture in the specified directory using Docling's default HTML backend.
   - Extracts two markdown views: `body_lines` (BODY content layer only) and `full_lines` (BODY plus FURNITURE), following the exact splitting and stripping rules.
   - Extracts `body_blocks` by splitting the BODY markdown on `"\n\n"` and stripping each element.
   - Records table count, table shapes (`[num_rows, num_cols]`), verbatim table cell texts, and picture count.

2. **Resource-Location Resolution Probes**:
   - Executes a fixed matrix of 10 resource-location resolution probes against `LOCAL_BASE` (absolute path of `<local_root>/page.html`) and `REMOTE_BASE` (`https://cdn.example.com/docs/page.html`).
   - Uses Docling's internal `ImageResourceLoader.resolve_relative_path` logic.
   - Records the outcome (`resolved` or `rejected`), the resolved string, and details of any exceptions raised.

3. **Fetch Probes**:
   - Executes a fixed matrix of 7 image-data load probes under specific switches (e.g., `enable_local_fetch`, `enable_remote_fetch`, `max_image_data_base64_bytes`).
   - Uses Docling's internal `ImageResourceLoader.load_image_data` step.
   - Records the outcome (`loaded`, `skipped`, or `blocked`), the size of the returned bytes, and details of any exceptions raised.

4. **URL Safety Probes**:
   - Executes a fixed matrix of 5 remote-URL safety validation probes.
   - Uses Docling's internal `validate_url_safety` check.
   - Records whether the URL is `allowed` or `rejected`, along with exception details.

5. **Summary**:
   - Aggregates the totals for all documents, tables, pictures, rejected resolutions, blocked fetches, and rejected URLs.
