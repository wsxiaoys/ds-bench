### Implementation Details:
1. **Leader Election**: Built on top of `etcd v3` using the JSON-gRPC gateway. It grants a lease with a bounded TTL, then performs a compare-and-create atomic transaction (using `create_revision == 0`) to guarantee that exactly one worker acquires leadership.
2. **Lease Management**: A background thread automatically keeps the lease alive for as long as the worker is healthy. On failure to acquire, the lease is immediately revoked to prevent any leaks.
3. **Fencing Token**: The `create_revision` of the election key is used as a natural, globally-monotonic fencing token. Every successive term's token is strictly greater than all previous ones.
4. **Fenced LanceDB Maintenance**: Only the active leader is permitted to run maintenance (compaction and index optimization via `table.optimize()`). To prevent stale leaders from corrupting the table, the leader re-checks that it still owns the election key with its own term's token in etcd before touching the LanceDB table.
5. **Failover Scenarios**:
   - **Graceful Failover**: The current leader steps down via `resign()`, immediately revoking its lease and deleting the election key so followers can take over without delay.
   - **Ungraceful Failover**: `simulate_crash()` stops the keepalive thread without revoking the lease, allowing the lease to expire after its TTL so that followers can safely take over.
6. **Testing**: Verified all functionalities (leader election, graceful/ungraceful failover, fencing token monotonicity, maintenance, and fencing checks) via a comprehensive test suite. All tests pass successfully.
