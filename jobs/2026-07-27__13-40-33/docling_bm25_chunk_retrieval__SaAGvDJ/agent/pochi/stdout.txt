## What it does

**Build (`python3 main.py --build`)**
- Converts `assets/report.pdf` with Docling's `DocumentConverter` into the structured `DoclingDocument` model (uses the pre-cached offline models; no network).
- Segments the document into structurally-aligned chunks — one chunk per detected **content** structural element (text paragraphs and the table), in document order. No arbitrary fixed-size windows.
- Maintains a heading stack (by section level) so every chunk is enriched with its hierarchical `heading_path` (e.g. `["Cryptography Standards"]`). Headings are folded into the indexed text so a query matching only a heading still retrieves that section's content chunk.
- The table is preserved: chunk 4's `text` contains every cell verbatim (`Component | Model | Rating\nFlux Capacitor | FCX-9 | 88\nPlasma Coil | PLC-3 | 42\nIon Damper | IOND-7 | 15`).
- Builds a classical Okapi BM25 index (k1=1.5, b=0.75) over the contextualized tokens and persists it.
- Writes `output/chunks.json` (each object has `chunk_id`, `heading_path`, `page_nos`, `text`, `term_count`) and `output/bm25_index.idx` (pickle, self-contained & reloadable).

**Query (`python3 main.py --query "<text>" [--top-k <k>]`)**
- Loads the persisted index from disk (works in a fresh process that did not build it) and prints **only** a JSON array of `{chunk_id, score}` ranked by descending score (default k=5).

**Seeded run (`python3 main.py --run-queries`)**
- Evaluates all queries in `assets/queries.json` and writes `output/query_results.json`.
