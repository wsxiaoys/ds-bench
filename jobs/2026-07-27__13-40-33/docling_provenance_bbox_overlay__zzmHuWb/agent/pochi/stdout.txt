Built a Docling-based per-page layout provenance overlay renderer in `main.py` and verified it end-to-end.

## What it does
- Converts `assets/report.pdf` with `DocumentConverter` using `PdfPipelineOptions(generate_page_images=True, images_scale=2.0)` — fully offline using the pre-baked local models (no network access).
- For each Docling page `N` (1-based), writes exactly `output/overlay_page_<N>.png` and `output/overlay_page_<N>.json`.
- Considers only **body** elements (`content_layer == BODY`) whose Docling label is one of the six supported types (`text`, `section_header`, `list_item`, `table`, `picture`, `caption`); everything else is ignored.
- Uses each element's self-reference string (e.g. `#/texts/4`) as `id` and its label string as `type`.
- Iterates **every** provenance entry per element, so an element spanning multiple pages is drawn on each page it has a box on.

## Coordinate mapping (the key part)
Docling provenance boxes are in the PDF page coordinate system (points, **bottom-left** origin). For each box:
1. `bbox.to_top_left_origin(page.size.height)` flips the y-axis to a top-left origin (still in points).
2. Scale to the actual rendered raster pixel dimensions using `sx = img_w / page.size.width`, `sy = img_h / page.size.height` (both equal 2.0 here: 1224×1584 from 612×792).
3. Clamp/order to satisfy `0 <= x0 < x1 <= image_width`, `0 <= y0 < y1 <= image_height`.

This gives pixel boxes that coincide with the element's true location in the raster.

## Output
- Overlay PNG: a copy of Docling's scale-2.0 page raster with one rectangle per element, drawn via `PIL.ImageDraw` in the exact type color (width 3 px). PNG dimensions are identical to the rendered raster (1224×1584).
- Manifest JSON: `{page_no, image_width, image_height, boxes:[{id, type, bbox:[x0,y0,x1,y1], color}]}`.

- All manifest boxes validated against the schema, type→color map, ordering, and bounds.
